## Answer

Covered. Cloud Workload rules and policies need Cloud Runtime Security or Cloud Posture Security, which are add-ons on XSIAM NG-SIEM and Enterprise and included in XSIAM Premium. Scanning and CIS checks cover VMs, hosts, Kubernetes clusters, container images and running containers. The Prevent action at runtime applies only to Kubernetes workload images through the admission controller, and it affects new deployments only. Other runtime assets, including VM hosts, raise issues only, so CIS fixes on those hosts are made by the customer. The endpoint hardening modules (Host Firewall, Device Control, Disk Encryption visibility) support Windows and Mac, not Linux. Agent software discovery and remediation needs the AES add-on on Platform XDR or XSIAM tenants, on Windows and Mac endpoints only. None of this is specific to model runtimes; it applies to any host or container that runs them.

Source statement: "Detects CVEs, malware, hard-coded secrets, and CIS benchmark violations." (https://cortex-docs.paloaltonetworks.com/cortex-xsiam/cloud-security/rules-and-policies)

Research detail: The Cortex XDR agent protects hosts, and can now run inside Google Cloud Run and Azure Container Instance workloads for malware, exploit and vulnerability protection. AES runs on the same agent to give visibility of AI components on endpoints.
