## Answer

Covered. Needs the Agentic Endpoint Security (AES) add-on on Platform XDR or XSIAM tenants, on Windows and Mac endpoints only. Poisoned-description and compromised-package checks are described in vendor blogs, not admin documentation. AES policy detail sits on docs.koi.ai, which is behind sign-in. Named typosquatting detection comes from Malicious Packages in Cortex Application Security (https://cortex-docs.paloaltonetworks.com/application-security/software-supply-chain-security/risk-and-remediation/malicious-packages). That page says it runs during SCA scans of dependencies and matches known-malicious packages in the OSV.dev dataset, so it needs repositories onboarded and is not a check on tool names as such. Application Security is an add-on that also requires Cloud Posture Security, Cloud Runtime Security or XSIAM Premium. AES impersonation coverage is shown by a Go module example, with Go discovery on Windows and macOS.

Source statement: "detect misleading plugin descriptions, unapproved shell executions, and unauthorized data transmission" (https://www.paloaltonetworks.com/blog/security-operations/a-quarter-of-innovation-with-koi-agentic-endpoint-security/)

Research detail: The July 2026 blog says AES finds risks in MCP servers, skills and plugins and supports supply chain protections for agents. The release notes describe risk assessment for AI plugins, components and binaries.
