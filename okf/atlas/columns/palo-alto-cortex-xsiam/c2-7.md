## Answer

Not covered. No sandbox for agent files, processes or network, and no in-flight agent stop. Endpoint isolation is a manual response action, and AES guardrails are documented only in a blog.

Research detail: Endpoint isolation halts all network access on an endpoint except traffic to Cortex XSIAM, DNS and root DHCP and HTTPS, which can cut off a host running an AI agent. The July 2026 blog says Agentic Endpoint Security (AES) adds guardrails that block autonomous agents on endpoints from running destructive commands, with custom runtime policies. For Cortex's own agents, sensitive actions need explicit user approval and execution is limited to the user's tenant permissions.

<!-- chunk: products -->
## Products

Cortex XDR agent network isolation, Agentic Endpoint Security (separate purchase), Cortex Agentic Assistant RBAC and approvals.

<!-- chunk: gaps -->
## Gaps

Isolation is documented as a manual action from the Action Center. AES guardrails are described in a blog, not in product documentation, and the release notes describe AES as visibility and risk assessment. No sandbox or in-flight stop is documented for Cortex's own agents.

<!-- chunk: options -->
## Options

Test isolation and AES guardrails against a synthetic agent on a lab endpoint, and ask for AES policy documentation before relying on it.
