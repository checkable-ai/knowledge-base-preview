## Answer

Covered. Identity Broker mode where Idira holds the MCP server OAuth app (with DCR for rotation); passthrough mode leaves tokens with the agent. Agent's own client secret cannot be rotated in place.

Source statement: "Idira acts as a dynamic enforcement point, granting agents access only for the duration of a specific task." (https://www.paloaltonetworks.com/idira/agentic.md)

Research detail: In the 'Keep the MCP server's OAuth app in Idira' mode, Idira acts as the OAuth client and obtains MCP server access tokens on behalf of agents, so agents connect without holding MCP server credentials, and with DCR Idira manages credential creation, rotation and renewal. Database access through the SIA MCP server uses zero standing privilege ephemeral users. The agent's own client secret is issued once and cannot be rotated in place.

<!-- chunk: products -->
## Products

Identity Broker, Secure Infrastructure Access ZSP, Secrets Manager SaaS, Agent Guard

<!-- chunk: gaps -->
## Gaps

Agent client credentials cannot be reissued or rotated, only deleted and recreated. Passthrough mode leaves token handling with the agent.

<!-- chunk: options -->
## Options

Use the Idira-held OAuth app mode with DCR and test revocation by suspending an agent and disabling a server.
