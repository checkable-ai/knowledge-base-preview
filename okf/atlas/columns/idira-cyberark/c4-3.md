## Answer

Not covered. The vendor does not document that the downstream MCP server or target system receives the initiating person's identity and enforces only that person's permissions. What is documented falls short: OAuth user sign-in and consent, access policies binding users or roles to agents and tools at the broker, and audits attributing calls to the human user. Passthrough mode accepts agent-supplied tokens.

Research detail: Agents connect through an OAuth 2.1 authorisation code flow in which the user signs in and approves the connection, and access policies bind the initiating users or roles to the agents and tools. Audits record the human user, agent identity, tool and MCP server for every call in the Idira-held OAuth app mode. The docs do not state how the user identity is propagated to the downstream MCP server or target system.
