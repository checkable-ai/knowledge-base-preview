## Answer

Partly covered. Identity exists only for Studio flows, not for Gemini in Gmail, Docs or the Gemini app, which act as the signed-in user. No documented link between the identity and the release or runtime location; the owner is the flow creator.

Source statement: "To search by AI agent info, select Agent info, and then select a nested column: Agent ID, Agent name, or Agent product." (https://knowledge.workspace.google.com/admin/reports/gemini-for-workspace-log-events)

Research detail: Workspace Studio flows run with a unique, auditable identifier and the Admin console log events carry an Agent ID, name and product. Gemini in Gmail, Docs and the Gemini app acts as the signed-in user and has no separate agent identity.

<!-- chunk: products -->
## Products

Workspace Studio agent identity, Gemini for Workspace log events (Agent info)

<!-- chunk: gaps -->
## Gaps

Applies to newly created Studio flows only. The agent product field is supported only for Studio flows. No link to a release or runtime is documented, and the owner is the user who built the flow.

<!-- chunk: options -->
## Options

Treat Studio flows as the agent population and keep a register of flow owners and purposes. Check the identity attribution setting.
