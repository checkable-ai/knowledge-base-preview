## Answer

Covered. IRAP workloads need the compliance security profile and listed regions (e.g. ap-southeast-2); only specific features are supported for regulated data. ISO 42001 not listed.

Source statement: "It involves independent assessment against the Australian Government Information Security Manual (ISM) controls." (https://docs.databricks.com/aws/en/security/privacy/irap)

Research detail: Databricks publishes an IRAP assessor letter of assessment dated 24 December 2025 for an ACSC Cloud Security Assessment, Phase 1a, against the March 2025 ISM up to PROTECTED, covering the Databricks Platform on AWS, Azure and GCP in Australian regions. The Trust Center lists IRAP PROTECTED for GCP australia-southeast1, AWS ap-southeast-2 and several Azure Australian regions. IRAP workloads need the compliance security profile, and the IRAP feature table lists Model Serving, Foundation Model APIs, Unity AI Gateway, managed MCP servers and Supervisor Agent as available in ap-southeast-2. The Trust Center also offers SOC 2 Type II, ISO 27001, 27017, 27018 and 27701 and an annual pen test confirmation letter.

<!-- chunk: products -->
## Products

IRAP PROTECTED assessment, compliance security profile, SOC 2 Type II, ISO 27001 family, annual pen test confirmation letter

<!-- chunk: gaps -->
## Gaps

The letter covers Phase 1a and notes findings tracked through a plan of action, and the full report and cloud controls matrix are not public. Databricks Sandbox and Agent Runtime are not named in the IRAP feature table. No ISO/IEC 42001 certification appears in the Trust Center compliance list. Customer-defined fields may sit outside the compliance boundary.

<!-- chunk: options -->
## Options

Request the IRAP Cloud Security Assessment Report and controls matrix and check the agent features in scope. Enable the compliance security profile and confirm each agent feature appears in the IRAP regional table before an authority-to-operate decision.
