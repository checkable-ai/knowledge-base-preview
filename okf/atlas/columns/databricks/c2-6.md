## Answer

Covered. Beta. A workspace admin must enable Agent Memory Sessions from the Previews page. Access is granted at store level.

Source statement: "Agent memory gives your agents long-term memory that persists across conversations." (https://docs.databricks.com/aws/en/agents/agent-memory/managed-memory)

Research detail: Managed agent memory stores long-term facts in Lakebase, partitioned by actor_id, session and path, with full-text search. Store access can be granted to other principals.

<!-- chunk: products -->
## Products

Managed agent memory

<!-- chunk: gaps -->
## Gaps

actor_id is not an access control and no per-entry controls exist. No retention or deletion behaviour is documented. Beta.

<!-- chunk: options -->
## Options

Create separate stores per user or tenant boundary and set actor_id from trusted context only.
