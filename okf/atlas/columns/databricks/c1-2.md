## Answer

Covered. User authorisation needs the Agent Bricks agent server. By default tools run as the app service principal. Service policies are Beta.

Source statement: "By default, your agent's tools run with the permissions of the app's service principal." (https://docs.databricks.com/aws/en/agents/deploy/agent-server)

Research detail: Unity Catalog grants decide which models, MCP services, functions, connections and data a user or service principal can call. MCP services support tool selection, and service policies can allow, deny or ask per caller, for example by tool name and OAuth client ID. User authorization scopes limit what an app can do with the user token.

<!-- chunk: products -->
## Products

Unity Catalog grants and GRANT policies, MCP service tool selection, service policies, user authorization scopes

<!-- chunk: gaps -->
## Gaps

Tool selection does not support exclusion patterns. Service policies are Beta and do not apply to Agent Services. Users with USE CONNECTION can bypass MCP tool selection.

<!-- chunk: options -->
## Options

Withhold USE CONNECTION from end users, set explicit tool lists, and test per-caller policies in Log mode before Enforce.
