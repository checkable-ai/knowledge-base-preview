## Answer

Not covered. Apps get a per-app service principal, but documentation does not bind each agent identity to a named owner, runtime location and attested release.

Research detail: An agent deployed with Agent Runtime is an app named agent-bricks-<name> that runs as the app's own service principal, and the docs recommend one dedicated service principal per app. The Unity Gateway usage table records client session, subagent, coding agent and agent version fields for each request. Legacy agents are registered as Unity Catalog model versions.

<!-- chunk: products -->
## Products

Agent Runtime on Databricks Apps, app service principals, Unity Gateway usage table, Unity Catalog models

<!-- chunk: gaps -->
## Gaps

No documented link from the agent identity to a named business owner or a release version for Agent Runtime deployments. agent_version in the usage table is client supplied context, not a platform attested release.

<!-- chunk: options -->
## Options

Use one service principal per agent, record owner and release as tags on the app and service principal, and correlate run_by in audit logs with the deployment record.
