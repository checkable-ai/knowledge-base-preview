## Answer

Covered. ABAC row filter and column mask policies are Beta and apply to Unity Catalog tables and views; AI Search indexes lack row and column permissions; sensitive data detection is pattern based.

Source statement: "ABAC supports row and column-level security through row filter policies and column mask policies on tables and views (Beta)." (https://docs.databricks.com/aws/en/data-governance/unity-catalog/abac/)

Research detail: Unity Catalog grants, ABAC row filters and column masks apply to tables an agent reads, and with user authorization they apply per user. The sensitive data detection policy can block or redact card and identity numbers in gateway traffic. Data classification tags sensitive columns for masking.

<!-- chunk: products -->
## Products

Unity Catalog ABAC, service policies (detect_sensitive_data), data classification, user authorization

<!-- chunk: gaps -->
## Gaps

AI Search does not support row or column level permissions, so retrieval filtering is left to the application. Sensitive data detection is pattern based only.

<!-- chunk: options -->
## Options

Use separate indexes per access boundary or filter by user attributes in the app, and test redaction with seeded data.
