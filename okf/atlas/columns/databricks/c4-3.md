## Answer

Covered. User authorization is Public Preview and needs admin enablement. Unity Catalog function tools support only app auth.

Source statement: "User authorization allows an agent to act with the identity of the user making the request." (https://docs.databricks.com/aws/en/agents/custom-agents/agent-authentication)

Research detail: User authorization (formerly on-behalf-of) passes a scoped token for the calling user to the agent, and Agent Runtime tools default to auth = user, running with the requesting user's permissions. Per-user OAuth HTTP connections give each user their own token to external services. Audit logs record run_by and run_as so a human caller can be told apart from an agent acting for them.

<!-- chunk: products -->
## Products

Databricks Apps user authorization, Agent Bricks request-user authorization, per-user OAuth HTTP connections, audit log identity_metadata

<!-- chunk: gaps -->
## Gaps

User authorization is Public Preview and needs an admin to enable it. If the user token is missing the helper falls back to the app service principal. Interrupted request-user runs cannot be recovered. Unity Catalog function tools support only app auth.

<!-- chunk: options -->
## Options

Add the documented whoami check, monitor audit run_as values, and avoid app auth for tools that touch user scoped data.
