## Answer

Not covered. Bits Guardrails (Preview) require approval only for Datadog's own Bits agents. Customer agents get no pre-execution approval step. Binding approval to the exact action, and denial and replay handling, are not documented.

Research detail: Bits Guardrails, in Preview, let admins set an Ask enforcement level so Bits needs approval from selected teams, roles or individuals before it runs an action, scoped by environment, service and resource tags, or Deny so it can only recommend. Bits code fixes go to a pull request that a person reviews and merges. This covers Datadog's own Bits agents only. Customer agents get no pre-execution approval step, and the docs do not explain how an approval is bound to one action execution.
