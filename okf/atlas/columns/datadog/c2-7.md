## Answer

Not covered. No sandboxing of files, processes or network egress for agents. No general emergency stop. AI Guard blocking only stops calls it evaluates in instrumented apps and is off by default. Bits Guardrails Deny covers only Datadog's own agents.

Research detail: Datadog does not sandbox agent code or set filesystem, process or egress policy for agents. AI Guard SDKs raise an AIGuardAbortError on a DENY or ABORT verdict when blocking is enabled, and blocking can follow a remote is_blocking_enabled setting, so a central switch can stop flagged prompts and tool calls in instrumented apps. Cloud SIEM workflows can block an IP address or disable a user account from a signal. For Datadog's own Bits agents, Bits Guardrails set Deny on actions and Bits Security Analyst has an Enabled toggle.

## Products

AI Guard blocking, Cloud SIEM Workflow Automation, Bits Guardrails

<!-- chunk: gaps -->
## Gaps

No sandbox or egress control. AI Guard stops only calls it evaluates, and the docs do not say what the application must do after the error. Custom agent runtime protection is in Limited Access and coding agent protection is in Preview. Bits Guardrails are in Preview.

<!-- chunk: options -->
## Options

Enable AI Guard blocking with handling that ends the agent run, and build a Cloud SIEM workflow that revokes the agent's credentials at its identity provider.
