## Answer

Covered, with conditions. Self-hosted setting; SSRF protection must be enabled. Execution stop is available through the n8n API.

Source statement: "When enabled, n8n validates all outbound HTTP requests from user-controllable nodes" (https://docs.n8n.io/deploy/host-n8n/configure-n8n/security/enable-ssrf-protection)

Last checked 17 November 2026.

Research detail: Task runners execute Code node JavaScript and Python, and external mode runs them as separate sidecar containers. n8n recommends distroless images, the nobody user, a read-only root filesystem and AppArmor for further hardening. SSRF protection checks outbound requests from user-controllable nodes against blocked and allowed ranges. The public API stops one or many running executions, and EXECUTIONS_TIMEOUT sets a default stop time for workflows.

<!-- chunk: products -->
## Products

Task runners (external mode), SSRF protection, POST /executions/{id}/stop and /executions/stop, EXECUTIONS_TIMEOUT

<!-- chunk: gaps -->
## Gaps

Internal mode shares the n8n process user and is insecure by design. Hardening and SSRF protection are self-hosted settings, and n8n names network-level controls as the primary egress defence. No single control revokes all credentials an agent workflow uses.

<!-- chunk: options -->
## Options

Run external task runners with the hardening steps, turn on SSRF protection, and test stopping an AI Agent execution mid tool call through the API.
