## Answer

Not covered. No documented control over who can read stored memory. Redis Chat Memory session keys and session TTL cover resume and retention on one node only, and nodes in a workflow share a memory instance by default.

Last checked 17 November 2026.

Research detail: Memory sub-nodes such as Postgres Chat Memory store chat history under a session key with a context window length. Nodes share one memory instance unless distinct session IDs are set.

<!-- chunk: products -->
## Products

Simple Memory, Postgres Chat Memory and other memory nodes

<!-- chunk: gaps -->
## Gaps

No access control or retention settings documented for memory stores. Session isolation depends on correct session key expressions.

<!-- chunk: options -->
## Options

Derive session keys from authenticated user IDs and control access at the database.
