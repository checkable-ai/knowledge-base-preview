## Answer

Not covered. No agent-to-agent authentication or authorisation. MCP bearer auth is not per-agent scoped and there is no A2A support.

Research detail: Inside one workflow, the AI Agent Tool node lets a parent agent call sub-agents, with no authentication between them. Across boundaries, a workflow agent can be exposed through the MCP Server Trigger with bearer or header auth, or through instance-level MCP with OAuth or an API key, and called from another agent's MCP Client Tool.

<!-- chunk: products -->
## Products

AI Agent Tool node, MCP Server Trigger, instance-level MCP, MCP Client Tool

<!-- chunk: gaps -->
## Gaps

No A2A protocol support documented. In-workflow agent calls have no authorisation. MCP access is not scoped per client.

<!-- chunk: options -->
## Options

Put cross-boundary agent calls behind MCP Server Trigger with per-caller credentials, or an external gateway.
