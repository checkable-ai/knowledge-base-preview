## Answer

Not covered. Purview policy middleware applies DLP to prompts and responses and FIDES labels stop confidential data leaving via public sinks, but neither filters what data each agent and user can retrieve. No retrieval entitlement filter is documented.

Research detail: Purview policy middleware blocks sensitive content in prompts and responses inline based on DLP policies, and fails closed when it cannot resolve user, tenant or app location. FIDES confidentiality labels stop private or user-identity data leaving through public sinks.

<!-- chunk: products -->
## Products

PurviewPolicyMiddleware, PurviewChatPolicyMiddleware, FIDES

<!-- chunk: gaps -->
## Gaps

Purview needs a Microsoft 365 E5 licence and pay-as-you-go billing. Agent-level Purview middleware does not check tool calls before they run. No retrieval entitlement filter.

<!-- chunk: options -->
## Options

Use the chat-level Purview middleware for full request coverage and enforce retrieval permissions in context providers.
