## Answer

Partly covered. Function tool calls, the framework's usual tool type, are not supported. Non-Azure tools, browser automation, connected agent and computer use tool calls are also not supported. Non-Foundry agents, including locally run or self-hosted Agent Framework agents, get no agentic or tool testing and only the callback-based local scan for content risks. Foundry workflow agents are not supported, so graph workflows are not tested. Retrieval is tested only through mock tool outputs and synthetic data, with no testing of a live retrieval pipeline. Runtime and sandbox testing is missing: mock tools do not mock behaviours, and the vendor says completely locked-down sandboxing is not supported, so attacks are controlled to avoid real-world impact. The framework's own Learn evaluation pages do not offer attack testing; FoundryEvals and local checks only score responses. Agent Framework's Foundry evaluation integration is not available for Go.

Source statement: "The AI Red Teaming Agent currently supported red teaming Foundry agents with Azure tool calls, with the following supportability matrix:" (https://learn.microsoft.com/en-us/azure/foundry/concepts/ai-red-teaming-agent)

Research detail: Checked evaluation and safety pages. Foundry safety evaluators score content harms but the framework does not offer automated adversarial testing of model, retrieval, tool or runtime boundaries.
