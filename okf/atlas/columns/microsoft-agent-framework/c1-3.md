## Answer

Covered. Approval is set per tool (ApprovalRequiredAIFunction in .NET, approval_mode=always_require in Python, ApprovalRequiredFunc in Go). Python binds approval responses to a pending request in the same session by default, and this can be disabled. CodeAct approvals cover the whole execute_code call, not nested calls.

Source statement: "When using functions, it's possible to indicate for each function, whether it requires human approval before being executed." (https://learn.microsoft.com/en-us/agent-framework/agents/tools/tool-approval)

Research detail: Tools marked approval-required pause the run and return the function name and arguments for a human decision, with approve or reject responses. By default an approval only authorises a call that matches a pending request in the same session, and unbound or replayed responses are ignored. FIDES binds approvals to the exact resolved invocation and consumes the grant once.

<!-- chunk: products -->
## Products

ApprovalRequiredAIFunction, approval_mode always_require, ToolApprovalMiddleware, FIDES approval_on_violation

<!-- chunk: gaps -->
## Gaps

Binding can be disabled with disable_approval_response_binding. CodeAct approvals cover the whole execute_code call, not each nested call.

<!-- chunk: options -->
## Options

Keep binding enabled, persist sessions in trusted storage, and keep high-risk tools as direct tools rather than CodeAct host tools.
