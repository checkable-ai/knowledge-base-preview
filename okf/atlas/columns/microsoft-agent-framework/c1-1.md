## Answer

Covered. Python only, in the beta agent-framework-tools package (emits an experimental warning). Needs Docker or Podman on PATH. DockerShellTool must be chosen, because LocalShellTool is not a sandbox. No DockerShellTool guidance for Go and no published DockerShellExecutor sample for .NET. Hyperlight CodeAct is a separate preview option.

Source statement: "The defaults disable networking, run as a non-root user, use a read-only root filesystem, drop capabilities, limit memory to 512 MiB, and cap the container at 256 processes." (https://learn.microsoft.com/en-us/agent-framework/integrations/by-component/tools/shell-tools)

Research detail: LocalShellTool requires approval by default, re-anchors the working directory and supports ShellPolicy regex allow and deny lists. DockerShellTool defaults to no network, non-root, read-only root filesystem and dropped capabilities. Hyperlight CodeAct limits sandboxed code to configured file mounts and allowed domains.

<!-- chunk: products -->
## Products

agent-framework-tools (LocalShellTool, DockerShellTool, ShellPolicy), Hyperlight CodeAct

<!-- chunk: gaps -->
## Gaps

Docs state ShellPolicy is not a security boundary and LocalShellTool is not a sandbox. Shell tools are pre-release. Host tools reached through call_tool run with full host permissions.

<!-- chunk: options -->
## Options

Use DockerShellTool or Hyperlight for untrusted commands, keep approval on, and run the host under least-privileged credentials.
