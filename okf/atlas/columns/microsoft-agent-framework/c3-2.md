## Answer

Not covered. One control point for all tool calls and internet access that itself enforces allowed tools, input formats, limits and blocks on dangerous actions. Nearby features fall short. Foundry Toolbox (beta in the framework) gives a curated MCP endpoint with central authentication and Responsible AI guardrails, but documents no input-format enforcement, call limits or internet access control, and function calling is not supported in a toolbox. Agent Hooks (experimental, Python only) is an interception contract: the customer supplies the interceptors, and it cannot block hosted tools that the provider runs on the server. The Foundry AI gateway (preview) offers rate limits and IP filters through Azure API Management policies, but only for new MCP tools created in the Foundry portal without managed OAuth, and not OpenAPI or code-first MCP tools. FIDES is experimental, Python-only information-flow control. Tool Approval is a human check. Per-tool allowed_tools filters and max_function_calls are settings on individual tools or clients, not a gateway. The Agent Safety page leaves input validation, input and output length limits and rate limiting to the developer.

Research detail: FIDES checks each tool call against content labels and blocks or gates sinks that refuse untrusted or confidential context, and treats MCP server metadata as untrusted by default. Function middleware can reject calls by argument, and Hyperlight restricts sandbox egress to allowed domains.

## Products

FIDES PolicyEnforcementFunctionMiddleware, SecureMCPToolProxy, function middleware, Hyperlight allowed_domains

<!-- chunk: gaps -->
## Gaps

FIDES is experimental, Python-only and unsupported with CodeAct. No tool quotas or rate limits. Host tools are not covered by sandbox egress rules.

<!-- chunk: options -->
## Options

Annotate privileged tools for FIDES, keep them off CodeAct, and enforce egress at the network layer.
