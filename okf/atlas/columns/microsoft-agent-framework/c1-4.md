## Answer

Covered. Foundry-hosted deployment with authorised management access. Creation via azd deploy or SDK, permissions via RBAC assignment to the agent identity, retirement via disable or delete.

Source statement: "This action permanently deletes the agent and all its versions." (https://learn.microsoft.com/en-us/azure/foundry/agents/how-to/manage-hosted-agent)

Research detail: The SDK does not manage agent identities or permissions. Through Foundry hosting, azd deploy creates an immutable agent version, an Entra agent identity and an endpoint, and RBAC for external resources is assigned to that identity.

## Gaps

No documented approval or retirement workflow for agents or permissions. Self-hosted agents rely on application deployment tooling.

## Options

Manage hosted agent versions and RBAC through infrastructure as code and Foundry, with a separate approval process.
