## Answer

Covered. .NET only (not available for Python or Go). Needs a vector store and an embedding model. Retention, deletion and encryption are left to the vector store.

Source statement: "Stored messages are scoped using configurable identifiers (application, agent, user, session) allowing fine-grained control over what history is stored and searchable." (https://learn.microsoft.com/en-us/agent-framework/concepts/agents/conversations/chat-history-memory-provider)

Research detail: Context providers supply long-term memory. The .NET ChatHistoryMemoryProvider stores chat history in a vector store and retrieves it across sessions, scoped by application, agent, user and session. Integrations exist for Mem0, Redis, Cosmos DB and Foundry memory.

<!-- chunk: products -->
## Products

ChatHistoryMemoryProvider, context provider integrations

<!-- chunk: gaps -->
## Gaps

ChatHistoryMemoryProvider is .NET-only. Retention, deletion and encryption are left to the vector store. Retrieved memories are injected as-is without validation.

<!-- chunk: options -->
## Options

Use a store with access control and retention policies, and treat recalled memory as untrusted input.
