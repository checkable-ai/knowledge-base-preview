## Answer

Covered. Foundry-hosted deployment. Approval is a documented workflow step, not a product-enforced gate. No traffic splitting. Draft versions are preview. Previous versions and images must be retained for rollback.

Source statement: "If the release fails its production checks, restore the previous concrete selector and verify new-session behavior again." (https://learn.microsoft.com/en-us/azure/foundry/agents/how-to/manage-hosted-agent)

Research detail: Hosted agent versions are immutable snapshots and an endpoint routes all traffic to one version, so changes ship as new versions. Declarative YAML agents let instructions, model options and schemas be versioned with source. Toolbox configurations are versioned.

<!-- chunk: products -->
## Products

Foundry hosted agent versions, declarative agents, Foundry Toolbox versions

<!-- chunk: gaps -->
## Gaps

No change approval step, traffic splitting or documented rollback command.

<!-- chunk: options -->
## Options

Use pull request review on YAML and image changes and redeploy a prior version to roll back.
