## Answer

Covered, with conditions. Python only, in the beta agent-framework-tools package. DockerShellTool requires Docker or Podman on PATH. DockerShellTool guidance isn't available for Go, and no runnable DockerShellExecutor sample is published for .NET. Hyperlight CodeAct is a separate option for generated code. LocalShellTool runs on the host and isn't a sandbox. Coverage uses self-hosted execution with DockerShellTool for containerised shell execution.

Source statement: "The defaults disable networking, run as a non-root user, use a read-only root filesystem, drop capabilities, limit memory to 512 MiB, and cap the container at 256 processes." (https://learn.microsoft.com/en-us/agent-framework/integrations/by-component/tools/shell-tools)

Last checked 15 November 2026.

Research detail: Hyperlight CodeAct runs generated code in a hardware-virtualised sandbox with read-only input mounts and an outbound allow list. DockerShellTool isolates shell commands in an OCI container. Foundry hosted agents run in per-session VM-isolated sandboxes with optional customer VNet egress.

<!-- chunk: products -->
## Products

Hyperlight CodeAct, DockerShellTool, Foundry Hosted Agents

<!-- chunk: gaps -->
## Gaps

Hyperlight and shell tools are preview or beta. The .NET Hyperlight package cannot restore until its dependency is published. Self-hosted harness hosts are the developer's responsibility.

<!-- chunk: options -->
## Options

Use Hyperlight or Docker for generated code and host the agent in Foundry or a hardened container platform.
