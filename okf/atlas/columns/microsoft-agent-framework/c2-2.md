## Answer

Not covered. No per-agent governance of model version, endpoint, data location, prompt data handling or limits. Provider integration pages only describe choosing an SDK and endpoint; data handling and geographic boundaries are left to the application owner.

Last checked 15 November 2026.

Research detail: Model clients name an explicit provider endpoint and model deployment, and run options include output token limits. The .NET SDK has an experimental routing chat client to switch models per session. The safety page states the framework imposes no input, output or rate limits.

## Products

Chat clients (Foundry, Azure OpenAI, OpenAI, Anthropic and others), RoutePersistingRoutingChatClient

<!-- chunk: gaps -->
## Gaps

Data handling and operating limits sit with the chosen inference provider. Routing is .NET-only and experimental.

<!-- chunk: options -->
## Options

Pin model deployments in configuration and enforce quotas at the provider or an external model gateway.
