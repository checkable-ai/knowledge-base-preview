## Answer

Covered. User and sandbox namespacing, ETag-conditioned writes and 30-day expiry apply to the default Foundry-hosted stores in Python. The hosting package is prerelease. Custom store providers control their own retention and must implement isolation themselves.

Source statement: "New default stores expire sessions 30 days after their last write." (https://learn.microsoft.com/en-us/agent-framework/hosting/foundry-hosted-agent)

Research detail: AgentSession holds conversation state locally or as a service conversation ID and can be serialised and resumed. In Foundry hosting the default session stores are namespaced by platform user and sandbox, use ETag conditional writes, and expire sessions 30 days after last write.

<!-- chunk: products -->
## Products

AgentSession, history providers, FoundryAgentSessionStore

<!-- chunk: gaps -->
## Gaps

Self-hosted apps must bind stored sessions to the authenticated user themselves. Docs warn restoring a session from untrusted storage is untrusted input.

<!-- chunk: options -->
## Options

Store serialised sessions in encrypted, access-controlled storage keyed to the authenticated user or tenant.
