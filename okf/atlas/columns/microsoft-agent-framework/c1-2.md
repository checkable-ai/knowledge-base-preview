## Answer

Covered. Applies to agents hosted in Microsoft Foundry with a Foundry-provisioned Entra agent identity. Foundry assigns no roles automatically; an administrator must grant them. Only some tools (for example MCP and A2A) support agent identity authentication, and the downstream resource enforces the roles.

Source statement: "Per-agent identities let you scope permissions and audit activity to individual agents." (https://learn.microsoft.com/en-us/azure/foundry/agents/concepts/agent-identity)

Research detail: Developers choose the tools per agent or per run, filter MCP tools with allowed_tools, add or remove tools during a run, and reject calls in function middleware. FIDES blocks sink tools when context is untrusted or above a confidentiality cap. Authorisation against the downstream system is left to tool code.

<!-- chunk: products -->
## Products

Agent tools list, MCP allowed_tools, progressive tool exposure, function middleware, FIDES

<!-- chunk: gaps -->
## Gaps

No per-user or role-based permission model in the SDK. Progressive exposure and FIDES are experimental and Python-only.

<!-- chunk: options -->
## Options

Enforce downstream authorisation in each tool, use Toolbox connections scoped per agent identity, and add FIDES sink annotations for privileged tools.
