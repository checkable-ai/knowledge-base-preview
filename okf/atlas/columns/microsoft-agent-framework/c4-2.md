## Answer

Not covered. The framework has no secret store, credential rotation, expiry or revocation. These sit with Entra, Key Vault or the tool provider. Nearby features (MCP header_provider, Foundry Toolbox server-side auth) keep tokens out of model arguments but do not provide short-lived scoped credentials with rotation and revocation.

Research detail: Foundry Toolbox MCP tools use server-side authentication through a Foundry project connection, so the framework client does not hold the upstream MCP bearer token. Local MCP tools accept a header_provider that keeps credentials out of model-supplied tool arguments and strips headers on cross-origin redirects. The framework itself has no secret store, rotation or revocation.

## Products

Foundry Toolbox, MCPStreamableHTTPTool header_provider, hosted agent managed identity

<!-- chunk: gaps -->
## Gaps

Rotation, expiry and revocation sit with Entra, Key Vault or the tool provider. Self-hosted function tools hold whatever credentials the host process has.

<!-- chunk: options -->
## Options

Route MCP and connector auth through Foundry Toolbox connections, use managed identity, and keep secrets in Key Vault rather than environment variables.
