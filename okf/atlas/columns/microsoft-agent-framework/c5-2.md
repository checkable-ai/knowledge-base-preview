## Answer

Not covered. Training agents on their tasks, and detection of anomalous agent behaviour as a feature of the framework. The framework's evaluation framework runs on demand (evaluate_agent, EvaluateAsync, with local checks or FoundryEvals), and its observability feature emits passive OpenTelemetry traces, logs and metrics. Nearby features sit in the separate Foundry service and fall short. The Agent Monitoring Dashboard offers continuous evaluation on sampled live traffic, plus preview alerts configured on latency, token usage, evaluation scores or red team findings. Fleet monitoring describes anomaly detection only as cost spikes, performance degradation and emerging issues found through trend analysis. Neither documents a baseline of agent behaviour or any task training, and the framework docs rely on Foundry for trace visualisation, not for these features. Custom agents would also need onboarding to the Foundry control plane via AI Gateway.

Research detail: The evaluation framework runs local checks and Foundry LLM-as-judge evaluators covering task adherence, tool call accuracy and safety categories, with repetitions to detect non-deterministic behaviour and per-agent workflow breakdowns.
