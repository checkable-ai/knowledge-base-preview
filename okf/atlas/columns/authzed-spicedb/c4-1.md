## Answer

Partly covered. The docs describe each agent having its own AgentIdentity and pin agent bundles by digest, but never tie the identity to a named owner or to where the agent runs. SpiceDB itself does not authenticate identities.

Source statement: "AgentIdentity is the named credential set an agent acts as" (https://openap.org/docs/crd-agentidentity)

Last checked 17 November 2026.

Research detail: AuthZed documents SpiceDB as an authorisation system and says it does not authenticate identities. Agents can be modelled as objects in the permission graph, and Restricted API Access service accounts identify workloads that call SpiceDB. Neither gives a stable agent identity tied to an owner, runtime and release.

## Gaps

In category with nothing documented as a feature. Open Agent Primitives (OAP) says an agent can run with its own identity, but the one blog post that describes it gives no detail.

## Options
