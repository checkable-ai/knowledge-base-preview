## Answer

Not covered. Agent Registry and rogue agent registration give each agent an instance name and ID, but identity is not tied to an owner or a runtime release. Identity comes from the customer's IdP.

Research detail: For rogue agent controls each agent must be registered with a unique instance name and ID, linked to its model proxies, and set up as a service identity in the customer's IdP with tokens carrying the agent identifier. Agent Registry catalogues agents, and MCP server creation records ownership metadata. MuleSoft relies on the IdP for identity rather than issuing one.

## Gaps

No documented link from agent identity to a runtime release. Identity quality depends on the external IdP and on matching CEL selectors.

## Options

Issue agent service identities from the IdP with owner attributes, and test that an unregistered agent ID is rejected at the model proxy.
