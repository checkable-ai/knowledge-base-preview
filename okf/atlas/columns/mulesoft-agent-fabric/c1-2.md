## Answer

Covered. Omni Gateway 1.9.3 or later, Managed or Connected Mode, an authentication policy first.

Source statement: "Controls access to tools, resources, and prompts based on user information such as Tiers, IP, Headers, or Claims" (https://docs.mulesoft.com/gateway/latest/policies-included-mcp-attribute-access-control)

Research detail: MCP Global Access filters tools, resources and prompts with allow and block rules, and MCP Attribute-Based Access Control writes per-tool Cedar rules over client ID, client name and JWT claims after an authentication policy. MCP Bridge publishes only the API operations agents should call, with optional read-only filtering. Both policies need Omni Gateway 1.9.3 or later and are not supported in Local Mode.

<!-- chunk: products -->
## Products

MCP Global Access, MCP Attribute-Based Access Control, MCP Tool Mapping, MCP Bridge

<!-- chunk: gaps -->
## Gaps

Managed and Connected Mode only. Global Access does not scope by consumer. Downstream system authorisation remains the target's job.

<!-- chunk: options -->
## Options

Combine ABAC rules on agent claims with read-only MCP Bridge servers, and test a direct call to the backend API that bypasses the gateway.
