## Answer

Covered. Managed identity as federated credential is preferred; client secrets and long-lived certificates are still permitted. Keeping tokens out of model context depends on agent design.

Source statement: "This integration allows the agent ID to receive the full benefits of MSI security and management, including automatic credential rotation and secure storage." (https://learn.microsoft.com/en-us/entra/agent-id/agent-on-behalf-of-oauth-flow)

Research detail: Credentials sit on the blueprint, not on each agent identity, and managed identities used as federated identity credentials are the preferred type, with automatic rotation. Agents obtain scoped OAuth tokens per resource through multi-stage token exchange, and the Auth SDK sidecar keeps token acquisition out of application code. Disabling a blueprint or agent identity stops authentication.

<!-- chunk: products -->
## Products

Microsoft Entra Agent identity platform, Microsoft Entra ID Auth SDK (sidecar)

<!-- chunk: gaps -->
## Gaps

Client secrets and certificates are still allowed. The sidecar returns bearer tokens to the agent process, so keeping them out of model context depends on the agent's design. Long-lived blueprint credentials are permitted.

<!-- chunk: options -->
## Options

Use managed identity federated credentials only and run the sidecar so the agent never holds blueprint credentials. Test that tokens are not written into prompts or tool outputs.
