## Answer

Not covered. Admins can block Rovo per app, but there is no general sandbox, network egress control, process policy or per-agent stop. Rovo Dev CLI permissions are user level.

Research detail: Rovo Dev CLI sets allow, ask or deny per tool and for bash command patterns, defaults to ask, and limits paths outside the workspace through allowedExternalPaths. Its runInSandbox option is macOS only and marked for internal users. Rovo agents run in Atlassian cloud. Admins can block Rovo per app, which disables Agents and Chat in that app, and can toggle Rovo Dev CLI and code reviews.

Rovo Dev CLI config.yml permissions, Rovo access in Atlassian Administration, Rovo Dev feature toggles

## Gaps

No general sandbox, network egress control or process policy for Rovo Dev CLI. CLI settings are user level. The page gives no time for an app block to take effect, and the Bitbucket section says AI deactivation is not immediate. No per-agent stop was found.
