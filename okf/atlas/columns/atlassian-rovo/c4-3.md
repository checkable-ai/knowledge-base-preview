## Answer

Covered. Applies when the agent uses the user's account option. In automations the agent uses the permissions of the person who builds the automation, not the end user.

Source statement: "The agent will adopt the identity of the person who's using it, inheriting all of their existing permissions and access." (https://support.atlassian.com/studio/docs/understand-rovo-agent-accounts/)

Research detail: With the User's account option the agent adopts the identity and permissions of the person using it, and actions are recorded as performed by the user with the agent's help. Third-party tool actions appear as the user, and A2A and MCP clients act within the authorising user's Atlassian permissions via OAuth.

<!-- chunk: products -->
## Products

Rovo Agents (User's account), Rovo MCP server, A2A connections

<!-- chunk: gaps -->
## Gaps

In automations a User's account agent runs with the full permissions of the person who built the automation, including restricted content. Audit attribution then shows the user, not the agent.

<!-- chunk: options -->
## Options

Use Agent's account for automations, as Atlassian recommends, and review automations built by privileged users.
