## Answer

Covered. Inbound A2A only (third-party agents calling Rovo). Off by default: an org admin must turn on the org-wide Allow A2A toggle in Atlassian Administration, and each user authorises the connection via OAuth 2.1. Access is limited to that user's Atlassian permissions and the org's AI and Rovo access policies. The toggle covers all apps at once, there is no per-agent allowlist, and the A2A pages do not describe audit logging of A2A calls.

Source statement: "When you authorize an A2A connection, you grant the agent access based on your own Atlassian permissions." (https://support.atlassian.com/atlassian-ai-gateway/docs/set-up-agent2agent-connections/)

Research detail: Third-party agents can call Rovo over the Agent2Agent protocol using a user OAuth 2.1 grant, within that user's permissions and org Rovo access policies. A2A is off by default and an org admin enables it with an Allow A2A toggle.

## Gaps

Inbound only as documented. No per-agent trust list, and the toggle applies to all apps. The A2A admin page does not describe audit logging of A2A calls.

## Options
