## Answer

Covered. A2A client channel is part of the GitHub Copilot harness, in preview, and only in early release cycle environments. Requires an Entra app registration with the MCS.InvokeAsA2A delegated permission and a client supporting OAuth 2.0 authorization code flow.

Source statement: "Because each request carries a user identity, Copilot Studio still checks whether that user has access to the agent before it responds." (https://learn.microsoft.com/en-us/microsoft-copilot-studio/agents-experience/publication-channels-mcp-agent-to-agent)

Research detail: Agents can call child agents, other Copilot Studio agents in the environment, and external agents over the A2A protocol, Foundry, Fabric and Microsoft 365 Agents SDK. A2A connections authenticate with none, API key or OAuth 2.0 and use the custom connector infrastructure. Microsoft states the maker is responsible for permissions, boundaries and traceability with external agents.

## Products

Connected agents, A2A agent connections

<!-- chunk: gaps -->
## Gaps

No mutual agent identity or trust boundary model is documented. A2A allows no authentication. Foundry, Fabric and SDK connections are preview. Full chat history is sent in A2A metadata.

<!-- chunk: options -->
## Options

Require OAuth 2.0 on A2A endpoints and govern the underlying custom connectors through data policies.
