## Answer

Not covered. Nearby features: the code interpreter sandbox, which the FAQ says blocks network access, system commands and unauthorized file operations, and admin quarantine. The sandbox covers code execution only, not the agent as a whole. Quarantine is not documented as stopping in-flight work or revoking downstream access at once, and makers can still test a quarantined agent.

Research detail: Admins with Global, AI or Power Platform administrator roles can quarantine an agent through the Power Platform API, which stops interaction in every channel except maker testing. The Microsoft 365 admin center can block an agent across Copilot, Teams and Outlook. Defender real-time protection custom rules block Copilot Studio tool invocations before they run. The GitHub Copilot harness runs each task in a sandbox governed by Copilot Studio.

## Products

Power Platform API agent quarantine, Microsoft 365 admin center block, Microsoft Defender real-time protection, GitHub Copilot harness sandbox

<!-- chunk: gaps -->
## Gaps

The harness sandbox's filesystem, process and network policy is not documented. Quarantine does not support classic chatbots, and Defender protection for Copilot Studio is in preview. Whether quarantine stops an in-flight run is not stated.

<!-- chunk: options -->
## Options

Script quarantine as an incident runbook step, create Defender custom blocking rules, and apply DLP connector policies to limit what a running agent can reach.
