## Answer

Covered. Applies to traffic through the MCP Gateway.

Source statement: "Identity forwarding sends authenticated user information to MCP servers." (https://portkey.ai/docs/product/mcp-gateway/authentication/identity-forwarding.md)

Last checked 17 November 2026.

Research detail: The MCP Gateway can forward the authenticated user's identity to the MCP server as a claims header, the original bearer token or a gateway-signed JWT. Servers using per-user OAuth 2.1 give each user their own tokens, and external identity providers such as Okta and Auth0 are supported for gateway sign-in.

<!-- chunk: products -->
## Products

MCP Gateway identity forwarding, per-user OAuth 2.1, JWT validation

<!-- chunk: gaps -->
## Gaps

Applies to MCP traffic. LLM calls carry user context only through metadata and API keys. Client credentials servers see one shared service identity.

<!-- chunk: options -->
## Options

Use OAuth 2.1 or identity forwarding with signed JWTs for servers that enforce per-user permissions.
