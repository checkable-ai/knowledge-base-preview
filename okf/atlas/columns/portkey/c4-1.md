## Answer

Not covered. No agent identity bound to a named owner, to where the agent runs or to a release is documented. The Agent Registry lists agents and controls access to them, and workspace-scoped API keys tie callers to a workspace, which falls short of an identity per agent.

Last checked 17 November 2026.

Research detail: Admins register agents in the Agent Registry and control access to each one. Service account API keys scoped to a workspace act as the workload credential, and the key ID stays the same through rotation. Nothing documented ties an agent identity to a named owner, runtime or release.

## Products

## Gaps

No agent identity object with owner, runtime and release fields is documented. The registry is for A2A agents that sit behind the gateway.

<!-- chunk: options -->
## Options

Treat the registry entry plus a dedicated service key per agent as the identity and record owner and release in request metadata.
