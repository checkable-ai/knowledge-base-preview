## Answer

Covered. Each deployment is defined in the proxy config with model, endpoint, region_name, timeouts and rpm/tpm limits. Region filtering needs enable_pre_call_checks: true in router_settings. Provider-side prompt data handling follows each provider's terms.

Source statement: "LiteLLM can automatically infer region_name for Vertex AI, Bedrock, and IBM WatsonxAI based on your litellm params." (https://docs.litellm.ai/docs/proxy/reliability)

Research detail: Each model name maps to explicit provider deployments with API base, credentials and per-deployment rpm limits, managed in config.yaml or the model API. Timeouts, context window pre-call checks and region_name filtering for routing are configurable. LiteLLM routes to providers and does not host model weights.
