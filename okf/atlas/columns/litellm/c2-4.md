## Answer

Not covered. No documented retention period or expiry for stored session history; the page only says history is stored in S3 and gives no duration. /v1/memory entries are not session-scoped and have no TTL. The Responses API session feature (previous_response_id, per-user response ID security) covers what is remembered, who reads it and resumption, but falls short on how long it is kept.

Last checked 16 November 2026.

Research detail: LiteLLM uses session IDs (x-litellm-trace-id) to count iterations and spend, with counters expiring after an hour. It does not store session state for agents. Checked the A2A and iteration budget docs.
