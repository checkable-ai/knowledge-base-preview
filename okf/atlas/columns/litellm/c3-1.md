## Answer

Covered. Budgets need Postgres; shared rate limits across instances need Redis; per key or team guardrail control needs an Enterprise licence. Prompt injection screening is enabled via the detect_prompt_injection callback (similarity check or LLM judge).

Source statement: "LiteLLM Supports the following methods for detecting prompt injection attacks." (https://docs.litellm.ai/docs/proxy/guardrails/prompt_injection)

Research detail: Virtual keys enforce allowed models, budgets, TPM, RPM and parallel limits per key, user, team, organisation, agent and customer, with per-model limits. Guardrails run pre_call, during_call and post_call, including built-in prompt injection detection by similarity or LLM check and third-party providers such as Lakera and Bedrock. Per key, team and model guardrail control requires an Enterprise licence.

<!-- chunk: products -->
## Products

Virtual keys, Budgets and Rate Limits, Guardrails, Prompt Injection Detection

<!-- chunk: gaps -->
## Gaps

Budgets need Postgres and fail open without it. Rate limits need Redis to be shared across instances. Several named guardrail integrations need an Enterprise licence.

<!-- chunk: options -->
## Options

Run Postgres and Redis, set default_on guardrails, and test injection detection with a known attack set.
