## Answer

Covered. Scheduled rotation needs LITELLM_KEY_ROTATION_ENABLED=true and a database; key rotation and secret manager integration are Enterprise features.

Source statement: "When a key is due for rotation, LiteLLM automatically regenerates it and invalidates the old key string." (https://docs.litellm.ai/docs/proxy/virtual_keys)

Research detail: Clients authenticate with virtual keys while provider and MCP credentials stay in the gateway. Keys can be scoped to models, given a duration, blocked and unblocked, and capped by upperbound parameters. Key regeneration with a grace period, scheduled auto-rotation and secret manager integration (AWS, Azure, Google, HashiCorp Vault, CyberArk) require an Enterprise licence.

<!-- chunk: products -->
## Products

Virtual keys, Key Rotations (Enterprise), Secret Managers (Enterprise), MCP OAuth

<!-- chunk: gaps -->
## Gaps

Rotation and secret manager storage need an Enterprise licence. Storing virtual keys in a secret manager is off by default. Keeping provider secrets out of model context depends on clients not passing them through.

<!-- chunk: options -->
## Options

Enable rotation_interval and store_virtual_keys under an Enterprise licence, and confirm a blocked or expired key is rejected across all proxy instances.
