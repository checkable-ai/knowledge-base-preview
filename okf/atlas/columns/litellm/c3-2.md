## Answer

Covered. Applies to MCP tool calls through the LiteLLM MCP gateway. Some guardrail integrations and features need an Enterprise licence. General internet egress is not controlled.

Source statement: "Control which MCP servers and tools can be accessed by specific keys, teams, or organizations in LiteLLM." (https://docs.litellm.ai/docs/mcp_control)

Research detail: The MCP gateway enforces allowed servers, tools and tool parameters per key, team, agent and organisation, per-server rate limits and per-server auth config (OAuth, OBO, API key, SigV4). MCP guardrails run pre_mcp_call on arguments and on tool descriptions during discovery, and post_mcp_call on results. Tool Policies classify tools seen in traffic as trusted, untrusted or blocked and block trust-chain violations.

## Products

MCP Gateway, MCP Permission Management, MCP Guardrails, Tool Policies

## Gaps

General internet egress for agents is not controlled. Tool Policy overrides per team or key only block.

<!-- chunk: options -->
## Options

Route all agent tool traffic through the MCP gateway and control other egress at the network layer.
