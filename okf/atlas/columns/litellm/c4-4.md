## Answer

Covered. Callers use LiteLLM virtual keys; admin sets per-key and per-team agent permissions. Explicit-deny default for non-admin keys needs general_settings.agent_access_default_deny: true (v1.108.0+).

Source statement: "A key with no agent selection inherits its team's access." (https://docs.litellm.ai/docs/proxy/access_management/agents)

Research detail: The A2A gateway authenticates callers with a LiteLLM virtual key and checks whether the key and its team may invoke the target agent, returning 403 otherwise. Agents can require a trace ID on inbound calls. The docs do not describe agent-to-agent trust boundaries or mutual authentication between agents.

<!-- chunk: products -->
## Products

LiteLLM Agent Gateway, Agent Permission Management

<!-- chunk: gaps -->
## Gaps

No rules on which agents may call which other agents. Caller identity is not forwarded to the backend agent.

<!-- chunk: options -->
## Options

Give each calling agent its own key restricted to permitted target agents, and authenticate the gateway to backend agents at the agent runtime.
