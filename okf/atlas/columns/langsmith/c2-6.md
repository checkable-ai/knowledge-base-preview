## Answer

Covered. Store TTL applies only to items created after configuration is deployed.

Source statement: "Configuring TTL for store items helps manage memory by removing stale data." (https://docs.langchain.com/langsmith/configure-ttl)

Research detail: Agent Server provides a PostgreSQL-backed long-term memory store with optional vector search, replaceable with a custom store, and store item TTL. Fleet agents keep long-term memory as files in the agent workspace, and memory writes need approval by default.

<!-- chunk: products -->
## Products

Agent Server store, Fleet memory

<!-- chunk: gaps -->
## Gaps

Store TTL applies only to items created after it is configured, and custom stores skip the TTL sweeper.

<!-- chunk: options -->
## Options

Set store.ttl before go-live and restrict store access with authorization handlers.
