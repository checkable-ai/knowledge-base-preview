## Answer

Covered. TTL must be configured (in langgraph.json) for threads and store items. Threads and store items do not expire by default. Store TTL applies only to items created after deployment; delete strategy not retroactive for existing threads. Regional hosting: an organisation cannot span regions.

Source statement: "Setting a TTL automatically deletes or prunes expired data." (https://docs.langchain.com/langsmith/configure-ttl)

Research detail: Trace retention is set per workspace or project with base (14 days) or extended (up to 180 days) tiers, and traces and examples can be deleted through the API. Thread checkpoints and memory store items have TTL policies. Data can be hosted in a regional instance, and SDK masking limits what is stored.

<!-- chunk: products -->
## Products

Data retention, trace deletes, TTL, regions, masking

<!-- chunk: gaps -->
## Gaps

Trace deletes run as a weekend batch with no confirmation. An organisation cannot have workspaces in different regions.

<!-- chunk: options -->
## Options

Set retention per project, configure TTLs and verify deletes by re-querying.
