<!-- chunk: answer -->
## Answer

Covered. Egress policy changes do not reach existing sandboxes; run cancellation is asynchronous unless waited on.

Source statement: "Restricted egress applies to non-Enterprise organizations by default and to organizations that request it." (https://docs.langchain.com/langsmith/sandboxes)

Research detail: Each LangSmith Sandbox is a Firecracker microVM with its own guest kernel. A per-connection egress proxy enforces allow or deny lists, refuses private, loopback and cloud-metadata addresses, and applies access_control changes immediately. The delete API tears down the sandbox runtime, and Agent Server runs can be cancelled with interrupt or rollback.

<!-- chunk: products -->
## Products

LangSmith Sandboxes, sandbox auth proxy, Agent Server run cancellation

<!-- chunk: gaps -->
## Gaps

Run cancellation is asynchronous unless wait=true is set. Organisation restricted-egress policy changes do not reach existing sandboxes. Organisations without restricted egress and without an allow list can reach any hostname on any TCP port. No process policy inside the guest is documented beyond mounts.

<!-- chunk: options -->
## Options

Set an allow_list on every sandbox, cancel runs with wait=true in incident runbooks, and test that deleting a sandbox stops in-flight commands.
