## Answer

Not covered. No documented per-agent identity tied to an owner, runtime location and release. API keys with expiry dates fall short.

Research detail: In agent-based workspaces each agent has an identifier that is set at creation and cannot be changed, and every trace records the agent and one of four fixed environments (Production, Staging, Development, Local). Deployments and assistants attach to the agent. The identifier is a LangSmith resource name, not a workload credential.

<!-- chunk: products -->
## Products

LangSmith agents, agent environments

<!-- chunk: gaps -->
## Gaps

No owner field or runtime attestation is bound to the agent identifier. The agent does not authenticate as itself, it uses API keys or service keys.

<!-- chunk: options -->
## Options

Record owner and release as resource tags or trace metadata and issue workload identity from an identity platform.
