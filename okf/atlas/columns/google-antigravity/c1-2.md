## Answer

Covered. Admin must configure MCP permission rules (allow, deny, ask) per server or tool; unconfigured MCP calls default to ask. Admin MCP allowlist is set via Gemini Enterprise settings.

Source statement: "Matches exact MCP tools or all tools on a specified server (applies equally to local and remote MCP servers)." (https://antigravity.google/docs/permissions/)

Research detail: Permission rules target MCP tools as server/tool, server/* or *, with unconfigured MCP calls defaulting to ask, and disabledTools withholds named tools. Admins can turn MCP off, set a JSON allowlist of local and remote servers, and restrict the browser agent to allowed URLs.

<!-- chunk: products -->
## Products

Antigravity permissions, MCP disabledTools, Gemini Enterprise MCP and external web access settings

<!-- chunk: gaps -->
## Gaps

Rules match tool names, not arguments or downstream resources. Actual downstream rights come from the credential used. The URL allowlist covers only the browser agent.

<!-- chunk: options -->
## Options

Combine the admin MCP allowlist with least-privilege OAuth scopes on each downstream system.
