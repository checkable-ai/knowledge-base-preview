## Answer

Not covered. No scoped short-lived agent credentials, vault or encrypted secret store. Nearby features (MCP OAuth/ADC token refresh, sandbox block on ~/.ssh and .env) fall short: static header secrets sit in plain MCP config and OAuth tokens are held in a local file.

Research detail: MCP servers can authenticate with Google ADC or OAuth, and Antigravity refreshes expired OAuth tokens and removes invalid ones. The terminal sandbox blocks sensitive files such as ~/.ssh and .env. OAuth tokens sit in a local JSON file and static bearer headers are written in plain MCP config.

<!-- chunk: products -->
## Products

Antigravity MCP authentication (google_credentials, OAuth), terminal sandbox

<!-- chunk: gaps -->
## Gaps

No vault integration or encrypted secret store documented. Header secrets are plain text in config. Unsandboxed commands can read any host secret.

<!-- chunk: options -->
## Options

Prefer OAuth or ADC over static headers, keep the sandbox on, and inject secrets through an external secret manager in MCP server wrappers.
