## Answer

Covered. Sandbox off by default in CLI; Windows sandbox in preview; unsandboxed runs use host privileges.

Source statement: "Kernel namespaces isolate the filesystem, hide host processes, and cut off networking." (https://antigravity.google/docs/sandbox/)

Research detail: The terminal sandbox uses Linux kernel namespaces or macOS Seatbelt, mounts only project and granted paths, blocks SSH keys and .env files, and gives sandboxed commands no network except read_url-allowed domains. Deny rules block an action immediately, and Gemini Enterprise admins can enforce sandbox mode, terminal review, and browser and MCP allowlists. A user stops a CLI stream with ctrl+c or esc, and an admin can switch AI developer tools off for a project.

<!-- chunk: products -->
## Products

Antigravity terminal sandbox, permission presets with allow, deny and ask rules, Gemini Enterprise AI developer tools security policies

<!-- chunk: gaps -->
## Gaps

Windows sandbox mode is in preview and the CLI sandbox is off by default. Approved unsandboxed commands run on the host with full privileges. The turn-off page does not say whether running sessions stop at once, and no documented control stops a running background agent or subagent.

<!-- chunk: options -->
## Options

Enforce sandbox mode and Require review through Gemini Enterprise policy, and test how fast the turn-off toggle and IAM role removal end an active session.
