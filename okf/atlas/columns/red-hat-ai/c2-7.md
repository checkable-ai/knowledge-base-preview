## Answer

Not covered. OpenShell agent sandbox is planned; no agent kill switch. OpenShift sandboxed containers are platform features.

Research detail: Red Hat's agent defence guidance runs agent pods in OpenShift sandboxed containers, which wrap each pod in a lightweight Kata VM and are generally available with OpenShift. OpenShift EgressFirewall filters egress by DNS name, and SELinux adds mandatory access control. OpenShell, a process-level agent sandbox with Landlock filesystem allowlists and per-binary egress policy through OPA, is planned for future releases. No agent-specific kill switch is described, so stopping an agent relies on standard Kubernetes and credential controls.

## Products

OpenShift sandboxed containers, OpenShift EgressFirewall, SELinux, OpenShell (planned)

<!-- chunk: gaps -->
## Gaps

OpenShell is planned, not shipped in OpenShift AI 3.5. Sandboxed containers and EgressFirewall are OpenShift platform features rather than Red Hat AI features. No documented one-step stop or access revocation for a running agent.

<!-- chunk: options -->
## Options

Run agent workloads under the Kata runtime class with EgressFirewall rules and no mounted service account tokens. Test stopping an agent by scaling to zero and revoking its Models-as-a-Service and MCP gateway credentials.
