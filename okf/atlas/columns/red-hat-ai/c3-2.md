## Answer

Covered, with conditions. Connectivity Link 1.3 MCP gateway is Technology Preview, with no production support. Per-tool authorisation is set up with a Kuadrant AuthPolicy on the gateway's MCP listener and needs an external identity provider (for example Keycloak) that holds tool roles. Revoked tools are blocked on tools/call but can still appear in listings until a new x-authorized-tools header is issued, and tokens already issued stay valid until they expire. Rate limits come from Connectivity Link's general rate-limiting policies on the gateway. Validation of tool inputs beyond JSON-RPC message structure is not documented.

Source statement: "Provide tool-level authorization to control access to individual MCP tools." (https://docs.redhat.com/en/documentation/red_hat_connectivity_link/1.3/html/registering_mcp_servers_and_creating_policies/mcp-gateway-authorization)

Last checked 13 November 2026.

Research detail: The MCP gateway aggregates MCP servers behind one endpoint, discovers and routes tools, and uses AuthPolicy and rate limiting resources. NeMo Guardrails can enforce PII, prompt injection and content safety rails on agent tool calls at the gateway. Both are Technology Preview.
