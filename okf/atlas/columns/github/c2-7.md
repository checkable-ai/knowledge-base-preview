## Answer

Covered. Cloud agent firewall is on by default and is not a complete security solution. The stop control applies to cloud agent sessions. The local CLI sandbox needs Windows 11 25H2 with BaseContainer, or Bubblewrap and slirp4netns on Linux.

Source statement: "Stopping a session ends the GitHub Actions run and preserves any commits already pushed." (https://docs.github.com/en/copilot/how-tos/copilot-on-github/use-copilot-agents/manage-and-track-agents)

Research detail: Copilot cloud agent runs in an ephemeral GitHub Actions environment behind a firewall that limits internet access to GitHub hosts, a default recommended allowlist and custom rules set by organisation owners. A user can click Stop session, which ends the GitHub Actions run and keeps commits already pushed. The agent can push only to a single branch, and workflows do not run on its code until a person with write access approves them. GitHub states the firewall covers only processes started by the agent's Bash tool, not MCP servers or setup steps, and may be bypassed by sophisticated attacks.

<!-- chunk: products -->
## Products

Copilot cloud agent firewall, Stop session, single-branch push restriction, workflow approval

<!-- chunk: gaps -->
## Gaps

No documented filesystem or process policy inside the runner. The firewall does not cover MCP server processes. Stop session is per session, with no documented enterprise-wide immediate halt of all running sessions. Local Copilot CLI and IDE agent mode run on the developer machine outside this sandbox.

<!-- chunk: options -->
## Options

Enforce the firewall and disable repository custom rules at organisation level. Test whether an MCP server can reach a blocked host. Use enterprise policy to disable the cloud agent as a coarse kill switch and time how quickly running sessions stop.
