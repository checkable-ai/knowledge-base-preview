## Answer

Not covered. The spec states it does not define the scope, representation, validity or revocation of in-task authorisation, and has no user identity propagation format.

Research detail: Authorisation can rest on an end user, a client application or both. An agent can pass an authorisation request back up a chain of tasks with the TASK_STATE_AUTH_REQUIRED state, and in-band credentials SHOULD be bound to the originating agent. The protocol states it does not define the scope, representation, validity or revocation of the resulting authorisation.
