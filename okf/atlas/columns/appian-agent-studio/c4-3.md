## Answer

Not covered. Agents run as the initiator for Appian data, and Appian MCP Server supports user-scoped OAuth inbound, but outbound MCP tools use only API key or OAuth client credentials, so external systems see a shared identity.

Last checked 12 November 2026.

Research detail: Agents run with the initiator's permissions. Every Query Records call is filtered by record-level and field-level security for that user, and sub-agents are invoked as the initiator. Appian MCP Server supports user-scoped OAuth 2.0 with actor attribution, and 26.9 added the OAuth authorisation code grant so clients can call Appian as the signed-in user.

<!-- chunk: products -->
## Products

Initiator-based execution, record-level security, Appian MCP Server OAuth

<!-- chunk: gaps -->
## Gaps

Delegation stops at Appian's boundary. Outbound MCP tools support only API key or OAuth client credentials, so external services see a shared identity.

<!-- chunk: options -->
## Options

Keep sensitive external actions behind Appian process models that apply user checks, and test with low-privilege initiators.
