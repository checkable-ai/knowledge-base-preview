## Answer

Not covered. No per-agent workload identity tied to owner, runtime and release; URLs and IDs identify objects and region but do not bind an identity to where the agent runs.

Last checked 11 November 2026. This platform is checked on demand, so this answer has not been rechecked since.

Research detail: Each agent has a stable agent ID within a project and region, and audit events carry the agent ID and published version ID. The creator becomes the asset admin. Agents run with the credentials configured on their tools rather than an identity of their own.
