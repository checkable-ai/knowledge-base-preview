## Answer

Covered.

Source statement: "Each agent can have its own sandbox + tool policy: full access, read-only, or no access." (https://docs.openclaw.ai/gateway/security/tool-permissions.md)

Last checked 17 November 2026.

Research detail: Operator scopes limit what each Gateway client can do, node command policy limits remote execution on paired devices, and per-agent tool profiles can deny messaging, cron, session spawning and control-plane tools. Cross-provider messaging can be confined to the current conversation. Channel pages add DM and group allowlists and action gates.

<!-- chunk: products -->
## Products

Operator scopes, per-agent tool policy, node command policy, channel allowlists, cross-provider messaging limits

<!-- chunk: gaps -->
## Gaps

Cross-provider messaging is allowed by default. Operator scopes are collaboration guardrails and not tenant isolation.

<!-- chunk: options -->
## Options

Apply the documented untrusted-content deny list and per-agent access profiles to every agent that reads external content.
