## Answer

Covered. Sandboxing is off by default and must be enabled. The docs say the sandbox is not a perfect security boundary, and tools.elevated runs exec outside the sandbox.

Source statement: "OpenClaw can run tool execution inside a sandbox backend to limit the damage tools can cause." (https://docs.openclaw.ai/gateway/sandboxing)

Last checked 17 November 2026.

Research detail: Sandboxes limit filesystem and process access, the browser has a strict SSRF policy, and an optional secret egress proxy can bind secrets to destinations. Operators can stop the Gateway, close exposure and rotate credentials. Each throwaway cloud worker holds a minted credential that is rotated and fenced.

<!-- chunk: products -->
## Products

Sandbox backends, browser SSRF policy, secret egress proxy, incident response runbook, token rotation

<!-- chunk: gaps -->
## Gaps

No single documented kill switch revokes a running agent. Sandbox network egress policy for general tools was not read and the sandbox is not a perfect boundary.

<!-- chunk: options -->
## Options

Define a runbook with gateway stop, token rotation and node revocation and test it.
