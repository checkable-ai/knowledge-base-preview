## Answer

Covered. Works only for HTTP MCP servers with oauth.identity set to per-requester, and needs gateway.publicOrigin set to the externally reachable HTTPS origin of the Gateway. The docs advise using it only in channels where every sender is mutually trusted, and a requester-private sign-in handoff is tracked as follow-up work.

Source statement: "OpenClaw returns a sign-in link for that sender instead of exposing another sender's credentials." (https://docs.openclaw.ai/cli/mcp/transports)

Last checked 17 November 2026.

Research detail: When an agent asks the openclaw delegation tool to change configuration, the change is checked against the requesting run's current delegation authority, which is revalidated before effects. Gateway scopes and trusted-proxy auth carry the operator identity inside the Gateway. Propagation of the initiating user to other downstream services is not documented.

<!-- chunk: products -->
## Products

openclaw delegation tool, operator scopes, trusted proxy auth

<!-- chunk: gaps -->
## Gaps

Delegation is documented for Gateway administration only. Downstream services see the credentials configured for the agent, not the initiating user.

<!-- chunk: options -->
## Options

Use per-user OAuth for MCP servers where supported and keep one trust boundary per Gateway.
