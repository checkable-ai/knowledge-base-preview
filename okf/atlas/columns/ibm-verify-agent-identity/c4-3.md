## Answer

Covered. Public preview.

Source statement: "The `may_act.sub` carries the Agent ID" (https://www.ibm.com/docs/en/agent-identity?topic=agent-generate-obo-token-agents-act-behalf-user)

Research detail: An OAuth 2.0 token exchange combines a user subject token, whose may_act claim names the agent, with the agent's actor token. The delegated token carries the user as sub and the agent in act, scoped and bound to a target audience, so resource servers see who authorised and which agent acted.
