## Answer

Not covered. Sandbox ttl and terminate and project key revocation exist, but no network egress, filesystem or process policy and no stated revocation timing.

Research detail: The Together code sandbox runs code in isolated runtime environments with a default 1 vCPU and 2 GiB of memory, an optional ttl set at creation, and a terminate call or CLI command that permanently ends a sandbox and discards its filesystem unless a snapshot alias is given. Project-scoped API keys can be revoked by project admins, and the docs advise revoking a leaked key immediately.

<!-- chunk: products -->
## Products

Together code sandbox (terminate, ttl, --rm), project API key revocation

<!-- chunk: gaps -->
## Gaps

The sandbox page does not say whether isolation is a microVM or container, and covers no network egress control or filesystem and process policy. Sandboxes persist until ended unless a ttl is set. The docs do not say how quickly a revoked project key takes effect, and legacy keys cannot be revoked, only regenerated. No stop control for a running inference or fine-tuning job was checked.

<!-- chunk: options -->
## Options

Set a ttl on every sandbox, test that a revoked key fails in flight requests, and add an external egress control for sandbox code.
