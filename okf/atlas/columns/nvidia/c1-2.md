## Answer

Covered. Set per MCP function group (include/exclude) and per token or A2A scope, not centrally.

Source statement: "The function group supports filtering using the `include` and `exclude` parameters." (https://docs.nvidia.com/nemo/agent-toolkit/latest/build-workflows/mcp-client.html)

Research detail: The MCP client limits which server tools become workflow functions with include and exclude lists. A2A servers enforce OAuth scopes, and the MCP auth guidance says to scope OAuth2 tokens to minimum permissions.

<!-- chunk: products -->
## Products

MCP client function groups, A2A server_auth scopes

<!-- chunk: gaps -->
## Gaps

Scopes are set per tool list or token, not as a central per-agent policy over connected systems.

<!-- chunk: options -->
## Options

Combine include lists with least-privilege OAuth scopes at each downstream service.
