## Answer

Not covered. The mcp_oauth2 provider stores per-user tokens separately, but the vendor documents no token revocation feature, rotation is guidance only (use environment variables or a secrets manager), and nothing guarantees secrets stay out of model context.

Research detail: The toolkit mcp_oauth2 provider obtains OAuth2 tokens per user and stores them separately per user in a configurable backend, with encryption recommended for external stores. Dynamic client registration credentials are cached for a configurable oauth_client_ttl. Security guidance says to keep secrets in environment variables or a secrets manager and rotate them.

NeMo Agent Toolkit authentication providers (mcp_oauth2, oauth2_auth_code_flow, service account auth)

## Gaps

Revocation and whether tokens can reach model context are not described. Rotation is guidance, not a feature.

## Options
