## Answer

Covered. Cowork cloud sessions; Enterprise-managed auth on Team and Enterprise with listed IdP and connectors. Token lifetime and rotation set by the IdP and connector. Local Cowork and Claude Code credential handling not covered.

Source statement: "Connector authorization tokens never enter the sandbox; connector calls are made on the server side." (https://support.claude.com/en/articles/14479288-claude-cowork-architecture-overview)

Research detail: In Cowork cloud sessions connector tokens stay server side and the sandbox holds only session tokens that expire within hours. Enterprise-managed auth (Team and Enterprise, Okta at launch, listed connectors only) issues connector access from the IdP and revokes it on deprovisioning. The 1Password integration (off by default, macOS) fills credentials in Chrome without Claude seeing them.

<!-- chunk: products -->
## Products

Cowork cloud sandbox, Enterprise-managed auth for connectors, 1Password for Claude

<!-- chunk: gaps -->
## Gaps

Token lifetime and rotation are set by the IdP and connector, not by Anthropic. Managed auth supports Okta and ten named connectors. Local Cowork and Claude Code credential handling is not covered by these pages.

<!-- chunk: options -->
## Options

Use managed auth for supported connectors and test that IdP deprovisioning ends connector sessions.
