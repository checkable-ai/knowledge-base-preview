## Answer

Not covered. Identity is per session or service user, with no registered agent identity tied to owner, runtime and release.

Research detail: Service users are non-human identities with an RBAC role, added to organisations independently of humans and shown separately in audit logs. Each cloud session also gets a short-lived OIDC token carrying org_id, devin_id, devin_trigger, requesting user and service_user_id claims. Identity is per session or per service user, not a stable per-agent identity tied to a release.

<!-- chunk: products -->
## Products

Service users, Devin OIDC session tokens

<!-- chunk: gaps -->
## Gaps

No registered agent identity linking an agent definition to its owner, runtime and version. Local Cascade and Devin Local agents run as the signed-in user.

<!-- chunk: options -->
## Options

Use one service user per automation or integration, name it after the owning team, and key cloud trust policies on OIDC claims.
