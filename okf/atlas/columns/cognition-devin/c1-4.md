## Answer

Not covered. No lifecycle object for an agent; service users and PATs are managed but agent configuration changes have no approval step.

Research detail: Admins create, change and delete service users and assign roles through the UI or v3 API, with key create, rotate and revoke actions recorded in audit logs. SCIM provisions and deprovisions users and groups, and a PAT policy can require admin approval and mandatory expiry. Security profiles and automations carry the agent's configuration.

## Products

Service users API, SCIM, PAT policy, security profiles

## Gaps

No lifecycle object for an agent itself. Custom subagents and plugins are files in repos with no approval step.

<!-- chunk: options -->
## Options

Provision service users and automations through API with change control, and govern plugin manifests via required and forbidden lists.
