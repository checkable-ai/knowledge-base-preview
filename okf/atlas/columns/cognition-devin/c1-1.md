## Answer

Covered. Devin CLI and Devin Local; Cascade has a separate max autonomy setting. OS sandbox not supported on Windows.

Source statement: "An allow rule never overrides a matching deny, regardless of how specific the allow rule is." (https://docs.devin.ai/cli/reference/permissions)

Research detail: Devin CLI and Devin Local use allow, ask and deny rules for file reads, writes, commands, HTTP fetches and MCP tools, with deny always winning and organisation rules taking top precedence. An OS-level sandbox restricts filesystem and network access, and admins can force sandbox mode with domain allow and deny lists. For Cascade, admins cap the maximum autonomy level and can restrict it to the workspace.

<!-- chunk: products -->
## Products

Devin CLI permissions, Devin Sandbox, Maximum autonomy level, Restrict Cascade to workspace

<!-- chunk: gaps -->
## Gaps

Bypass mode auto-approves everything unless org deny or ask rules apply. Edit and write tools run outside the sandbox. Org overrides replace root lists rather than merging them.

<!-- chunk: options -->
## Options

Enforce sandbox and org deny rules from team settings, cap Cascade autonomy, and test sandbox escapes.
