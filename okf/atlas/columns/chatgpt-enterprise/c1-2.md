## Answer

Covered. Role-specific app access and per-action controls are Enterprise and Edu; Business admins can only enable or disable an app. Only some limits have UI controls; other fields are configured through TOML.

Source statement: "Which commands the agent can run, which require approval, and which it cannot run." (https://learn.chatgpt.com/docs/enterprise/agent-security)

Research detail: Admins set per-app access by role, enable individual read and write actions, and choose whether new actions are enabled. Custom MCP apps start with new actions disabled and show changes as a diff. Workspace agent builders can add action constraints such as limiting email recipients to a domain. Role-specific app access is Enterprise and Edu only.

<!-- chunk: products -->
## Products

Plugins page in Admin Console, app action controls, custom MCP action control, workspace agent action constraints

<!-- chunk: gaps -->
## Gaps

Business admins can only enable or disable an app for the workspace. Some apps have no configurable actions. Action constraints do not filter data returned by an app.

<!-- chunk: options -->
## Options

Set new actions to disabled and review each app's write actions before enabling.
