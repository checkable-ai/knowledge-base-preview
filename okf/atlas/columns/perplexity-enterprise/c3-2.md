## Answer

Not covered. Perplexity documents no control point that validates tool-call input formats, enforces per-tool rate or usage limits, or blocks dangerous actions in the call itself. The nearby features fall short of that: the Computer Network Firewall Policy controls domain-level egress only, connector enablement and per-tool Allow, Always ask or Disable settings decide which tools can be reached, and Comet domain permissions restrict browsing. Perplexity also says it cannot verify third-party MCP servers.

Research detail: Tool access is governed by organisation connector enablement, per-tool Allow, Always ask or Disable with admin locks for Microsoft 365, and a toggle that blocks member-added custom MCP connectors. Computer sandbox egress is controlled by the network firewall policy, and Comet agent actions by domain permissions.

## Products

Connector permissions, custom connector controls, Network Firewall Policy, Comet domain permissions

## Gaps

No documented schema validation, per-tool rate limits or screening of tool output for injection. Perplexity states it cannot verify third-party MCP servers.

<!-- chunk: options -->
## Options

Keep member custom connectors off and route custom MCP servers through Cloudflare Access or PrivateLink.
