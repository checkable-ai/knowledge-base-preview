## Answer

Covered. The Sandbox API is experimental and may change without notice. Dedicated sandboxes give VM-level isolation. Pooled sandboxes suit workloads within one trust boundary only.

Source statement: "A Job is a real VM, so this gives the strongest isolation (VM-level), supports any hardware flavor including GPUs, and is the right choice for mutually-untrusted code." (https://huggingface.co/docs/huggingface_hub/en/concepts/sandbox)

Research detail: Sandboxes run code in an isolated cloud VM built on Jobs, with a documented trust model. Dedicated sandboxes give VM-level isolation. Pooled sandboxes use separate uids and Landlock and are meant for one trust boundary only. Spaces allow outbound requests only on ports 80, 443 and 8080.

<!-- chunk: products -->
## Products

Sandboxes (huggingface_hub, experimental), Jobs, Spaces

<!-- chunk: gaps -->
## Gaps

The Sandbox API is experimental. Outbound TCP is not isolated in pools. No egress allowlist is documented for dedicated sandboxes.

<!-- chunk: options -->
## Options

Use dedicated sandboxes for untrusted code and kill them after each workload. Add egress controls outside Hugging Face.
