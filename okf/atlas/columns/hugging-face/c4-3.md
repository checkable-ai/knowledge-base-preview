## Answer

Covered. Enterprise plan. Needs an organisation-bound OAuth app with the token-exchange privilege, set up via Hugging Face support. Tokens reach organisation resources only (outside it, read-only public collections and gated repos the user was granted). Anyone holding the client secret can issue tokens for any member.

Source statement: "The token's effective permissions are limited both by the requested scope and by the user's role within the organization." (https://huggingface.co/docs/hub/oauth)

Research detail: OAuth apps can act on behalf of a user with scopes such as inference-api and write-repos. On Enterprise, Token Exchange (RFC 8693) lets a backend issue a token for a named organisation member, limited by requested scope and the member's organisation role, and each exchange is written to the audit log.

## Products

Sign in with Hugging Face OAuth scopes, OAuth Token Exchange (Enterprise)

<!-- chunk: gaps -->
## Gaps

Delegation reaches Hugging Face services only. No propagation of user identity to downstream non-Hugging Face systems. Token Exchange identifies the user by email, and the client secret can mint tokens for any member.

<!-- chunk: options -->
## Options

Restrict Token Exchange client secrets to a hardened backend and review exchange events in audit logs.
