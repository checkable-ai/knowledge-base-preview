## Answer

Partly covered. Vercel Agent itself has no separate identity record. The OIDC token claims name the team, project and environment, but no release or deployment, and Vercel Agent changes are attributed to the requesting user. Per-agent identity exists only as a workload identity for agents you deploy as projects, or as separate Linux users inside one Vercel Sandbox.

Source statement: "If you change the name of your team or project, the claims within the OIDC token will reflect the new names." (https://vercel.com/docs/oidc/reference)

Last checked 17 November 2026.

Research detail: Vercel Agent works inside a selected team and project. Its Vercel changes are attributed to the requesting user via Vercel Agent, and its GitHub commits come from the Vercel Agent GitHub App. Activity Log events name the user and record session and approval steps. There is no separate agent identity record linking an owner, runtime and release.

## Products

Vercel Agent attribution, Vercel Agent GitHub App, Activity Log events

<!-- chunk: gaps -->
## Gaps

The agent acts as the user for Vercel changes, so the agent is not a distinct identity there. Release linkage for the agent itself is not described.

<!-- chunk: options -->
## Options

Treat the Vercel Agent GitHub App and the approving user as the agent identity and record the team's agent settings in your register.
