## Answer

Covered. Applies to tools on MCP servers reached through the AI MCP Server entity. A per-tool ACL fully overrides the default tool ACL, with no merging. CEL-based ACLs need Kong Gateway 3.16 or later data planes.

Source statement: "The request is denied with HTTP 403." (https://developer.konghq.com/ai-gateway/entities/ai-mcp-server/)

Last checked 16 November 2026.

Research detail: AI MCP Server ACLs filter tools/list and check each tools/call per consumer, consumer group or OAuth token claim, with deny rules winning. OAuth2 scoping can give write tools stricter access than read tools, and 2.1.0 added CEL allow_when and deny_when expressions. AI Models and AI Agents carry their own allow or deny ACLs.

<!-- chunk: products -->
## Products

AI MCP Server access.acls, AI Auth Strategy, AI Model and AI Agent ACLs

<!-- chunk: gaps -->
## Gaps

Applies only to systems reached through the gateway. Tool annotations such as destructive do not change runtime behaviour.

## Options
