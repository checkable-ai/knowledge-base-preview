## Answer

Not covered. No per-agent identity tying an owner, runtime and release together. The Catalog agent card carries a name, description and version, and the entry can link to a gateway implementation, but no owner or runtime binding is documented. AI Consumers and AI Auth Strategies identify callers only.

Last checked 16 November 2026.

Research detail: Callers are identified as AI Consumers, resolved by an AI Auth Strategy from an API key or an OIDC token claim. Kong Identity issues client credentials whose client ID becomes the consumer's custom_id, giving a machine identity for an agent. Upstream agents are registered as AI Agent entities with an immutable name.

## Products

AI Consumer, AI Auth Strategy, Kong Identity, AI Agent entity

<!-- chunk: gaps -->
## Gaps

No documented link from a consumer identity to an owner, runtime or release version. Identity is per gateway caller, not a workload attestation.

<!-- chunk: options -->
## Options

Use labels and naming conventions to carry owner and release, or pair with a workload identity system such as SPIFFE and map its claims to consumers.
