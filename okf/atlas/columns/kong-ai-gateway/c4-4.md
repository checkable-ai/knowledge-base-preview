## Answer

Covered. Access is controlled at the agent level, not per skill. Callers need an AI Consumer identity via an AI Auth Strategy (one strategy per AI Agent).

Source statement: "Access is enforced before traffic reaches the upstream agent." (https://developer.konghq.com/ai-gateway/entities/ai-agent/)

Research detail: AI Agent entities of type a2a proxy A2A traffic and require callers to authenticate through an AI Auth Strategy (key-auth or OIDC). ACLs allow or deny AI Consumers, consumer groups or authenticated groups before traffic reaches the upstream agent, and the gateway can sign upstream requests with AWS SigV4.

<!-- chunk: products -->
## Products

AI Agent entity, AI Auth Strategy, access.acls

<!-- chunk: gaps -->
## Gaps

Access is controlled at the agent level, not per skill. Upstream authentication beyond SigV4 is not described. The getting-started guide configures no authentication.

<!-- chunk: options -->
## Options

Configure OIDC auth strategies on every agent and test that a denied consumer gets 403 for agent card and message calls.
