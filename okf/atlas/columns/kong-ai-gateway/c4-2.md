## Answer

Not covered. Token Vault (AI MCP Server entity) issues per-caller short-lived credentials cached for at most 5 minutes, but the vendor documents no rotation or revocation lifecycle for them. It also documents no guarantee that secrets never reach the model. AI Vaults hide provider keys but leave rotation to the backing vault.

Research detail: Provider and upstream credentials are held in AI Vaults (HashiCorp Vault, AWS, GCP, Azure, CyberArk Conjur or the write-only Konnect Config Store) and resolved by reference at request time, so callers never see the provider key. The AI MCP OAuth2 plugin strips the caller's token before forwarding by default and can exchange it for a different token, cached until its expiry. Changelog 2.2.0 adds Token Vault support for short-lived upstream credentials.

## Gaps

Rotation is left to the backing vault and cache settings. Token Vault has a changelog entry but no dedicated documentation page was found. Token exchange is Enterprise tier.

<!-- chunk: options -->
## Options

Use a dynamic secrets backend with short cache TTLs and test revocation propagation through the gateway cache grace period.
