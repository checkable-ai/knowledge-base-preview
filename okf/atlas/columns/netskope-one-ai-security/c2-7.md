## Answer

Not covered. No documented limits on an agent's files or processes and no per-agent kill switch. MCP traffic blocking and Agent Action Control (beta) act on network and tool traffic only.

Research detail: Netskope controls agent network traffic from its proxy. A Real-time Protection policy on the MCP Server category with a Block action stops all MCP traffic, or only chosen activities such as CallToolRequest. Agent Action Control (beta, formerly Agent Guardrails) applies intent, risk and access based policies to agent actions across 70 agents and 79 apps. Netskope does not sandbox agent code or set filesystem and process policy on the host.

<!-- chunk: products -->
## Products

Real-time Protection policies for MCP traffic, Agent Action Control (beta), Agentic Broker.

<!-- chunk: gaps -->
## Gaps

The pages give no timing for a block to take effect and do not say whether it covers endpoint client traffic, cloud traffic or both. Agent Action Control needs Netskope Support to enable it. There is no per-agent revoke of credentials.

<!-- chunk: options -->
## Options

Pilot a block policy on a test MCP server and time it from save to the first blocked event, and pair with a host sandbox for execution containment.
