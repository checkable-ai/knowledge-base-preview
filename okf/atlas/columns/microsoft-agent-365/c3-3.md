## Answer

Covered. Purview DLP applies to Teams, OneDrive, SharePoint and email interactions. Agents are unaware of blocks, and retrieval from non-Microsoft stores is not covered.

Source statement: "Supported by explicitly specifying agent instances in the DLP policy as you would a user, or by specifying a security group that includes agent instances." (https://learn.microsoft.com/en-us/purview/ai-agent-365)

Research detail: Purview DLP can include agent instances as users to block or audit agent-to-human and human-to-agent content in Teams, OneDrive, SharePoint and email. Sensitivity label encryption must grant the agent VIEW and EXTRACT rights, and files must be explicitly shared with agent instances. SharePoint restricted access control can limit which agents reach a site.

<!-- chunk: products -->
## Products

Microsoft Purview DLP and sensitivity labels, SharePoint Advanced Management

<!-- chunk: gaps -->
## Gaps

DLP locations are limited and the agent is unaware of a block. New content created by agents does not inherit labels. Retrieval from non-Microsoft stores is not covered.

<!-- chunk: options -->
## Options

Add agent instances to DLP policies, enable labels for SharePoint and OneDrive, and monitor DLP outcomes for broken workflows.
