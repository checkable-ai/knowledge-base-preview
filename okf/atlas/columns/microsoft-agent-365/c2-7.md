<!-- chunk: answer -->
## Answer

Not covered. No limits on files, processes or network egress. Block and disable actions give a stop but not the limits the outcome also requires.

Research detail: Admins can block an agent across the organisation, soft delete or permanently delete it, and stop the Azure infrastructure behind a Foundry agent from the Microsoft 365 admin center. Defender real-time protection custom rules block matching tool invocations before they run for Agent 365 tools through Work IQ MCP, and Defender for Endpoint can block local agent actions. Agent 365 does not host agent code, so it supplies no sandbox, filesystem or egress policy of its own.

<!-- chunk: products -->
## Products

Microsoft 365 admin center agent actions, Microsoft Defender real-time protection, Defender for Endpoint runtime protection

<!-- chunk: gaps -->
## Gaps

Blocking a SharePoint or Foundry agent only affects Microsoft Copilot Chat. Admin actions fail on agents behind Power Platform Firewall in active enforcement mode. The default Defender rule audits only, and agents without Work IQ MCP integration are not covered. Endpoint runtime protection is in preview. Propagation time for a block is not stated.

<!-- chunk: options -->
## Options

Create Defender custom blocking rules for high-risk scenarios, use Entra Agent ID and Conditional Access to revoke access, and keep the Power Platform API quarantine route in the runbook for firewalled environments.
