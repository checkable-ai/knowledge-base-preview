## Answer

Covered. Entra Agent ID is available to all Entra customers, but extending Entra security features (Conditional Access, risk detection, network controls) to agents requires Microsoft Agent 365 (included in Microsoft 365 E7, or an add-on to E5/A5/Business Premium). Trust boundaries come from standard Entra tenant and permission scoping, not a dedicated A2A policy model.

Source statement: "The platform supports standard protocols such as OAuth 2.0, Model Context Protocol (MCP), and agent-to-agent (A2A) for authentication and agent-to-agent communication." (https://learn.microsoft.com/en-us/entra/agent-id/what-is-microsoft-entra-agent-id)

Research detail: Agent identities authenticate to other agents as Entra-protected resources, and risk-based Conditional Access can block risky agents from accessing resources or other agents. Foundry supports the agent identity for A2A tools, and Purview audits agent-to-agent interactions. Admins can connect up to 10 agents to an agent in the registry.

<!-- chunk: products -->
## Products

Microsoft Entra Agent ID, Conditional Access for agents, Purview Audit, registry Connected Agents tab

<!-- chunk: gaps -->
## Gaps

No documented A2A protocol support in Agent 365 itself or trust-boundary model for cross-tenant agent calls. Connected Agents applies to Microsoft 365 Copilot agents.

<!-- chunk: options -->
## Options

Register the receiving agent as an Entra resource, require tokens for each call and test that Conditional Access blocks unapproved agent callers.
