## Answer

Not covered. API keys are long-lived with optional expiry. Ephemeral tokens exist only for browser and mobile voice clients. Remote MCP tokens are supplied by the developer per request, and Grok Build stores MCP OAuth tokens in a local file. No short-lived scoped credential issuance for agents generally.

Research detail: API keys support expiry, a rotate endpoint with a grace period for the old secret, disable and delete, and GitHub secret scanning. Ephemeral tokens keep API keys out of browser voice clients. In Grok Bot, connector OAuth tokens stay on Cursor's backend and Bots invoke tools without receiving them, and masked secret requests keep values out of the transcript and away from the model.

<!-- chunk: products -->
## Products

Management API key rotation, ephemeral tokens, Grok Bot connector backend and Team Secrets, Grok Build auth_provider_command

<!-- chunk: gaps -->
## Gaps

Remote MCP on the API passes an authorization token supplied by the developer in each request. Grok Build stores MCP OAuth tokens in a local file. Grok Bot brokerage is Cursor-operated.

<!-- chunk: options -->
## Options

Pair API keys with a secrets manager and short expiry. Use Grok Build's external auth provider to mint short-lived tokens.
