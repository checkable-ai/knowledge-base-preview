## Answer

Partly covered. The vendor says Auto Review does not review every side effect, naming memory writes and most settings changes, and says it should complement explicit boundaries and least privilege. No documented checks on tool input formats, no limits or quotas on tool calls, and no per-tool allowlisting within an MCP server, because the MCP allowlist controls only which servers and hosts a Bot can reach. No equivalent gateway exists for the xAI API or Grok Build.

Source statement: "It does not review every side effect." (https://docs.x.ai/grok-bot/security)

Research detail: Remote MCP limits tools per server with allowed_tools, and web search can restrict or exclude up to 5 domains. Grok Build has per-tool allow and deny rules including MCPTool and WebFetch, plus PreToolUse hooks. Grok Bot Enterprise adds an MCP allowlist, Auto Review and a destination allowlist for egress.

<!-- chunk: products -->
## Products

Remote MCP allowed_tools, web search domain filters, Grok Build permissions and hooks, Grok Bot network controls

<!-- chunk: gaps -->
## Gaps

No central per-agent tool policy for API workloads. Grok Build hook failures fail open. Grok Bot network controls default to allow-all.

<!-- chunk: options -->
## Options

Front MCP servers with a tool gateway. Pin Grok Build rules in requirements.toml.
