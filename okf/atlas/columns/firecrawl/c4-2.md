## Answer

Partly covered. No documented key or token expiry or scheduled rotation, static API keys do not expire by default, and there is no brokering of credentials for other systems an agent uses.

Source statement: "The client opens a browser, the user signs in and picks a team, and Firecrawl creates a dedicated key for that connection." (https://docs.firecrawl.dev/authentication.md)

Last checked 17 November 2026.

Research detail: MCP sign-in creates a dedicated key per connection that the client never sees, and OAuth refresh tokens rotate and work once. Keys can be revoked at any time and the webhook secret can be regenerated. Static keys do not expire by default and there is no brokered delivery of downstream secrets.

<!-- chunk: products -->
## Products

API keys, MCP OAuth connections, OAuth for apps, webhook signing secret

<!-- chunk: gaps -->
## Gaps

No documented key expiry or scheduled rotation. Firecrawl brokers its own access only, not credentials for other systems an agent uses.

<!-- chunk: options -->
## Options

Prefer OAuth connections over pasted keys, rotate keys on a schedule outside the product and restrict each key.
