## Answer

Not covered. No distinct per-agent identity tying owner, runtime and release. Agents run as the signed-in user or a robot account.

Research detail: Agents are published as versioned solution packages (1.0.0, incremented on each republish) and deployed into Orchestrator folders. At run time a conversational agent executes as the signed-in user on UiPath-authenticated channels, or as an unattended robot account on anonymous channels. The documentation does not describe a distinct workload identity issued to each agent.

## Products

Solutions packages, Orchestrator robot accounts, Serverless robots

## Gaps

No per-agent identity linking owner, runtime and release. Audit records the user or robot account, not the agent. A shared robot account hides which agent acted.

<!-- chunk: options -->
## Options

Assign one robot account or external application per agent workload and record the mapping. Test what identity appears in Orchestrator audit for a Maestro-run agent.
