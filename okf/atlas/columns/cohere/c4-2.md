## Answer

Not covered. The documented short-lived tokens are for external systems and service accounts authenticating to North through federated identity. They are not scoped credentials issued to agents for tools, and they have no documented rotation or revocation. Static custom headers remain static.

Research detail: North holds each user's OAuth access tokens for connectors they have authorised and forwards them to MCP tool servers in the request auth header, outside model context. Custom MCP servers can be added to an agent with a static shared secret header, and Cohere's Wiz example keeps the downstream service account credentials on the MCP server. Rotation, expiry, scoping and revocation of the tokens North holds are not documented.

## Gaps

No documented token storage, rotation, expiry or revocation. Raw connector tokens are passed to the MCP server rather than exchanged for narrower ones. Shared secret headers are static. North admin documentation is not public (the Cohere customer hub needs a login), so launch posts, product pages and the public North MCP SDK repository were used.
