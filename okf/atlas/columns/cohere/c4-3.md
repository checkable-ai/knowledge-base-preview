## Answer

Covered. Documented for custom MCP servers via the public North MCP Python SDK. Servers must set trusted_issuers to verify tokens in production.

Source statement: "You can access the user's identity (from the identity provider used with North)." (https://github.com/cohere-ai/north-mcp-python-sdk)

Research detail: North sends an X-North-ID-Token from the user's identity provider with each MCP tool call, and servers can restrict accepted issuers with trusted_issuers. The same request carries the user's own OAuth tokens for authorised connectors, so the tool server can call Google Drive, Slack or GitHub on that user's behalf. The North 2 post says North integrates with existing identity and access management systems.

## Products

North MCP integration, North MCP Python SDK, North connectors

<!-- chunk: gaps -->
## Gaps

Documented for custom MCP servers through the public SDK. Behaviour of built-in connectors is not documented. Tokens are passed through unchanged with no downscoping, and ID token signatures are only verified when trusted_issuers is set.

<!-- chunk: options -->
## Options

Set trusted_issuers on every MCP server and test that a built-in SharePoint or Jira connector honours the calling user's own permissions.
