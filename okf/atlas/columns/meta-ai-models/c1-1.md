## Answer

Covered. Muse Code only. The --yolo and --disable-sandbox flags remove the limits.

Source statement: "The sandbox limits filesystem writes and network access, and refuses to run if it cannot enforce that boundary." (https://dev.meta.ai/docs/muse-code/permissions.md)

Research detail: Muse Code sets local scope through permission profiles (Ask me, Auto-review, Unrestricted, Read-only), approval modes, deny-over-allow prefix rules and an OS sandbox that allows writes only to the workspace and a temp directory. .git, .muse and .agents stay read-only and the sandbox fails closed if it cannot be confirmed.

<!-- chunk: products -->
## Products

Muse Code permissions and sandbox

<!-- chunk: gaps -->
## Gaps

--yolo and --disable-sandbox remove all limits. Hooks and MCP tools run outside the sandbox. Default Auto-review lets an LLM judge decide eligible requests.

<!-- chunk: options -->
## Options

Pin Read-only or Ask me profiles in managed configuration and block --yolo in CI images.
