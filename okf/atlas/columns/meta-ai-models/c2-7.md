## Answer

Covered. Muse Code CLI only. --yolo and --disable-sandbox remove containment. Stopping is by ending the local process.

Source statement: "The sandbox limits filesystem writes and network access, and refuses to run if it cannot enforce that boundary." (https://dev.meta.ai/docs/muse-code/permissions.md)

Research detail: Muse Code runs shell commands under an OS sandbox (Seatbelt on macOS, bundled bubblewrap on Linux, Windows sandbox) that allows writes only to the workspace and a temp directory and keeps .git, .muse and .agents read-only. Network mode is proxy-only by default with per-destination approval, or restricted with no network. A live probe confirms enforcement and the tool call fails before it starts if containment is not proven. A killed Muse Code process leaves an append-only log and can be resumed, and Model API background responses can be cancelled.

<!-- chunk: products -->
## Products

Muse Code OS sandbox and network proxy, Model API cancel response

<!-- chunk: gaps -->
## Gaps

The --yolo and --disable-sandbox flags remove containment for a run. Stopping a session is documented only as killing the local process. No central admin kill switch or immediate key revocation path for a running agent is documented. Cancel applies only to background responses. The hosted Model API offers no server-side code execution.

<!-- chunk: options -->
## Options

Block --yolo and --disable-sandbox through managed settings or CI policy, run with --sandbox-network restricted where possible, and delete API keys to cut access during an incident.
