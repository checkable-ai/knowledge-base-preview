## Answer

Covered. Muse Code only. Allow/deny rules and approval policy must be configured. MCP tools are not OS-sandboxed.

Source statement: "A deny rule always overrides an allow rule, whatever the specificity." (https://dev.meta.ai/docs/muse-code/permissions.md)

Research detail: Muse Code's default proxy-only network mode asks for approval for each new host, port or protocol, and TCP approval rules are limited to the exact host and port. MCP tool calls go through approval unless the server declares them read-only, and approved plugin allowed-tools skip prompts for that turn. The Model API has only one tool_choice mode and no allowed-tools parameter.

<!-- chunk: products -->
## Products

Muse Code network sandbox, MCP approvals, plugin allowed-tools

<!-- chunk: gaps -->
## Gaps

MCP tools are not sandboxed and the docs do not describe MCP allowlists. Read-only status is self-declared by the server.

<!-- chunk: options -->
## Options

Restrict MCP servers through managed settings and front them with a tool gateway that enforces per-tool scopes.
