## Answer

Covered. Applies to Muse Code only. The --yolo and --disable-sandbox flags remove the sandbox. Hooks and MCP tools run outside it.

Source statement: "The sandbox limits filesystem writes and network access, and refuses to run if it cannot enforce that boundary." (https://dev.meta.ai/docs/muse-code/permissions.md)

Last checked 16 November 2026.

Research detail: Muse Code runs shell commands under an OS sandbox (Seatbelt, bubblewrap, Windows sandbox) with workspace-only writes, a network proxy and a live probe that fails closed. The Linux sandbox drops all capabilities. The Model API offers no server-side code execution tool, so execution is local.

<!-- chunk: products -->
## Products

Muse Code sandbox

<!-- chunk: gaps -->
## Gaps

Not a container or VM. Hooks and MCP tools run outside it, and flags can disable it.

<!-- chunk: options -->
## Options

Run Muse Code inside a disposable container for untrusted repositories as the docs advise for --yolo.
