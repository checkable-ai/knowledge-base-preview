## Answer

Covered. Requires API keys with suitably restricted privileges per calling agent; Agent Builder A2A server.

Source statement: "Both A2A endpoints require API key authentication." (https://www.elastic.co/docs/explore-analyze/ai-features/agent-builder/a2a-server)

Research detail: Agent Builder exposes agents over the A2A protocol with a metadata endpoint and a protocol endpoint, both requiring an API key. A read-only key can limit what the calling agent can do. The page documents no per-agent trust boundary or mutual authentication.

<!-- chunk: products -->
## Products

Agent Builder A2A server

<!-- chunk: gaps -->
## Gaps

API key only. No allowlist of caller agents and no agent card signing documented. Streaming unsupported and confirmation prompts cannot be answered over A2A.

<!-- chunk: options -->
## Options

Issue one scoped API key per calling agent and place an A2A gateway in front for pairing policy.
