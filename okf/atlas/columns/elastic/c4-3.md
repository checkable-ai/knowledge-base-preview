## Answer

Covered. OAuth 2.1 MCP access is Serverless only. Agent Builder tools otherwise run with the current user's or API key's privileges. No user propagation to external MCP servers.

Source statement: "Each person consents separately and gets their own connection, acting with their own permissions" (https://www.elastic.co/docs/explore-analyze/ai-features/agent-builder/mcp-server)

Research detail: Agent Builder tools run Elasticsearch requests with the privileges of the current user or API key, so DLS and FLS apply per user. On Serverless, MCP clients connecting with OAuth 2.1 act with the authorising user's live permissions. Elasticsearch also supports run_as impersonation through the es-security-runas-user header. User identity is not propagated to external MCP servers, which receive static connector headers.

<!-- chunk: products -->
## Products

Agent Builder tool execution identity, MCP server OAuth, run_as

<!-- chunk: gaps -->
## Gaps

OAuth for the MCP server is Serverless only. API key callers share one identity. No user propagation to external MCP or third-party services.

<!-- chunk: options -->
## Options

Use OAuth on Serverless or per-user API keys, and front external MCP servers with an OBO-capable gateway.
