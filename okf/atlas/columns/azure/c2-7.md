## Answer

Covered. Disabling an agent identity or blueprint needs Agent ID Administrator in Entra. Tenant-wide Conditional Access blocking needs Microsoft Entra ID P1. Hosted agents run in VM-isolated sandboxes. Docs do not state the effect on tokens already issued; Foundry Stop prevents new runs but does not terminate existing runs.

Source statement: "Conditional Access policies can block authentication and token issuance of agent identities." (https://learn.microsoft.com/en-us/entra/agent-id/disable-agent-identities)

Research detail: Foundry Code Interpreter runs agent-written Python in a sandboxed container, and Azure Container Apps dynamic sessions give Hyper-V isolated sandboxes with optional network controls. Foundry Agent Service Standard Setup with private networking places agent compute in a customer subnet with no public egress. Entra Agent ID lets admins disable an agent identity or blueprint to stop token issuance, and Conditional Access can block agent authentication tenant wide.

<!-- chunk: products -->
## Products

Foundry Code Interpreter, Azure Container Apps dynamic sessions, Foundry private networking, Microsoft Entra Agent ID

<!-- chunk: gaps -->
## Gaps

When Code Interpreter is used through a toolbox in a hosted agent, all users in a project share one container. Disabling an identity blocks new tokens, and the effect on tokens already issued and work in flight is not stated.

<!-- chunk: options -->
## Options

Give each user or workload its own project or session pool, and test how fast a disabled agent identity stops a running agent.
