## Answer

Partly covered. Azure Machine Learning does not actively scan compute nodes for vulnerabilities while they are in use. Nodes that are not idle cannot be updated to the latest VM image, and deployed compute instances are not actively updated. Microsoft Defender for Servers agent installation on compute instances is not supported. Once a customer adds dependencies or brings their own base images, vulnerability management is theirs. No hardening or scanning of the Foundry Agent Service hosted tool runtime is documented.

Source statement: "Although OS VM images are regularly patched, Azure Machine Learning doesn't actively scan compute nodes for vulnerabilities while they're in use." (https://learn.microsoft.com/en-us/azure/machine-learning/concept-vulnerability-management?view=azureml-api-2)

Research detail: Source statement: Hosted agents have managed execution. Defender assesses supported container assets.

Assessment: Customer container scanning coverage must be verified for the hosting path.
