## Answer

Not covered. Snowflake documents that agent monitoring traces in the AI observability event table record user, role, tool calls, timestamps and agent version, and that entries can't be modified. The page does not say entries can't be deleted, does not describe tamper detection or integrity validation, and documents no write-once storage or export to such storage. The nearby feature (the event table with the no-modification statement) falls short of the 'no entry altered or deleted without detection' outcome, and the vendor does not state it meets part of the outcome.

Research detail: Each Cortex Agent turn is a trace in SNOWFLAKE.LOCAL.AI_OBSERVABILITY_EVENTS with spans for planning, tool execution, SQL and response, recording inputs, outputs, user, role and warehouse, and Snowflake states entries cannot be modified. Cortex AI Gateway records span metadata for every request in an event table queried with AGENT_TRACE_TABLE, with prompt and response capture off unless enabled and client traces accepted by OTLP when turned on.

## Products

AI_OBSERVABILITY_EVENTS, Cortex AI Gateway AGENT_TRACE_TABLE

<!-- chunk: gaps -->
## Gaps

Gateway traces do not record content by default, records over 1 MB are truncated, and the gateway page does not state immutability or retention. Reasoning capture depends on the model and surface.

<!-- chunk: options -->
## Options

Enable gateway logging with payload capture for regulated agents, restrict MONITOR, and test whether a privileged role can delete gateway trace rows.
