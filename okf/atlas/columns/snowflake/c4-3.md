## Answer

Covered. Permissions follow the caller's Snowflake role. Owner's rights procedures and Cortex Search run with owner's rights, so propagation is not uniform for those tools.

Source statement: "Cortex Agents determines permissions from the Snowflake context of the request" (https://docs.snowflake.com/en/user-guide/snowflake-cortex/cortex-agents)

Research detail: Cortex Agents determine session permissions from the querying user's default role, and each tool runs with Snowflake privileges for that caller. Cortex Analyst runs generated SQL under the calling role, CoWork applies the user's RBAC and masking policies, and MCP connectors use per-user OAuth to the third-party service. Stored procedure tools keep their owner's or caller's rights setting, and Cortex Search runs with owner's rights.

<!-- chunk: products -->
## Products

Cortex Agents, Cortex Analyst, Snowflake CoWork, MCP connectors

<!-- chunk: gaps -->
## Gaps

The default role is used, not the session role. Owner's rights procedures and Cortex Search break pure user propagation, and the run API can exclude code execution under owner's rights.

<!-- chunk: options -->
## Options

Use caller's rights procedures for custom tools, set user default roles deliberately, and test with a low-privilege user.
