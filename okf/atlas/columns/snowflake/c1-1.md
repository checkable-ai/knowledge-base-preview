## Answer

Covered. Code execution tool must be enabled per agent. PyPI packages need the owner to hold the PYPI_REPOSITORY_USER role. Filesystem and process policy is not customer-configurable.

Source statement: "The sandbox has read and write access to the workspace stage location mounted into it" (https://docs.snowflake.com/en/user-guide/snowflake-cortex/cortex-agents-code-execution-tool)

Research detail: The code execution tool runs Python in a sandbox that can only access data passed into the session and the mounted workspace stage. It cannot query data or reach arbitrary stages, skill stages are read-only, and PyPI packages need the owner to hold PYPI_REPOSITORY_USER. The tool is enabled per agent in the spec.

<!-- chunk: products -->
## Products

Cortex Agents code execution tool

<!-- chunk: gaps -->
## Gaps

No configurable per-agent filesystem or process policy beyond enabling the tool and package repositories. General outbound network rules for the sandbox are not described.

<!-- chunk: options -->
## Options

Leave code execution off for agents that do not need it, and test sandbox egress and file access before production.
