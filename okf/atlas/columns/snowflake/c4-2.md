## Answer

Not covered. OAuth token exchange gives one-hour role-scoped tokens, but there is no endpoint to revoke a single delegated token, rotation is only by repeating the exchange, and keeping secrets from the model is guidance rather than an enforced control.

Research detail: MCP connectors keep OAuth client credentials in an API integration, each user authorises the third-party service, and disabling the integration invalidates all user tokens and calls the server's revocation endpoint. Refresh token lifetime is set with OAUTH_REFRESH_TOKEN_VALIDITY, which defaults to never expiring. Custom tools reach external services through SECRET objects referenced in UDF and procedure handler code instead of literal values.

<!-- chunk: products -->
## Products

API integrations, external MCP server objects, SECRET objects, external access integrations

<!-- chunk: gaps -->
## Gaps

Secret rotation is not documented beyond replacing or altering the secret. The pages do not state that secret values are kept out of model context. Default refresh token validity is unlimited.

<!-- chunk: options -->
## Options

Set a finite OAUTH_REFRESH_TOKEN_VALIDITY, keep secrets inside handler code, and test whether tool results can echo secret material back into the agent.
