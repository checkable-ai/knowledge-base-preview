<!-- chunk: answer -->
## Answer

Covered. The client application must implement the approval prompt. Applies to tools that return permission options, such as the code execution tool.

Source statement: "A non-empty options list means the client must prompt the user for approval before the tool is executed." (https://docs.snowflake.com/en/user-guide/snowflake-cortex/cortex-agents-run)

Research detail: A response.tool_use event can carry a permission object, and a non-empty options list means the client must prompt the user before the tool runs. The client returns a permission_decision tied to that tool use, and a denial reason is passed to the model. The code execution tool defaults to permission_policy always_ask.

<!-- chunk: products -->
## Products

Cortex Agents run API permission handling, code execution permission_policy

<!-- chunk: gaps -->
## Gaps

Approval is documented for code execution, not as a general per-tool policy. Replay protection and approver authorisation are not described, and the client application must implement the prompt.

<!-- chunk: options -->
## Options

Keep always_ask on, build the approval prompt in the client, and test that a decision cannot be reused for a different tool_use_id.
