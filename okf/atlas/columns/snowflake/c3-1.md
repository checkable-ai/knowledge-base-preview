## Answer

Not covered. The objection is right. The gateway page says only traffic through the gateway picks up its controls, so it is not a control point every call must pass through. It documents no rate limits or routing policies. Per-user spend quotas cover only the cost part of the outcome.

Research detail: Model-level RBAC through SNOWFLAKE.MODELS application roles controls which roles can use each model, replacing the deprecated CORTEX_MODELS_ALLOWLIST. Cortex AI Gateway, in public preview, is an account-level object whose specification sets the exposed models, with USAGE and MONITOR privileges per role. Per-user quotas set monthly or daily limits that block AI functions, Cortex Agents, CoWork, CoCo and the gateway, and gateway spend can be pooled into tag-based team budgets. Cortex AI Guardrails screen for prompt injection and jailbreaks on Cortex Agents, CoWork and CoCo.

## Products

SNOWFLAKE.MODELS RBAC, Cortex AI Gateway, per-user quotas, resource budgets, Cortex AI Guardrails

<!-- chunk: gaps -->
## Gaps

Guardrails for third-party traffic through the gateway and dynamic model routing are announced as coming soon, not available. The gateway is in preview. Quotas apply within minutes and team budgets can lag up to hours. Rate limits per agent are not documented.

<!-- chunk: options -->
## Options

Expose only approved models in the gateway specification and grant USAGE to named roles. Test a quota block on gateway traffic and measure overrun.
