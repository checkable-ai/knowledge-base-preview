## Answer

Covered. Gemini Enterprise with Model Armor and observability logging enabled. For ingress traffic the customer joins Model Armor logs to StreamAssist logs in their own SIEM or log pipeline. Needs Cloud Trace User and Logs Viewer roles. Prompt and response content logging is optional. The customer assigns the response owner.

Source statement: "To correlate these logs with user identities and trace spans, you perform a log join" (https://docs.cloud.google.com/gemini/enterprise/docs/correlate-model-armor-logs)

Research detail: Gemini Enterprise usage logs mark fields as sensitive and elide them when prompt logging is off, carry session and user pseudo IDs, and can be routed by sinks. Model Armor verdicts appear in audit logs. Gemini CLI telemetry carries session.id and user.email and can drop prompts.

<!-- chunk: products -->
## Products

Gemini Enterprise usage audit logs, Model Armor logs, Gemini CLI OpenTelemetry

<!-- chunk: gaps -->
## Gaps

No built-in detections or response ownership. CLI logs prompts by default.

<!-- chunk: options -->
## Options

Send logs to a SIEM, as the security overview recommends, and write detections there.
