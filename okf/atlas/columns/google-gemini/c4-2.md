## Answer

Covered. Gemini API managed agents, Public Preview. Revocation is by deleting the credential.

Source statement: "The agent now makes authenticated requests to api.github.com, and the token never exists inside the sandbox." (https://aistudio.google.com/docs/agent-credentials)

Research detail: Gemini API managed agents store secrets as managed credentials referenced by ID, and an egress proxy injects them at request time so they are never exposed inside the sandbox. Gemini Enterprise holds OAuth client details in authorization resources for A2A agents and connector actions. Rotation, expiry and revocation of these credentials are not documented.

<!-- chunk: products -->
## Products

Gemini API managed agents credential injection, Gemini Enterprise authorization resources

<!-- chunk: gaps -->
## Gaps

Managed agents are in Public Preview. No documented rotation or expiry for managed credentials. Gemini API keys are static and rotated manually.

<!-- chunk: options -->
## Options

Use short-lived tokens as the managed agents page advises, keep long-lived keys in Secret Manager, and test whether injected credentials ever reach model context.
