## Answer

Covered. Gemini Enterprise registered agents with authorization configured per agent. Not available in the Gemini API or CLI.

Source statement: "Gemini Enterprise Admin" (https://docs.cloud.google.com/gemini/enterprise/docs/register-and-manage-an-a2a-agent)

Research detail: Gemini Enterprise can register an OAuth authorization for an A2A agent. After the end user consents, it sends that user's OAuth token in the Authorization header so the agent acts on the user's behalf. Connector retrieval preserves source ACLs per user.

<!-- chunk: products -->
## Products

Gemini Enterprise A2A authorization, Gemini Enterprise connectors

<!-- chunk: gaps -->
## Gaps

OAuth propagation is optional and set per agent. Without it, Cloud Run agents receive a Google-signed service ID token, not the user identity. Gemini API and Gemini CLI have no OBO model.

<!-- chunk: options -->
## Options

Require OAuth authorization on every registered agent and validate tokens at the agent or an Apigee proxy.
