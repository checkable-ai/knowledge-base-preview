## Answer

Covered. Managed agents (Public Preview) with a network allowlist configured, since egress is open by default. Gemini CLI sandboxing is opt-in.

Source statement: "When an allowlist is set, only requests to explicitly listed domains are permitted." (https://aistudio.google.com/docs/agent-environment)

Research detail: Gemini API managed agents run in a Google-hosted Linux sandbox isolated at the OS level, with open outbound access by default that a network allowlist can restrict, and secrets injected by an egress proxy. Gemini CLI offers opt-in sandboxing (Seatbelt profiles, Docker or Podman, gVisor, LXC) with writes confined to the project directory and proxied network profiles, and admins can enforce the Docker sandbox through the system settings file. Gemini Enterprise admins can suspend, disable or delete an agent. None of the pages read documents a cancel operation for a running API interaction or Jules task.

<!-- chunk: products -->
## Products

Gemini API managed agents, Gemini CLI sandboxing and system settings, Gemini Enterprise agent states, Jules VM

<!-- chunk: gaps -->
## Gaps

CLI sandboxing is off unless enabled. Managed agent egress is open by default. No documented cancel for a running interaction. Google states the CLI enterprise controls are not a foolproof security boundary. Jules network policy is not described.

<!-- chunk: options -->
## Options

Enforce the CLI sandbox and coreTools allowlist in system settings, set a network allowlist on managed agents, and test whether disabling a Gemini Enterprise agent stops an in-flight run.
