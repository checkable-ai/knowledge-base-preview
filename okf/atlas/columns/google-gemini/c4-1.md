## Answer

Not covered. No per-agent identity bound to owner, runtime and release. API keys identify a project, and Gemini Enterprise agents are registered resources.

Research detail: Gemini Enterprise agents are named resources managed through AgentService, with owners, states and audit-logged create, update and delete operations. Gemini API managed agents are created as API resources, up to 1,000 per project. None of the documentation describes a workload identity per agent linked to a runtime and release.

<!-- chunk: products -->
## Products

Gemini Enterprise agents, Gemini API managed agents

<!-- chunk: gaps -->
## Gaps

No per-agent workload credential or binding to a release version is documented. Gemini API keys identify a project, not an agent.

<!-- chunk: options -->
## Options

Pair agents with Google Cloud service accounts or Workload Identity in the Google Cloud column, and record agent ID, owner and version in an external registry.
