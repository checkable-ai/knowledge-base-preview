## Answer

Covered. Gemini CLI only. Admin policies are system-wide per machine.

Source statement: "Administrators can enforce system-wide policies (Tier 4) that override all user and default settings." (https://geminicli.com/docs/reference/policy-engine/)

Research detail: Gemini CLI has a policy engine that allows, denies or asks the user for each tool call, matching tool name, argument regex and shell command prefix, with an admin tier loaded from system directories. Admins can allowlist tools with tools.core and disable YOLO mode. Trusted folders disable project settings, MCP servers and auto-accept in untrusted directories.

<!-- chunk: products -->
## Products

Gemini CLI policy engine, system settings, trusted folders

<!-- chunk: gaps -->
## Gaps

The enterprise page says these patterns are not a foolproof boundary against users with local admin rights. Trusted folders are off by default.

<!-- chunk: options -->
## Options

Deploy admin policy files and the system settings file through device management, and enable trusted folders and sandboxing.
