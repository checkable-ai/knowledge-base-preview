## Answer

Covered, with conditions. Hooks are a guardrail, not a complete enforcement boundary. Managed hooks on Work Cloud support only MCP tool handlers. Enterprise tooling must install and update hook scripts separately. WebSocket transport is experimental and unsupported.

Source statement: "PreToolUse can intercept Bash, file edits performed through apply_patch, MCP tool calls, and other local function tools." (https://learn.chatgpt.com/docs/hooks)

Research detail: The Codex CLI, IDE extension and desktop app run tools through one harness with sandboxing, approvals, command rules, hooks at tool and session events, and MCP support. Admin-managed hooks are trusted by policy and user hooks need hash-based trust.

## Products

Codex CLI and app harness, hooks, rules

## Gaps

Managed hooks on cloud orchestration support only MCP tool handlers, and a callback error can fail without blocking the tool.

<!-- chunk: options -->
## Options

Use allow_managed_hooks_only and test hook failure behaviour.
