## Answer

Covered. Codex cloud environments only; OIDC for cloud resources is by request for Enterprise. Plain environment variables and local credentials are not covered.

Source statement: "Programs receive a placeholder; the proxy substitutes the real value for allowed destinations." (https://learn.chatgpt.com/docs/environments/cloud-environments)

Research detail: Cloud environments offer network secrets: programs see a placeholder and the proxy substitutes the real value for allowed HTTPS destinations. Tasks can get short-lived cloud credentials through OIDC, by request for Enterprise. Access tokens have admin-set expiry limits, rotation and revocation.

<!-- chunk: products -->
## Products

Cloud environment network secrets, OIDC for cloud resources, access tokens

<!-- chunk: gaps -->
## Gaps

Secrets set as plain environment variables reach processes directly. Locally, credentials sit in auth.json or the OS keyring, and MCP bearer tokens come from environment variables. OIDC is by request only.

<!-- chunk: options -->
## Options

Use network secrets and OIDC in cloud environments and an external secrets manager for local and CI runs. Test whether an agent can read a substituted secret.
