## Answer

Covered. Requires per-user sign-in to connected services; the connected service applies the signed-in account's permissions.

Source statement: "the connected service still decides which data the signed-in account can read." (https://learn.chatgpt.com/docs/enterprise/roles-and-workspace-permissions)

Research detail: Connected systems decide what the signed-in account can reach: Codex cloud respects source repository permissions and MCP servers support per-user OAuth. Access tokens act as the creating user, so runs use that user's access.

<!-- chunk: products -->
## Products

MCP OAuth, plugin connections, Codex access tokens

<!-- chunk: gaps -->
## Gaps

No documented token exchange or chained delegation that carries the initiating user to downstream services. Workspace connections use a shared company account, not the user.

<!-- chunk: options -->
## Options

Prefer per-user OAuth connections over shared connections and check downstream logs show the end user.
