## Answer

Not covered. No documented admin emergency stop that halts all Codex activity and cuts access at once. Nearby features fall short: sandbox and permission profiles limit files and network, and turning off Local computer access with Work Cloud interrupts running turns, but only for that one mode. The admin page says to treat access removal, task interruption and data retention as separate actions.

Research detail: Codex runs local commands in an OS sandbox (Seatbelt on macOS, bwrap and seccomp on Linux, MXC on Windows) and cloud tasks in isolated OpenAI-managed containers with the agent phase offline by default. The workspace-write mode keeps .git, .codex and similar paths read-only, network is off by default, and a command proxy enforces allow and deny domain rules that admins can lock through Agent Security. Stopping is weaker: admins revoke access tokens (which stop new runs only), remove users, or turn off local computer access, which interrupts running turns.

<!-- chunk: products -->
## Products

Codex sandbox modes, network_proxy and Agent Security managed networking, access token revocation, cloud-local access setting.

<!-- chunk: gaps -->
## Gaps

The proxy does not filter web search, app or MCP calls, browser activity or model requests. There is no single admin switch to halt all Codex activity, and the docs do not say whether revoking a token stops an in-flight run. In the CLI the documented stops are /archive and closing the session.

<!-- chunk: options -->
## Options

Test token revocation and the local access toggle against a running cloud task, and lock sandbox and network settings through managed requirements.
