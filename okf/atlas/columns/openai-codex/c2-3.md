## Answer

Covered, with conditions. Locally, the OS sandbox may not work when Linux runs in a container such as Docker. Cloud runs in OpenAI-managed containers. The network proxy does not cover web search, connectors, MCP or browser activity, and DNS rebinding protection is not complete. Pro, Business, Enterprise, Edu and Edu Pro default VMs have 4 vCPUs, 16 GiB memory and 32 GiB disk. Larger VMs and custom specifications are available for Enterprise.

Source statement: "Locally, Codex uses an OS-enforced sandbox that limits what it can touch (typically to the current workspace)." (https://learn.chatgpt.com/docs/agent-approvals-security)

Last checked 18 November 2026.

Research detail: Local runs use OS sandboxes (Seatbelt on macOS, bwrap with seccomp on Linux, MXC on Windows) with network off by default in workspace-write and a managed proxy for domain rules. Cloud tasks run in isolated VMs with internet off by default.

<!-- chunk: products -->
## Products

Codex sandbox, network proxy, Codex cloud VMs

<!-- chunk: gaps -->
## Gaps

DNS rebinding protection is best effort. Windows network support is limited. Cloud environments do not inherit local device policy.

<!-- chunk: options -->
## Options

Keep network off by default and use permission profiles with the proxy feature so domain rules are enforced.
