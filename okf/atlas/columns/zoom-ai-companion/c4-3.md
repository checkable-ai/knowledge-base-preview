## Answer

Covered. Requires admin mapping of Zoom users to accounts in the connected system and permission alignment between Zoom and the external platform.

Source statement: "Access to connected third-party content depends on permission alignment between Zoom and the external platform." (https://library.zoom.com/ai/ai-whitepaper/zoommate.md)

Research detail: ZoomMate connectors apply source-system permissions. Admins map Zoom users to accounts in the connected system, usually by email, indexed content carries native permission metadata, and real-time MCP access is limited to what the user can currently access. User-level sources such as email and calendar are read live through the API at request time.

<!-- chunk: products -->
## Products

ZoomMate connectors, account-level and user-level sources

<!-- chunk: gaps -->
## Gaps

The mapping is by email address and the docs do not describe token-based propagation of the user identity to downstream services. Custom agent tool calls through MCP do not document whose identity is used.

## Options

Verify permission trimming with test users across separate folders and confirm whether MCP tools act per user or with a shared credential.
