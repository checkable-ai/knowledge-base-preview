## Answer

Covered. Only in the Custom policy template. Blocking sensitive info types in prompts is in preview. Label-based exclusion covers emails sent on or after 1 Jan 2025. Files uploaded into prompts are not scanned. Policy updates can take up to four hours. Admin unit support is rolling out. Licensing per Microsoft 365 enterprise plans.

Source statement: "You can create a DLP policy to prevent these Copilot experiences from using files and emails that have sensitivity labels when generating responses." (https://learn.microsoft.com/en-us/purview/dlp-microsoft365-copilot-location-learn-about)

Research detail: Purview enforces data access for AI per user and agent: sensitivity labels require VIEW and EXTRACT rights before AI apps return content, DLP excludes labelled items from Copilot responses, and Azure AI Search can enforce labels at query time for RAG apps. DLP policies can scope agent instances and custom apps can call Purview APIs inline.

<!-- chunk: products -->
## Products

Sensitivity labels, DLP for Microsoft 365 Copilot location, Azure AI Search label enforcement, Purview APIs, Endpoint DLP

<!-- chunk: gaps -->
## Gaps

Strongest for Microsoft 365 content. Foundry policy enforcement needs user-context tokens and developer integration. ChatGPT Enterprise and Claude Enterprise agents lack label and DLP support.

<!-- chunk: options -->
## Options

Test label enforcement with a RAG app on Azure AI Search and a DLP policy scoped to an agent instance.
