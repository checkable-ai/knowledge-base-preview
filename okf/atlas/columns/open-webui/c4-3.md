## Answer

Covered. OAuth mode works only when users sign in through the same OAuth provider and the token has the scopes the server needs. Session mode sends the user's Open WebUI session token and suits servers that authenticate against Open WebUI itself. MCP servers can only be added by administrators.

Source statement: "OAuth: Sends the access token from the user's Open WebUI SSO sign-in as a bearer token." (https://docs.openwebui.com/features/extensibility/mcp)

Research detail: API keys inherit the creating user's role and group permissions, and those are re-checked on every request. For MCP and OpenAPI tool servers an admin can pick the Session or OAuth mode so the user's own Open WebUI or SSO token reaches the tool server. Tools attached to a model only work for users who have read access to them.

<!-- chunk: products -->
## Products

API key inheritance, MCP Session and OAuth auth modes, per-user tool access checks

<!-- chunk: gaps -->
## Gaps

Delegation is a bearer token pass-through. No token exchange, audience scoping or downstream authority limits are documented. Admin-configured tool servers can use a shared key instead.

<!-- chunk: options -->
## Options

Use the OAuth mode with an identity provider that issues audience-scoped tokens and test what the tool server enforces.
