## Answer

Covered, with conditions. Applies when Open Terminal runs in Docker; in bare metal mode the agent runs with the user's full permissions. Egress allowlist needs --cap-add NET_ADMIN. Restricted security context applies to Kubernetes and OpenShift backends only. Terminals needs an Open WebUI Enterprise License for production use.

Source statement: "The container reaches exactly one path on your machine, the volume you mounted." (https://docs.openwebui.com/features/open-terminal/advanced/security)

Last checked 17 November 2026.

Research detail: Open Terminal in Docker limits the agent to its own container, with only the mounted volume reachable from the host. Egress can be limited to listed domains and Terminals policies set resources and a restricted security context. Bare metal mode gives the agent the user's full rights. Creating Tools is treated as equivalent to shell access to the server.

<!-- chunk: products -->
## Products

Open Terminal Docker mode, egress allowlist, Terminals policies, Tools Access permission

<!-- chunk: gaps -->
## Gaps

No per-command or per-path allow list inside the terminal is documented. Mounting the Docker socket is effectively root on the host. Restricted security context applies to Kubernetes and OpenShift backends only.

<!-- chunk: options -->
## Options

Run Terminals on Kubernetes with a restricted security context, keep egress allowlisted and keep Tools Access limited to admins.
