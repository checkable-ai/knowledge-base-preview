## Answer

Covered. Per-portal tool exposure; Access policies decide who can connect.

Source statement: "Turned-off tools will not appear in the portal's tool list. Users will not be able to call them." (https://developers.cloudflare.com/cloudflare-one/access-controls/ai-controls/mcp-portals/)

Research detail: Portal admins choose which servers, tools and prompts each portal exposes, can disable individual tools, and can run an allowlist mode where everything is hidden unless enabled. Access policies decide who can connect to a portal and whether each server appears in it, so groups can get different tool sets (for example read-only tools for finance). Policies use identity, group and device posture selectors.

<!-- chunk: products -->
## Products

MCP server portals, Cloudflare Access policies

<!-- chunk: gaps -->
## Gaps

Per-tool permissions are set per portal rather than per user inside one portal. Independent MFA, purpose justification and temporary authentication are not enforced for servers authorised through a portal. Argument-level restrictions are not documented.

<!-- chunk: options -->
## Options

Build separate portals per role. Enforce argument limits in the upstream MCP server.
