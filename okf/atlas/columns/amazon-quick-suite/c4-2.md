## Answer

Partly covered. The page does not state that secrets never reach the model. Remote MCP, agent-to-agent and generic HTTP connectors can be set to no authentication, API key and service-to-service credentials are long-lived, and automated workflows use service-level credentials not bounded by a user's permissions. No per-credential revocation workflow is described beyond KMS key revocation.

Source statement: "AWS Quick stores each connector's OAuth tokens in a token vault in your AWS Quick account and uses the refresh token to renew the access token." (https://docs.aws.amazon.com/quick/latest/userguide/quick-action-auth.html)

Last checked 17 November 2026.

Research detail: Connector OAuth tokens sit in a token vault in the customer's Quick account and are refreshed automatically. With three-legged OAuth the user signs in at the provider, so Quick never receives the password. Stored credentials and OAuth tokens are encrypted with the account's customer managed KMS key when one is registered, and revoking the key locks access.

<!-- chunk: products -->
## Products

Token vault, Default OAuth app, customer managed KMS keys

<!-- chunk: gaps -->
## Gaps

Remote MCP, A2A and generic HTTP connectors can be set to no authentication. Refresh tokens last 90 days with the default OAuth app. Service-level credentials used by automated workflows reach whatever they permit.

<!-- chunk: options -->
## Options

Use Default OAuth app or customer OAuth, register a customer managed key before onboarding and avoid the no authentication option.
