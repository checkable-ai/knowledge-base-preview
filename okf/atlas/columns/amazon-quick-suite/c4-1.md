## Answer

Not covered. No separate agent identity object tying an agent to its owner, the place it runs and its release. Nearby features fall short: chat agents have an ARN, an owner or viewer permission and a version number in agent metadata logs, and Quick Automate projects keep version history, but none is described as an agent identity. Automated workflows authenticate at service level, not as an agent identity.

Research detail: Quick Automate projects keep a version history and deployment status, chat agents have named owners and vended logs report agent hours per agent. Automated workflows run under service-level authentication rather than a user identity. A stable agent or workload identity bound to owner, runtime and release is not documented as a separate object.
