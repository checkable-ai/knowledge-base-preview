<!-- chunk: answer -->
## Answer

Not covered. No sandbox, egress policy or agent kill switch. Playbooks can call other systems to disable accounts, but no agent-specific stop is documented.

Research detail: Sentinel playbooks are Logic Apps workflows that run from automation rules or manually, and Microsoft gives the example of isolating a machine from the network and blocking an account before the SOC is notified. A playbook can therefore call the agent platform or identity provider to disable an agent identity as a response action. Blocking unsafe agent actions at runtime sits in Defender, not Sentinel. Sentinel provides no sandbox or egress policy of its own.

<!-- chunk: products -->
## Products

Sentinel playbooks and automation rules (Azure Logic Apps). Defender real-time protection for agents is a separate product.

<!-- chunk: gaps -->
## Gaps

The stop is only as fast and complete as the target system's API, and the documentation gives no agent-specific playbook template. Logic Apps charges apply. Sandboxing and egress control are out of scope.

<!-- chunk: options -->
## Options

Build and test a playbook that disables an Entra agent identity and revokes its sessions on a high-severity agent alert, and time the end-to-end response.
