## Answer

Covered. Custom MCP tools are prerelease; need Sentinel data lake and Defender licences. Security Operator, Security Admin or Global Admin creates tools; Security reader or Global reader invokes them. Scope is Sentinel and Defender data.

Source statement: "You can create custom Sentinel MCP tools to have granular control over the data accessible to your security agents and create deterministic agentic workflows." (https://learn.microsoft.com/en-us/azure/sentinel/datalake/sentinel-mcp-create-custom-tool)

Research detail: Sentinel limits what agents can do against Sentinel itself. MCP tool access needs at least Security reader, custom MCP tools let teams prescribe which KQL queries and data an agent can reach, and Azure RBAC, resource-context RBAC and table-level RBAC restrict data access. It does not scope agent actions against other connected systems.

<!-- chunk: products -->
## Products

Sentinel roles and table-level RBAC, custom Sentinel MCP tools

<!-- chunk: gaps -->
## Gaps

Only covers Sentinel and Defender data as a target system. Custom MCP tools are prerelease.

<!-- chunk: options -->
## Options

Assign agent principals least-privilege Sentinel roles and expose only custom tools to production agents.
