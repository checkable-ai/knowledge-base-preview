## Answer

Covered. LangSmith Agent Auth is in beta. Needs a configured OAuth provider, a user_id and scopes passed to authenticate(), and the developer using the returned token for downstream calls.

Source statement: "Any unique identifier to scope this token to the human caller" (https://docs.langchain.com/langsmith/agent-auth)

Research detail: The custom @auth.authenticate handler's user object is propagated into run config as langgraph_auth_user, and the docs describe using it to call MCP servers, databases or other agents with user-scoped credentials. Agent Auth can scope OAuth tokens to a human user ID. The developer builds the downstream propagation and token exchange.

<!-- chunk: products -->
## Products

Agent Server custom auth, LangSmith Agent Auth, MCP endpoint user-scoped tools

<!-- chunk: gaps -->
## Gaps

No built-in token exchange (for example OAuth on-behalf-of). Delegation constraints and audience restriction are left to the developer.

<!-- chunk: options -->
## Options

Implement token exchange in custom auth middleware and pass user tokens to downstream MCP servers. Test that a user cannot obtain another user's token.
