## Answer

Not covered. A2A endpoint relies on generic custom auth. No agent-to-agent trust boundaries or per-pair authorisation documented.

Research detail: Agent Server exposes each assistant over A2A JSON-RPC at /a2a/{assistant_id} with an agent card. Custom authentication runs as middleware on every request, so A2A callers pass the same auth as other API calls. The A2A page does not describe authentication or trust boundaries itself.

<!-- chunk: products -->
## Products

Agent Server A2A endpoint, custom auth

<!-- chunk: gaps -->
## Gaps

No documented agent-to-agent trust model, mutual authentication or per-pair authorisation. Several A2A methods are unsupported.

<!-- chunk: options -->
## Options

Implement caller identification for calling agents in @auth.authenticate and restrict assistant access with @auth.on handlers. Disable A2A with http.disable_a2a where unused.
