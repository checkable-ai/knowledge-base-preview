## Answer

Covered. TTL is configured on the Agent Server and applies to new threads and items only. Extended trace retention is an Enterprise feature. Data residency via self-hosting or BYOC.

Source statement: "Setting a TTL automatically deletes or prunes expired data." (https://docs.langchain.com/langsmith/configure-ttl)

Research detail: Traces have base 14-day and extended retention tiers, set per workspace or project, and can be deleted by trace ID or metadata. Thread, checkpoint and store data expire under configured TTLs. BYOC and self-hosting keep data in the customer's VPC. Permitted use rules are not covered.

<!-- chunk: products -->
## Products

LangSmith trace retention and deletion, Agent Server TTL, BYOC and self-hosting

<!-- chunk: gaps -->
## Gaps

Deletion jobs run weekly with no confirmation. SaaS extended retention is capped at 180 days from 14 September 2026. No data use policy controls.

<!-- chunk: options -->
## Options

Set TTLs on threads and store items, mask PII before tracing, and self-host where residency requires.
