## Answer

Covered. Needs Agent Server (LangSmith Deployment) with a persistent checkpointer; TTL must be configured, as threads do not expire by default. Access to threads is controlled through custom auth handlers.

Source statement: "Retains the thread and latest checkpoint, but deletes older checkpoint data that subsequent runs won't need." (https://docs.langchain.com/langsmith/configure-ttl)

Research detail: Checkpointers store thread-scoped state for resumption, human-in-the-loop and time travel. On Agent Server, @auth.on handlers stamp owner metadata on threads and filter access by user. Thread TTL with delete or keep_latest strategies sets retention.

<!-- chunk: products -->
## Products

LangGraph checkpointers, Agent Server threads, custom auth, checkpointer TTL

<!-- chunk: gaps -->
## Gaps

Open-source LangGraph has no access control on threads. In-memory savers lose state on restart.

<!-- chunk: options -->
## Options

Use Postgres checkpointers, owner filters on threads and a TTL. Test cross-user thread access.
