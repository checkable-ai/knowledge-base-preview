## Answer

Covered. Scopes SecOps MCP tools only, using IAM allow and deny policies and the MCP Tool User role. Other connected systems are not covered.

Source statement: "IAM deny policies and allow policies help you secure Google Cloud and Google MCP servers." (https://docs.cloud.google.com/chronicle/docs/secops/use-google-secops-mcp)

Research detail: Calls to the SecOps MCP server need the MCP Tool User role and mcp.tools.call permission, plus Chronicle API roles. IAM allow and deny policies can combine the principal, a read-only tool attribute, service or tool name and the OAuth client ID, so an agent can be held to read-only SecOps tools. Data RBAC scopes further limit which SecOps data a principal sees.

<!-- chunk: products -->
## Products

Google SecOps remote MCP server, IAM, data RBAC

<!-- chunk: gaps -->
## Gaps

Scopes cover actions against SecOps only, not other systems the agent reaches. Data RBAC overview does not mention service accounts or agents.

<!-- chunk: options -->
## Options

Apply IAM deny policies on non-read-only SecOps MCP tools for agent principals and test them.
