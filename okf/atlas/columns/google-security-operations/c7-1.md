## Answer

Not covered. No public Google Security Operations documentation describes a record of each agent action (Triage and Investigation Agent, Detection Engineering Agent, agentic playbook steps, MCP server tool calls) attributed to agent, user or session, kept in write-once or integrity-validated storage, or a documented export of that record to such storage. Nearby features fall short: Cloud Audit Logs and SecOps audit logs record admin and API activity but are not documented as tamper-evident for agent actions, and data retention settings are not an immutable action record.

Research detail: SecOps can hold ingested agent and AI service logs, and log data cannot be deleted manually. Retention is 12 months by default, extendable to five years. SecOps's own Admin Activity audit logs are always on, and Data Access logs can record SIEM searches. Triage agent investigations are audited through InvestigationService methods when Admin Read is enabled.
