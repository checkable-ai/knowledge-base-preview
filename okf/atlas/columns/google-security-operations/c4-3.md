## Answer

Covered. Applies to the SecOps remote MCP server, where the caller's Google Cloud identity and IAM roles govern tool calls. Playbook agent steps use Google-managed permissions, not the analyst's. No delegation beyond SecOps.

Source statement: "The server uses the OAuth 2.0 protocol with Identity and Access Management (IAM) for authentication and authorization." (https://docs.cloud.google.com/chronicle/docs/secops/use-google-secops-mcp)

Research detail: The remote MCP server authenticates with OAuth 2.0 and authorises through IAM, so tool calls made by an MCP client run under the calling principal's identity and roles. This propagates the user identity into SecOps only. Agents embedded in SecOps playbooks use Google-managed permissions rather than the analyst's identity.

## Products

Google SecOps remote MCP server, IAM

## Gaps

No documented token exchange or delegation chain beyond SecOps. Workforce Identity Federation providers created for SecOps cannot be reused for the MCP server.
