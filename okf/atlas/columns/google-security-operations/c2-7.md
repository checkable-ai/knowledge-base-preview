## Answer

Not covered. No customer sandbox for files, processes or network, and no documented control to cancel an investigation already running. Nearby features: the 20 minute maximum run time and the setting to turn auto-investigation off or narrow it only stop future runs.

Research detail: SecOps does not run customer agent code, so there is no customer sandbox. Its Triage and Investigation Agent runs Google-managed search and enrichment tools, each investigation runs for at most 20 minutes, and admins can switch auto-investigation off or narrow it in SIEM Settings. Playbook AI agent steps can be set to manual and can stop the playbook on failure, and IAM deny policies can block MCP tools by principal, tool name, read-only attribute or OAuth client.

<!-- chunk: products -->
## Products

Triage and Investigation Agent settings, Agentic Automation playbook steps, IAM allow and deny policies for the SecOps remote MCP server

<!-- chunk: gaps -->
## Gaps

Playbook agent permissions are managed by Google and cannot be scoped by the customer. No documented control cancels an investigation already running. Containment of external agents that use the MCP server depends on the client.

<!-- chunk: options -->
## Options

Gate remediation behind manual playbook steps and use IAM deny policies on the MCP server as the revocation path for external agents. Test the effect of turning off auto-investigation mid-run.
