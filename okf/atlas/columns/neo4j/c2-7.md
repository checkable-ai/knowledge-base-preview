## Answer

Not covered. Read-only mode (NEO4J_READ_ONLY) only disables write tools. No sandbox for files, processes or network egress, and no documented agent kill switch. User suspension is a database account control, not an agent stop.

Research detail: The Neo4j MCP server disables its write-cypher tool when NEO4J_MCP_READ_ONLY is true, and Aura Agent runs read queries only. In Enterprise Edition an administrator can set a user to SUSPENDED, which removes a native user's roles, and users holding the TERMINATE TRANSACTION privilege can end running transactions by ID. An Aura Agent can be switched from external back to internal at any time.

<!-- chunk: products -->
## Products

MCP read-only mode, Aura Agent read-only queries, ALTER USER SET STATUS SUSPENDED, TERMINATE TRANSACTIONS

<!-- chunk: gaps -->
## Gaps

The README warns that procedures wrongly classed as read-only may bypass the read-only check. The docs do not say that suspending a user closes existing sessions. Suspended external provider users keep their provider roles. Aura Agent documents no query timeout and no network egress policy.

<!-- chunk: options -->
## Options

Test whether a suspended user's open session is cut, and pair read-only mode with a database role that holds only read privileges.
