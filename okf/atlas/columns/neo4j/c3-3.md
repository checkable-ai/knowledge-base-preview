## Answer

Not covered. No data loss prevention or inspection of returned data is documented, and no gateway sits in front of agents and users. The nearest feature is role-based privileges (allowlist/denylist on graph elements and properties) in Neo4j Enterprise Edition, AuraDB Business Critical and AuraDB Virtual Dedicated Cloud. It filters reads per role but does not inspect or redact content. Property-based DENY also does not apply to nodes lacking the property.

Research detail: Sub-graph access control limits reads by label, relationship type and property, and property-based rules filter nodes by property value per role. With MCP HTTP mode passing each user's token, retrieval is enforced per user. Query log literal obfuscation and parameter logging settings keep values out of logs.

## Products

Neo4j RBAC, property-based access control, MCP HTTP mode

<!-- chunk: gaps -->
## Gaps

No DLP or content inspection of returned data. Property-based DENY fails open on missing properties.

## Options
