<!-- chunk: answer -->
## Answer

Covered, with conditions. Fine-grained privileges need Enterprise Edition or higher Aura tiers. MCP read-only mode via NEO4J_READ_ONLY.

Source statement: "Keep in mind that currently the agent only supports read only queries against the database." (https://neo4j.com/docs/aura/aura-agent/)

Last checked 12 November 2026.

Research detail: RBAC with GRANT and DENY privileges scopes access by database, node label, relationship type and property, and property-based rules filter by property value. The MCP server has a read-only mode that disables write tools, and Aura Agent supports only read-only queries.

<!-- chunk: products -->
## Products

Neo4j RBAC, property-based access control, MCP read-only mode, Aura Agent

<!-- chunk: gaps -->
## Gaps

Property-based DENY fails open if the property is missing. Property-based control needs Enterprise Edition or AuraDB Business Critical or Virtual Dedicated Cloud. Misclassified custom procedures can bypass the read-only check.

<!-- chunk: options -->
## Options

Give each agent a least-privilege role and test DENY rules with missing properties and custom procedures.
