## Answer

Covered, with conditions. Neo4j MCP server in HTTP transport mode only (not STDIO). The calling client must send the end user's credentials (Basic or Bearer) on every request; Bearer tokens need Enterprise or Aura with SSO/OAuth. Aura Agent does not document this.

Source statement: "By default, the server reads credentials from the Authorization header." (https://neo4j.com/docs/mcp/current/authentication/)

Last checked 12 November 2026.

Research detail: Neo4j has an IMPERSONATE user privilege, and the security and query logs record both executingUser and authenticatedUser when one user acts as another. The MCP server in HTTP mode accepts per-request bearer tokens, so queries can run under the end user's OIDC identity and roles.

<!-- chunk: products -->
## Products

IMPERSONATE privilege, MCP server HTTP mode, OIDC SSO

<!-- chunk: gaps -->
## Gaps

Aura Agent does not document whether tool queries run as the calling user. Driver impersonation docs were not opened.

## Options

Test that an MCP call with a user's token returns only that user's permitted subgraph and that logs show both identities.
