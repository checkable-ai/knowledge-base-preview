## Answer

Not covered. No retention setting or access control for Harness session logs. API context caching cannot be turned off.

Research detail: DeepSeek Harness keeps each session as an append-only event log persisted to JSONL with single-writer handles, flush checkpoints and resume after crash. On the API, context caching writes a disk cache by default that is removed within hours to days, and user_id isolates KV cache between a customer's end users.

## Products

DeepSeek Harness session persistence, API context caching

## Gaps

No retention setting for harness logs documented. API caching cannot be turned off according to the caching guide, and cache storage location is not stated beyond the privacy policy.

<!-- chunk: options -->
## Options

Set user_id on every API call, store harness logs on encrypted managed storage and apply your own retention.
