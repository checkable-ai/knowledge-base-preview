## Answer

Covered, with conditions. Applies to Agent Sandbox code execution. Sandbox file input and output is capped at 100MB per request or response. Sandbox memory state persists up to 14 days (configurable TTL). You cannot install your own libraries; the sandbox has a fixed set of preinstalled packages. Sandboxes must run in supported Agent Platform locations, including australia-southeast2.

Source statement: "This isolation reduces security risks by preventing the code from touching your system's resources, files, or network." (https://docs.cloud.google.com/gemini-enterprise-agent-platform/scale/sandbox/code-execution-overview)

Last checked 17 November 2026.

Research detail: Agent Sandbox runs untrusted code, shell and browser work in container-isolated sandboxes. Code execution sandboxes have a limited file system and no network access. Managed Agents run each agent in an isolated sandbox with network access off by default.

<!-- chunk: products -->
## Products

Agent Sandbox (code execution, computer use, shell), Managed Agents API

<!-- chunk: gaps -->
## Gaps

No per-action allow list for local commands or file paths. Sandbox isolation technology is not named. Managed Agents API is pre-GA and not for production data.

<!-- chunk: options -->
## Options

Run tool code in code execution sandboxes rather than the agent runtime. Use custom containers with only the needed binaries and VPC Service Controls for sandbox egress.
