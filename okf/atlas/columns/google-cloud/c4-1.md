## Answer

Not covered. Agent Identity is derived from the hosting resource ID. No owner attribute is documented, and redeploying creates a new principal so it is not tied to a release.

Research detail: Agent Identity gives each agent deployed to Agent Runtime a SPIFFE-based IAM principal derived from its reasoningEngines resource ID, with an auto-provisioned X.509 certificate valid for 24 hours. Grants use the principal:// identifier and principalSet bindings can cover all agents in a project or organisation. Without the identity flag, Agent Runtime falls back to service accounts.

Agent Identity, Agent Runtime, Agent Registry

## Gaps

No documented owner attribute. Redeploying an agent creates a new principal and existing grants do not carry over. The identity is tied to the resource, not to a revision or release. Manage agent access still labels agent identity preview.

<!-- chunk: options -->
## Options

Record owner and release in Agent Registry entries or resource labels. Use project-scoped principalSet bindings for baseline grants and check grants after each redeploy.
