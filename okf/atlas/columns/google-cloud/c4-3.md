## Answer

Covered. Needs a 3-legged OAuth auth provider in Agent Identity auth manager; the legacy IAM Connectors API is preview.

Source statement: "3-legged OAuth auth providers require user consent because the agent accesses resources on behalf of the user." (https://docs.cloud.google.com/iam/docs/auth-with-3lo-v2)

Research detail: Agents can act with user-delegated authority through a 3-legged OAuth auth provider: the user signs in and consents, the auth manager stores the tokens in a Google-managed vault, and the agent retrieves them for tool calls. End-user access events are attributable to the agent's SPIFFE ID. Agent Runtime also supports an OAuth client ID per agent for end-user consent.

<!-- chunk: products -->
## Products

Agent Identity auth manager (3-legged OAuth), Agent Runtime

<!-- chunk: gaps -->
## Gaps

Feature is preview and the IAM Connectors API will not reach GA. No documented propagation of the initiating user identity to Google Cloud APIs or to downstream agents in a chain. Revocation not described.

<!-- chunk: options -->
## Options

Use the Agent Identity API path for new projects. Test whether downstream audit logs record both the user and the agent identity.
