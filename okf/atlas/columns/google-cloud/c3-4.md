## Answer

Covered, with conditions. Agent Gateway must be set up and enforcing; it runs in dry-run mode until enforcement is turned on. Destination agents must be in Agent Registry or targeted by an explicit policy. Agent Gateway for cross-cloud is in Limited Preview. Agent Gateway for GKE is in Preview. Agent Gateway support for Cloud Run agents is coming soon. Client-to-Agent mode is not supported for Gemini Enterprise.

Source statement: "You specify agents by their agent identity, the identity of the agent initiating communication with a resource." (https://docs.cloud.google.com/gemini-enterprise-agent-platform/govern/policies/iam-overview-uap)

Last checked 17 November 2026.

Research detail: Agent Gateway carries A2A traffic and access policies bind calling agent principals to registered destination agents with allow and deny rules. Model Armor screens A2A Send Message operations and agent cards on egress.

<!-- chunk: products -->
## Products

Agent Gateway, IAM access policies, Agent Registry, Model Armor

<!-- chunk: gaps -->
## Gaps

Only MCP traffic gets attribute parsing, so A2A schemas and skills are not enforced. A2A streaming and gRPC are not sanitised.

<!-- chunk: options -->
## Options

Register each A2A agent and write per-pair access policies. Validate A2A payload schemas in a custom extension.
