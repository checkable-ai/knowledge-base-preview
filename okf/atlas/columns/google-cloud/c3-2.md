## Answer

Covered. Agent traffic must route through Agent Gateway (GA), which denies connections until an IAM policy grants access. Tool-level allow policies and Destructive, ReadOnly and Open World conditions use IAM Unified Access Policies (GA). Conditions on protocol attributes are MCP only. Input-format and value-limit checks rely on semantic governance natural language constraints, which are Preview, LLM-based (the vendor says verdicts may not be accurate), need non-streaming model calls because a tool call in a streamed response might not be blocked, and run only in listed Americas and Europe regions, so Australian regions are not among those documented. No built-in JSON schema validation or per-tool call-rate limit is documented. RateLimitPolicy is described for ingress protection, and token management policies (agent-to-model traffic only) are coming soon.

Source statement: "Governs outbound requests initiated by agents to external tools, remote MCP servers, SaaS APIs, or downstream agents." (https://docs.cloud.google.com/gemini-enterprise-agent-platform/govern/gateways/agent-gateway-overview)

Research detail: Agent Gateway is the egress point for agent calls to MCP servers, APIs and agents. It checks IAM access policies (including per-tool CEL rules), verifies the target against Agent Registry, applies Model Armor and semantic governance, and denies requests with no matching policy. Custom authorisation engines can be attached through Service Extensions.

<!-- chunk: products -->
## Products

Agent Gateway, IAM access policies, Agent Registry, Model Armor, semantic governance policies

<!-- chunk: gaps -->
## Gaps

No documented per-tool rate limits or quotas. MCP tools/list and A2A streaming pass without Model Armor sanitisation. Semantic governance is preview.

<!-- chunk: options -->
## Options

Add a custom CONTENT_AUTHZ extension for rate limits. Keep unregistered endpoints denied.
