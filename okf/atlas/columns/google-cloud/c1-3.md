## Answer

Not covered. No documented feature where an authorised person approves the exact action before it runs, with refusal and repeat-attempt handling. Computer use leaves confirmation to the customer's application, and ADK tool confirmation is experimental.

Research detail: ADK tool confirmation pauses a tool for a yes or no decision or structured input, and the response must match the function_call_id of the confirmation request. A false confirmation returns a rejected status without running the action. Remote confirmation through the REST API is supported, with the invocation ID needed for resumed runs.

## Gaps

Experimental, and not supported with VertexAiSessionService, the managed Sessions service. No approver identity or authorisation check is described. Semantic governance returns only ALLOW or DENY with no escalation.

<!-- chunk: options -->
## Options

Build approval in application code with approver identity checks, or use an in-memory or custom session service until VertexAiSessionService is supported.
