## Answer

Covered, with conditions. MCP server management applies to the Developer, Basic, Standard, Premium, Basic v2, Standard v2 and Premium v2 tiers, and to the self-hosted gateway. MCP server capabilities are not supported in workspaces. On these tiers policies apply to all tools in an MCP server, not per tool. Per-tool blocking from Microsoft Agent 365 works only on MCP servers registered in the AI Gateway tier, which is in public preview in East US 2 and Sweden Central. Agent 365 tool threat protection is in preview, needs a Microsoft Defender or Microsoft Purview licence and a delegated Microsoft Entra ID user token, and applies to one MCP server at a time. API Management v2 tiers do not support tool-level access control or tool threat protection.

Source statement: "Use policies to control access, authentication, and other aspects of the tools." (https://learn.microsoft.com/en-us/azure/api-management/mcp-server-overview)

Last checked 17 November 2026.

Research detail: The gateway exposes REST APIs or existing MCP servers as governed MCP endpoints with rate limits, quotas, JWT validation, IP filtering and content safety checks on tool calls. The AI Gateway tier adds Agent 365 tool threat protection that checks tool arguments and results, plus per-tool blocking. Backend authentication uses keys, OAuth, managed identity or mTLS.

<!-- chunk: products -->
## Products

MCP server governance policies, llm-content-safety on MCP tools, AI Gateway tool threat protection, Agent 365 tool blocking

<!-- chunk: gaps -->
## Gaps

Classic and v2 tiers apply policies to all tools in a server. Tool threat protection is a preview, covers one MCP server at a time, needs a delegated Entra token and skips tools/list calls. Egress filtering for the internet is not described. Resources and prompts are not supported.

<!-- chunk: options -->
## Options

Use the AI Gateway tier for per-tool control and fail closed with Defender block mode.
