## Answer

Covered, with conditions. Credential manager is available on all API Management tiers. It is not supported in the self-hosted gateway. It is not supported in sovereign clouds or in the regions australiacentral, australiacentral2 and indiacentral. It is not available in workspaces. It applies to backend OAuth 2.0 APIs. Shared backend connections in AI Gateway (public preview, East US 2 and Sweden Central) run with the connection's permissions, not the caller's. Available in all API Management service tiers.

Source statement: "To enable a simplified authentication experience for users of client applications (such as static web apps) that call backend SaaS APIs that require a user context, you can enable access to a connection on behalf of a Microsoft Entra user or group identity." (https://learn.microsoft.com/en-au/azure/api-management/credentials-overview)

Last checked 17 November 2026.

Research detail: Credential manager supports a user-delegated scenario where a connection is held on behalf of a Microsoft Entra user or group, and the gateway attaches that user token to backend calls. Gateway policies can validate caller JWTs and forward the Authorization header. Agent 365 tool threat protection also uses an on-behalf-of exchange with the caller's delegated token.

<!-- chunk: products -->
## Products

Credential manager attended scenario, validate-jwt and validate-azure-ad-token policies, header forwarding

<!-- chunk: gaps -->
## Gaps

Delegation is an OAuth connection pattern for SaaS backends. It is not a general agent-to-tool delegation chain. Shared backend connections in the AI Gateway tier run with the connection's permissions, not the caller's.

<!-- chunk: options -->
## Options

Use per-user credential manager connections or forward the user's Entra token to MCP backends. Test token exchange against each backend.
