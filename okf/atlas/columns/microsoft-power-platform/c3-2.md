## Answer

Covered, with conditions. Advanced connector policies cover certified connectors only; custom and HTTP connectors need classic data policies and connector endpoint filtering. Policies apply per environment or environment group, not per user or agent. Blocking is per MCP server, not per tool inside one. Design-time enforcement is rolling out by maker portal. On non-managed environments nonblockable connectors stay nonblockable. Connector endpoint filtering is a preview feature.

Source statement: "At runtime, when a connector operation is invoked, it queries the effective policy for the current hosting environment." (https://learn.microsoft.com/en-us/power-platform/admin/advanced-connector-policies)

Last checked 17 November 2026.

Research detail: Data policies and advanced connector policies are the main tool gateway. They set which connectors, actions and MCP servers can be used per environment, group or tenant, enforced at design time and runtime. Advanced connector policies deny new connectors by default. Flow throttling limits exist on the platform side.

<!-- chunk: products -->
## Products

Data policies, advanced connector policies, flow limits

<!-- chunk: gaps -->
## Gaps

Policies work at environment scope, not per user or agent. No schema validation or injection screening of tool calls is documented. No per-tool control inside an MCP server.

<!-- chunk: options -->
## Options

Adopt advanced connector policies on environment groups and review blocked connector reports before widening access.
