## Answer

Not covered. No scanning of tools or connectors for look-alike names, poisoned tool descriptions or compromised packages is documented. Nearby features fall short: advanced connector policies block new connectors by default and can block a whole MCP server, and certified connectors are vetted by Microsoft, but none inspects metadata. Custom and HTTP connectors are not covered by advanced connector policies.

Research detail: Microsoft tests and certifies connectors. Advanced connector policies block new connectors by default and let admins block an entire MCP server. Custom connectors are governed by classic data policies. Scanning for squatting or tool metadata poisoning is not documented.

## Products

Certified connectors, advanced connector policies

## Gaps

No scanning of third party connector content or MCP tool descriptions. Custom and HTTP connectors are not covered by ACP.

<!-- chunk: options -->
## Options

Allow only certified connectors and review custom connectors manually before they join an environment.
