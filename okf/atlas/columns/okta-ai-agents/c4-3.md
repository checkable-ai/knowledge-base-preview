## Answer

Covered. User must sign in and consent on first use; downstream server must support token exchange; gateway handles MCP tool calls only.

Source statement: "The gateway injects the downstream access token into the outbound call and proxies the request to the remote MCP server." (https://developer.okta.com/docs/concepts/agent-gateway/)

Research detail: Cross App Access issues a short-lived ID-JAG carrying the user's identity, which the resource authorisation server exchanges for its own access token under admin policy set in Okta. Agent Gateway exchanges the agent token for downstream tokens on behalf of the user, with first-use consent and stored per-user refresh tokens. A linked app restricts an agent to acting for users currently signed in to that app.

<!-- chunk: products -->
## Products

Cross App Access (XAA), Agent Gateway, Auth0 Token Vault

<!-- chunk: gaps -->
## Gaps

Downstream apps must implement the ID-JAG grant. Delegation chains beyond one hop are not described.

<!-- chunk: options -->
## Options

Check which target apps support XAA in the Okta Integration Network and test multi-hop delegation explicitly.
