## Answer

Not covered. No sandbox for agent files, processes or network; agent blocking is described only in a blog. User and device suspension is a nearby feature but is not an agent kill switch.

Research detail: Prisma Browser states it can stop hijacked agents or unsafe actions before they execute and can pause an agentic workflow for human approval. Administrators can suspend a user or a single device, which replaces the browser with a block page, and can force removal of extensions. Browser hardening adds strict origin isolation. It is a browser control point, not a sandbox for agent code execution or a process kill switch for agents outside the browser.

<!-- chunk: products -->
## Products

Prisma Browser agentic controls, user suspension, device suspension, extension block rules, Strict Origin Isolation

<!-- chunk: gaps -->
## Gaps

No documented sandbox for agent code, filesystem or process policy. Agentic action blocking is described in a blog, not the admin guide. Suspension does not support the Prisma Browser Extension or mobile. A known limitation stops identity-based blocks from removing force-installed extensions.

<!-- chunk: options -->
## Options

Pair with a runtime sandbox for agent code. Test user and device suspension timing on a running agentic session in a pilot tenant.
