<!-- chunk: answer -->
## Answer

Covered. Requires configuring secrets engine roles (e.g. AWS) and restricting each agent's access to the appropriate roles via policies. Agent Registry ceiling policies and RAR constraints are Vault Enterprise only.

Source statement: "Configure a Vault role that maps to a set of permissions in AWS as well as an AWS credential type." (https://developer.hashicorp.com/vault/docs/secrets/aws)

Research detail: Vault ACL policies are deny by default and grant capabilities per path, with parameter constraints. For agents, ceiling policies in the Agent Registry cap what an agent can ever do, and per-session RAR constraints in the token narrow access further. Scope applies to Vault paths and the credentials Vault issues, not to actions taken with those credentials in the target system.

<!-- chunk: products -->
## Products

Vault ACL policies, Agent Registry ceiling policies, RAR vault:path_access constraints

<!-- chunk: gaps -->
## Gaps

No control over actions against connected systems once a credential is issued, beyond the role scoping of each secrets engine. Ceiling policies and RAR are Enterprise only.

<!-- chunk: options -->
## Options

Scope secrets engine roles narrowly per agent and enforce action-level limits in a tool gateway.
