## Answer

Covered. Vault Enterprise agentic IAM (Enterprise 2.1+ or HCP Vault Dedicated). Needs an external IdP or authorisation server to issue the delegated token. Applies to access to Vault; downstream services receiving Vault-issued credentials are outside Vault.

Source statement: "effective permission set that is the intersection of three independent controls" (https://developer.hashicorp.com/vault/docs/ai/iam)

Research detail: Vault Enterprise validates delegated OAuth JWTs, including RFC 8693 token exchange tokens, where an agent acts for a human subject. Access is the intersection of the user's ACL policies, the agent's ceiling policies and the token's authorization_details. Audit logs record both the user and the agent. Vault consumes the delegated identity but does not pass it on to downstream services that receive Vault-issued credentials.

<!-- chunk: products -->
## Products

Vault Enterprise agentic IAM, OAuth resource server profiles, RAR

<!-- chunk: gaps -->
## Gaps

Downstream propagation of user identity is outside Vault. Depends on an external IdP or authorisation server to issue the delegated token.

<!-- chunk: options -->
## Options

Pair with an IdP that supports token exchange and RAR (the GA post lists IBM Verify, Auth0, PingFederate, Entra and Okta) and test downstream audit attribution.
