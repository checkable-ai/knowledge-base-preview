## Answer

Not covered. No sandboxing of agent files, processes or network access. Lease and token revocation cut off only Vault-issued credentials, and there is no documented agent kill switch.

Research detail: Vault does not sandbox agent code or set process or network policy. It gives a deterministic way to cut off an agent's secrets: revoking a lease invalidates the secret immediately, lease revoke -prefix revokes many at once, and revoking a token revokes its children and every lease it created. Setting an entity to disabled stops its tokens being used.

<!-- chunk: products -->
## Products

Vault lease revocation, token revoke, identity entity disabled flag

<!-- chunk: gaps -->
## Gaps

Revocation only covers credentials Vault issued. Tokens of a disabled entity are blocked but not revoked. The Agent Registry API has no disable field and does not say whether deleting a record ends existing tokens.

<!-- chunk: options -->
## Options

Pair Vault revocation with a runtime sandbox and egress control, and script a kill path that disables the entity and revokes its token tree.
