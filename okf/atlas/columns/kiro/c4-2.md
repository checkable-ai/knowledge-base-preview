## Answer

Not covered. Kiro Web OAuth connections keep tokens from the agent, limit access to approved permissions and delete credentials on disconnect. But the vendor does not document short-lived rotated per-agent credentials. MCP servers can read secrets and environment variables configured for the session. Kiro Web IAM role credentials are available to the agent and MCP servers.

Research detail: Kiro Web stores sandbox secrets encrypted at rest and injects them as environment variables, but the documentation warns the agent may exfiltrate them. Kiro Crew has a secrets vault referenced as secret://NAME, strips sensitive environment variables from subprocesses and redacts credential patterns from tool output. The IDE expands only approved environment variables in MCP configuration.

<!-- chunk: products -->
## Products

Kiro Web secrets, Kiro Crew secrets vault and output redaction, Mcp Approved Env Vars setting

<!-- chunk: gaps -->
## Gaps

No documented rotation, expiry or revocation of secrets. Kiro Web secrets are readable by the agent. API keys for the CLI have no documented scope, expiry or revocation.

<!-- chunk: options -->
## Options

Issue short-lived scoped tokens from an external secrets manager and keep long-lived credentials out of the sandbox.
