## Answer

Covered. Covered once set up. The local command sandbox is off by default and has to be turned on. It limits terminal commands and their child processes, and stdio MCP servers when MCP wrapping is on. Its network mode blocks outbound traffic unless a sandbox_network rule allows the host, and fs_read and fs_write rules decide which paths those commands can read and write. Built-in file tools and remote HTTP or SSE MCP traffic sit outside the sandbox. The vendor says the sandbox is not a guarantee of isolation. For stopping, Stop, /workflow cancel or Ctrl+X stops a workflow run at once and marks it aborted, but file changes already made stay in place. Kiro Web runs each task in its own isolated sandbox with domain limits you can set. Its pages document no stop for a single task, though deleting a session removes its sandbox. Cloud sessions need a Pro, Pro+, Pro Max or Power plan.

Source statement: "Use Stop, `/workflow cancel`, or `Ctrl+X` only when work must stop immediately." (https://kiro.dev/docs/workflows/manage/)

Research detail: The local command sandbox in Kiro IDE 1.3 and CLI 2.31 wraps shell commands, their child processes and optionally stdio MCP servers in Seatbelt or Bubblewrap, blocks network by default except allowed hosts, and lets a project file only tighten the global policy. Kiro Web runs each task in its own sandbox with four network levels including a custom domain allow-list, and the Crew credential-masking sandbox fails closed. Admins can deactivate a user or group with immediate loss of access.

## Products

Local command sandbox, Kiro Web sandbox, Kiro Crew sandbox modes, Kiro console Deactivate plan

<!-- chunk: gaps -->
## Gaps

The local sandbox is off by default, leaves the agent harness, built-in file tools and remote MCP servers outside it, and runs commands unsandboxed when the platform backend is missing. No documented control stops a single running Kiro Web task other than deleting the session.

## Options

Distribute a global sandbox.json with enabled set to true and DEFAULT_BLOCKED, and test the time from Deactivate plan to an active session ending.
