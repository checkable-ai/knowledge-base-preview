## Answer

Covered. Client-side in IDE and CLI; depends on workspace trust and active rules. Downstream MCP server credentials are a separate boundary.

Source statement: "Kiro's permissions system evaluates each MCP tool call." (https://kiro.dev/docs/mcp/security/)

Research detail: Rules on the mcp and web_fetch capabilities can deny or require approval by tool or URL pattern. Admins can turn off MCP or restrict it to a registry allow-list, and turn off web search and fetch. Kiro Web limits sandbox network access to connections only, common registries, a custom domain list or open internet, and the GitHub app is limited to repositories the org owner selects.

<!-- chunk: products -->
## Products

Permission policies, MCP governance, Web tools governance, Kiro Web internet access, Kiro Agent GitHub app

<!-- chunk: gaps -->
## Gaps

What the agent can do inside a connected system depends on the credentials given to each MCP server. MCP and web governance are client-side and do not apply to Builder ID or social sign-in users.

<!-- chunk: options -->
## Options

Pair Kiro rules with least-privilege tokens per MCP server and a network egress proxy.
