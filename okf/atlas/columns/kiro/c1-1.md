<!-- chunk: answer -->
## Answer

Covered. Client-side policy file at an OS-protected path (e.g. deployed via MDM); users with local admin access could bypass it. Applies to IDE and CLI.

Source statement: "The policy applies to every Kiro surface on the machine, because the IDE and the CLI read the same file." (https://kiro.dev/docs/enterprise/governance/permissions/)

Research detail: Capability rules for fs_read, fs_write, shell, web, mcp and other capabilities take allow, ask or deny effects with glob patterns across Kiro, administration, user, workspace, agent and session scopes, and the most restrictive effect wins. Admins deploy deny or ask rules in managed-settings.json at an OS-protected path through MDM. Untrusted workspaces do not load repository agents, steering or MCP configuration.

<!-- chunk: products -->
## Products

Permissions (permissions.yaml), Permission policies (managed-settings.json), Workspace trust

<!-- chunk: gaps -->
## Gaps

Enforcement is in the client, and the documentation says users with admin rights on their machine can circumvent policies. Policies are machine-wide, not per user or group.

<!-- chunk: options -->
## Options

Remove local admin rights on managed devices and monitor the managed-settings file with endpoint tooling.
