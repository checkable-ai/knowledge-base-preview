## Answer

Covered. Client-side in Kiro IDE and CLI; depends on configured rules, and tools set to auto-approve run without a prompt. Not applied in Kiro Web.

Source statement: "Review each tool request carefully before approval" (https://kiro.dev/docs/mcp/security/)

Research detail: When a rule says ask, Kiro prompts with Allow, Always allow, Deny and Always deny for the specific invocation, and chained shell commands are approved one sub-command at a time. Admin ask rules force a prompt even over user allow rules. In headless mode every ask is treated as a deny.

## Products

Permissions approval UI, Permission policies

<!-- chunk: gaps -->
## Gaps

Replay protection and binding of an approval record to the executed action are not documented. Always allow creates broad generalised patterns. Kiro Web runs without per-action prompts.

<!-- chunk: options -->
## Options

Restrict Always allow scopes through admin ask rules on sensitive capabilities and review session rules.
