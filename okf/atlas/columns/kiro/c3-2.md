## Answer

Not covered. No single documented control point enforces allowed tools, input formats, call limits and internet access together. Nearby features (the sandbox network rules, Kiro Web domain allow-list, permission policies) fall short.

Research detail: Admins can disable MCP or restrict it to a hosted registry of pinned servers, disable web search and fetch, and deploy deny or ask rules on shell, file, web and MCP capabilities. Kiro Web limits sandbox egress by domain. Pre Tool Use hooks can block calls, and Crew blocks built-in dangerous command patterns.

<!-- chunk: products -->
## Products

MCP governance, Web tools governance, Permission policies, Kiro Web internet access, hooks, Crew denied commands

<!-- chunk: gaps -->
## Gaps

All enforcement is client-side and bypassable by local admins. No tool quotas, schema enforcement or injection screening, and MCP and web governance do not cover Builder ID or social sign-in users.

<!-- chunk: options -->
## Options

Add a network egress proxy and an MCP gateway for central enforcement and logging.
