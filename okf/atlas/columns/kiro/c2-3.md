## Answer

Covered. Kiro Web (and Crew) only; the local IDE and CLI have no sandbox by default.

Source statement: "Each task runs in its own sandbox with configurable access controls, ensuring your code and resources remain protected." (https://kiro.dev/docs/web/sandbox/)

Research detail: Kiro Web runs each task in its own isolated sandbox with a headless browser, controlled network access and deletion with the session. Kiro Crew uses Linux namespaces or macOS Seatbelt to hide credential directories and refuses to start when the sandbox cannot be applied. The IDE and CLI run on the user's host and rely on permission rules rather than a sandbox.

## Products
