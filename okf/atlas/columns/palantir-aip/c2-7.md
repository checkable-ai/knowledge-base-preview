## Answer

Not covered. No documented filesystem or process sandbox for agent code and no command to halt a running agent. Egress policy revocation limits network only.

Research detail: Foundry controls outbound reach through network egress policies. A user proposes a policy, it only works once an Information Security Officer or Enrollment Administrator approves it, a workload must import it explicitly, and a revoked or Palantir-paused policy makes dependent workloads fail to run. Compute modules run as isolated containers in replicas, and administrators can disable model families or restrict AIP by user group or organisation in Control Panel.

<!-- chunk: products -->
## Products

Network egress policies (approve, revoke, pause), compute module containers, Control Panel AIP and model family switches

<!-- chunk: gaps -->
## Gaps

No page read describes a filesystem or process sandbox for agent code, or a command that halts a running agent session. The compute modules page does not cover sandboxing, egress or stopping a module. The enable-AIP page does not say how fast a change takes effect, and warns that disabling a model family breaks dependent workflows. Importers of an egress policy can run arbitrary code in Foundry.

<!-- chunk: options -->
## Options

Test whether revoking an egress policy or disabling a model family interrupts an in-flight agent session, and request Palantir's compute module isolation documentation under NDA.
