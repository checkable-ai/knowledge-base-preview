## Answer

Not covered. Rotation, expiry and revocation of agent credentials are not documented, and source secrets are readable by agent code. Platform-provisioned tool credentials fall short.

Research detail: Pro-code agents get OSDK, Ontology MCP and Palantir MCP credentials from the platform, and agent code does not hold a client ID, secret or Foundry token. Secrets for external sources are written into the agent container at /app/var/run/source_credentials.json and replaced atomically.

## Products

Pro-code agent library, Data Connection sources

## Gaps

Source secrets are readable by agent code, so nothing documented stops code from passing them to the model. Rotation, expiry and revocation of agent tokens are not described. Beta, and sources are not supported on CBAC environments.

<!-- chunk: options -->
## Options

Test whether source secrets can reach model context or logs, and check token lifetime on the agent client.
