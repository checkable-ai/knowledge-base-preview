## Answer

Not covered. No file, process or network limits and no immediate stop or access cut-off for customers' agents. The PXI sandboxed bash and the switches that disable bash, external resources or the assistant apply only to Arize's own assistant.

Last checked 16 November 2026.

Research detail: Arize AX and Phoenix trace, evaluate and monitor agents that run elsewhere. They do not run agent code, so they offer no sandbox, filesystem or egress policy, and no control to stop a running agent or revoke its access. Arize Guards can block or replace a single LLM message that fails a check, which is an output control inside the application, not a stop for the agent.

## Gaps

No execution containment or kill switch. Guards act per message and need to be wired into the application code.

<!-- chunk: options -->
## Options

Use the runtime or gateway that hosts the agent for sandboxing and stop controls, and send its traces to Arize.
