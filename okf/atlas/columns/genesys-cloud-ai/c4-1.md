## Answer

Not covered. No documented per-agent identity binding an owner, a runtime and a release. Published versions and named agent objects identify a release only; ownership is not tied to them.

Last checked 16 November 2026.

Research detail: Agentic virtual agents and AI Guides are named AI Studio objects with their own permissions for the agent, its versions and jobs, and a public API that exposes agents and versions. Each agent is invoked from an Architect Virtual Agent flow. No separate workload identity, owner field or credential is documented for an agent.

<!-- chunk: products -->
## Products

AI Studio agentic virtual agents, AI Guides, AI Studio APIs

<!-- chunk: gaps -->
## Gaps

No agent identity linking an accountable owner, runtime and release. Data actions run under integration credentials, not an agent identity.

<!-- chunk: options -->
## Options

Use the agent ID and published version from the API as the agent identifier and record owner externally, or tie each agent to a dedicated data action integration and OAuth client.
