## Answer

Covered. Per-tool authorisation is via Agent Privilege MCP Gateway; PingGateway tutorial enforces one scope per MCP server.

Source statement: "The OAuth scopes determine the resources that the AI agent identity can access." (https://docs.pingidentity.com/pingone/ai_agents/p1_managing_ai_agents.html)

Research detail: PingOne agent Resources tabs assign OAuth scopes, and Advanced Identity Cloud application privileges set which application, which users or groups the agent may act for, and which scopes. Agent Privilege's MCP Gateway authorises individual tools, prompts and resources and hides tools a user is not entitled to.

<!-- chunk: products -->
## Products

Agent IAM Core resources and application privileges, Agent Privilege MCP Gateway

<!-- chunk: gaps -->
## Gaps

The PingGateway tutorial enforces one scope for the whole MCP server, not per tool. Tool-level rules there need PingOne Authorize or similar.

<!-- chunk: options -->
## Options

Use Agent Privilege tool policies, or add PingOne Authorize to PingGateway routes for per-tool decisions.
