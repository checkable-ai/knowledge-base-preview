## Answer

Not covered. The gen_ai.agent.id, name and version attributes (Development status) report an agent identity and release, but the spec has no owner attribute and no attribute binding the agent to where it runs. Identity is reported by instrumentation, not issued or verified. Nearby features fall short of the outcome of an identity tied to owner, location and release.

Research detail: The spec defines gen_ai.agent.id (stable identifier of a hosted agent resource), gen_ai.agent.name, gen_ai.agent.version and gen_ai.agent.description on agent spans, plus a gen_ai.main_agent entity whose id MUST be a stable provider-assigned identifier such as a Bedrock agent ARN or an A2A Agent Card entry. This lets a conforming tool tie telemetry to a stable agent identity and release.

## Gaps

No owner attribute. Runtime linkage relies on generic OpenTelemetry resource attributes outside this spec. Identity is reported, not issued or verified. All attributes are Development status.

## Options

Pair the attributes with an identity provider or agent registry that issues the ids, and add owner as a resource attribute by local convention.
