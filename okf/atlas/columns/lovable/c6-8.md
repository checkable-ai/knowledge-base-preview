## Answer

Partly covered. Prompt, permission and knowledge changes are not versioned or approved as releases. Approval applies to publishing, not each change.

Source statement: "Block publishing with critical issues prevents publishing while critical findings are unresolved." (https://docs.lovable.dev/features/security.md)

Last checked 17 November 2026.

Research detail: Enterprise publishing can need admin approval, block publishing while critical findings are unresolved, and every publish records the commit SHA. Lovable saves every change as a version that can be reverted, and Git sync supports pull request review.

<!-- chunk: products -->
## Products

Publishing policies, block publishing on critical issues, version history, Git sync

<!-- chunk: gaps -->
## Gaps

Approval covers later updates until something the policy checks changes. Prompt, permission and knowledge changes are not versioned as releases.

<!-- chunk: options -->
## Options

Use Git sync with branch protection for code changes.
