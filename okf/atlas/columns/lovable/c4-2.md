## Answer

Partly covered. Short-lived, scoped credentials issued to agents are not documented, and the docs do not say whether secrets stay out of the model. Provider tokens are refreshed by the gateway rather than issued short-lived, and public secrets and connectors that bypass the gateway can be visible inside a project and to Lovable.

Source statement: "Gateway connectors keep all credentials on Lovable's side and do not expose them in the project." (https://docs.lovable.dev/integrations/security.md)

Last checked 17 November 2026.

Research detail: Connector credentials are stored encrypted and cannot be read back by members, admins or Lovable. Gateway connectors keep provider tokens on Lovable's side and give each project only an opaque connection key. Build secrets are encrypted workspace values that nobody can view after saving, and API keys carry scopes, expiry and revocation.

<!-- chunk: products -->
## Products

Connector gateway, project secrets, build secrets, workspace API keys

<!-- chunk: gaps -->
## Gaps

Public-marked secrets and connectors that do not use the gateway can be visible inside a project and to Lovable. Rotation and expiry of provider tokens sit with the provider.

<!-- chunk: options -->
## Options

Prefer gateway connectors, keep secrets out of chat and set expiry on every API key.
