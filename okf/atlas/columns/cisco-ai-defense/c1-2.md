## Answer

Covered. Applies to systems reached through MCP servers. Needs an enabled runtime policy with an MCP security profile attached to the connection.

Source statement: "We can choose to monitor or block access to each individual tool." (https://www.cisco.com/c/en/us/customer-success/video/demo/cisco-ai-defense-mcp-runtime.html)

Research detail: MCP Security Profiles define tool access per tenant MCP server and tool, and block tools above a chosen risk severity found by the MCP scanner. Release 2026.8.2 adds identity-aware, deny-by-default tool authorisation for MCP servers and tools at discovery and invocation. Policies attach to connections, one policy per connection.

<!-- chunk: products -->
## Products

MCP Security Profiles, MCP Runtime Guardrails, identity-aware tool-access policies

<!-- chunk: gaps -->
## Gaps

Scopes cover MCP tools only, not other APIs. Per-user detail for the Duo-based policy is only in release notes.

<!-- chunk: options -->
## Options

Route all agent tool traffic through the AI Defense MCP gateway and test deny-by-default with an unapproved tool.
