## Answer

Not covered. No sandbox for files, processes or network, and no emergency stop for a running agent. Policy blocking of prompts and tool calls is traffic filtering, not containment.

Research detail: AI Defense mediates AI traffic but does not run or sandbox agent code. The runtime gateway proxies model calls and blocks prompts or responses that break policy, and MCP guardrails block risky tool calls and whole MCP servers, re-scanning tools to catch rug-pull changes. This gives policy-driven blocking of model and MCP traffic, which can cut a misbehaving agent off from tools.

## Products

AI Defense runtime gateway, runtime policies, MCP Runtime Guardrails and risk profiles

<!-- chunk: gaps -->
## Gaps

No code execution sandbox, filesystem or process policy, or general network egress control. No documented control stops a running agent. Block is not available for API-enforced runtime protection.

<!-- chunk: options -->
## Options

Pair AI Defense with a sandboxed runtime and an egress firewall, and test how fast a policy change blocks an active MCP connection.
