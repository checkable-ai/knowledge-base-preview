## Answer

Not covered. Credential rotation is not documented. 1Password for NVIDIA OpenShell (beta) keeps secret values out of the agent process and context, scopes them to approved hosts and limits them to a TTL, after which placeholders stop resolving. After expiry, though, it only offers to approve a new connection, with no rotation of the underlying credential. Credential Broker is a public preview for GitHub Actions only, with no rotation and no agent support yet.

Research detail: Credential Broker releases a single item-scoped credential to a verified requester per job and logs each delivery, in public preview for GitHub Actions only. For agents, the NVIDIA OpenShell integration keeps placeholders in the sandbox and swaps real secrets at the gateway for approved hosts within a set window, Agentic Autofill fills logins without the agent seeing values, and the Environments MCP server never returns secret values. Privileged Access routes agent access through a proxy so agents do not see raw secrets.

## Products

Credential Broker, 1Password for NVIDIA OpenShell, Agentic Autofill, Environments MCP Server, Privileged Access (Apono Agentic Access)

<!-- chunk: gaps -->
## Gaps

Automatic rotation is not in the Broker release. Broker agent support is planned, not available. The OpenShell integration is beta and the SDK tutorial still passes secrets into the app process.

<!-- chunk: options -->
## Options

Prefer the OpenShell, Agentic Autofill or Apono proxy patterns over SDK retrieval. Rotate target-system secrets outside 1Password until rotation ships.
