## Answer

Covered. Sandbox limits depend on OS support; Cursor says some commands bypass the sandbox and run modes are not a security boundary.

Source statement: "Team settings take precedence over individual and project configuration." (https://cursor.com/docs/agent/security/run-modes)

Research detail: Run Modes (Auto-review, Allowlist, Run Everything) govern local tool calls, and the sandbox limits shell commands to the workspace with network blocked by default, using Seatbelt on macOS and Landlock with seccomp on Linux. Hooks can deny shell, file read and tool calls. Admin team policies override user and project settings.

<!-- chunk: products -->
## Products

Run Modes, Agent sandbox, Hooks, .cursorignore, Team read policy

<!-- chunk: gaps -->
## Gaps

Cursor states Auto-review and allowlists are not a security boundary. The Linux sandbox needs kernel 6.2 or later. Terminal and MCP tools ignore .cursorignore.

<!-- chunk: options -->
## Options

Enforce Auto-review with sandboxing at team level, deploy fail-closed hooks via MDM or cloud distribution, and test sandbox escapes.
