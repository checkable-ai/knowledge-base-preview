## Answer

Covered. Cloud runs can be cancelled via API; local sandbox varies by OS; no admin-wide stop for local agents.

Source statement: "Cancellation is terminal - the run transitions to `CANCELLED` and cannot be resumed." (https://cursor.com/docs/cloud-agent/api/endpoints)

Research detail: Local agent commands run in an OS sandbox (Seatbelt on macOS, Landlock and seccomp on Linux) with writes limited to the workspace and network blocked by default apart from the allowlist. Team settings override user and project files. Cloud Agents run in per-agent Firecracker microVMs in a separate AWS account, with egress modes that Enterprise admins can lock. The Cancel A Run API ends a cloud run terminally.

<!-- chunk: products -->
## Products

Agent sandbox and run modes, sandbox.json, Cloud Agent microVMs, Lock Network Access Policy, Cancel A Run API

<!-- chunk: gaps -->
## Gaps

Windows sandboxing is not described, and Linux falls back to approval prompts on older kernels. The network lock does not reach self-hosted machines. No admin-wide stop for local agents or documented revocation of the GitHub app grant was found.

<!-- chunk: options -->
## Options

Lock the network policy and run modes at team level, script the cancel endpoint into incident runbooks, and revoke the GitHub app installation to cut repository access.
