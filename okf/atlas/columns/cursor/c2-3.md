## Answer

Covered. Cloud Agents only; network egress restriction to an allowlist is configurable and admins can enforce it org-wide. Local agents use the OS sandbox.

Source statement: "Runtime workspaces run on Firecracker-based microVM infrastructure." (https://cursor.com/docs/cloud-agent/security)

Research detail: Local shell commands run in an OS sandbox with workspace-limited writes and default-deny network. Cloud Agents run in per-agent Firecracker microVMs in a separate AWS account, with configurable egress modes. Self-hosted machines are also supported.

<!-- chunk: products -->
## Products

Agent sandbox, Cloud Agent VMs, Cloud Agent network policy, Self-hosted machines

<!-- chunk: gaps -->
## Gaps

Local agents outside the sandbox have the user's full permissions. Egress enforcement for hosted runs is not described.

<!-- chunk: options -->
## Options

Require sandboxing and lock egress to an allowlist. Run sensitive work on self-hosted machines behind your own controls.
