## Answer

Not covered. No per-agent identity tied to owner, running location and release. Session tokens and signed-in user identity cover one session type and do not identify the release.

Research detail: Sessions in a self-hosted environment receive an Anthropic-signed ES256 JWT carrying the session ID, environment (pool) ID, organisation ID, runner and the creating user or service identity, verifiable against a public JWKS. Local sessions carry a session.id, account and organisation attributes on OpenTelemetry data. Neither links the agent to a release or configuration version.

<!-- chunk: products -->
## Products

Claude Code self-hosted environments session token (CLAUDE_CODE_SESSION_ACCESS_TOKEN), OpenTelemetry standard attributes

<!-- chunk: gaps -->
## Gaps

Signed identity exists only for self-hosted cloud sessions. Local CLI sessions have no workload identity beyond the signed-in user. Any process in the session can read and present the token, and there is no revocation feed.

<!-- chunk: options -->
## Options

Use self-hosted environments where downstream services must verify the agent. Record session.id with the Claude Code version and managed settings source in your own inventory.
