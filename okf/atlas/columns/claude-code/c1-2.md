## Answer

Covered. Enforcement needs managed settings or managed-mcp.json. Controls apply to server and tool selection, not to what the downstream credential permits.

Source statement: "As an administrator, you can restrict which servers run in your organization, from deploying a fixed approved set to disabling MCP entirely, and you can provide servers to every user." (https://code.claude.com/docs/en/managed-mcp)

Research detail: MCP tools can be allowed or denied per server and per tool in permission rules, managed allowlists and denylists control which MCP servers load by URL or command, WebFetch rules scope domains, and the sandbox network allowlist limits shell egress. Subagents can be given their own tool and MCP server lists.

<!-- chunk: products -->
## Products

Permission rules (MCP, WebFetch), allowedMcpServers and deniedMcpServers, managed-mcp.json, sandbox network isolation, subagent tools and mcpServers

<!-- chunk: gaps -->
## Gaps

Scopes apply to tool calls, not to what the downstream credential permits. serverName matching is not a security control. Server-managed settings apply one policy per organisation.

<!-- chunk: options -->
## Options

Match MCP servers by serverUrl or serverCommand, set allowManagedMcpServersOnly, and scope downstream credentials separately.
