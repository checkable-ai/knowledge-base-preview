## Answer

Covered. Enforced on the client through admin-deployed managed settings (MDM, managed file, or server-managed settings on Team/Enterprise). The sandbox is off by default and has to be turned on. allowManagedDomainsOnly locks network domains to the managed list, but only for commands running inside the sandbox. WebFetch is controlled by permission rules, not the sandbox domain list. managed-mcp.json cannot be delivered through server-managed settings. Bash argument patterns are fragile, so checking input formats beyond the permission rules needs PreToolUse hooks.

Source statement: "The Bash sandbox is a boundary that the operating system enforces around the shell commands Claude runs on your machine." (https://code.claude.com/docs/en/sandboxing)

Research detail: The client enforces tool policy itself: permission rules per tool and MCP tool, managed MCP allowlists and denylists, PreToolUse hooks that can allow, deny or rewrite input, sandbox egress allowlists, and the auto mode classifier, with a server-side probe that scans incoming tool results for suspicious content. Gateway policies can apply different settings per IdP group.

<!-- chunk: products -->
## Products

Permission rules, managed MCP controls, hooks, sandbox network isolation, auto mode classifier

<!-- chunk: gaps -->
## Gaps

Enforcement is client-side, not a separate gateway. No tool quotas or rate limits, no schema validation policy, and Bash rules match command text.

<!-- chunk: options -->
## Options

Pair managed permission rules with an enforced sandbox and a TLS-inspecting egress proxy, and use PreToolUse HTTP hooks to call an external policy service.
