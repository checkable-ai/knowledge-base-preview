## Answer

Covered, with conditions. Enforced on the client through admin-deployed managed settings (server-managed settings, MDM, registry or managed-settings.json). managed-mcp.json is a system file and cannot be delivered through server-managed settings. allowManagedMcpServersOnly is needed to stop users broadening the allowlist. The restrictions cover MCP servers that Claude Code loads itself. Network controls from the sandbox apply only to sandboxed shell commands, and the sandbox is off by default. Where installed mods approve tool calls, preserving denials requires managed settings, managed-mcp.json, or a Team or Enterprise /login credential.

Source statement: "Allowlists and denylists filter which configured servers are allowed to load." (https://code.claude.com/docs/en/managed-mcp)

Last checked 18 November 2026.

Research detail: The client enforces tool policy itself: permission rules per tool and MCP tool, managed MCP allowlists and denylists, PreToolUse hooks that can allow, deny or rewrite input, sandbox egress allowlists, and the auto mode classifier, with a server-side probe that scans incoming tool results for suspicious content. Gateway policies can apply different settings per IdP group.

<!-- chunk: products -->
## Products

Permission rules, managed MCP controls, hooks, sandbox network isolation, auto mode classifier

<!-- chunk: gaps -->
## Gaps

Enforcement is client-side, not a separate gateway. No tool quotas or rate limits, no schema validation policy, and Bash rules match command text.

<!-- chunk: options -->
## Options

Pair managed permission rules with an enforced sandbox and a TLS-inspecting egress proxy, and use PreToolUse HTTP hooks to call an external policy service.
