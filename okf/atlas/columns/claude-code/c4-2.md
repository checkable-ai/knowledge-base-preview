## Answer

Not covered. No documented rotation or revocation of agent credentials and no short-lived credential issuance across agents. The Anthropic-hosted cloud session proxy keeps git credentials outside the VM, but covers only those sessions and does not stop a secret printed by a tool reaching the model.

Research detail: The sandbox can deny or mask named credential files and environment variables. In mask mode sandboxed commands see a per-session placeholder and the sandbox proxy substitutes the real value only on requests to allowed hosts. Cloud sessions keep GitHub credentials on Anthropic servers and give the VM a short-lived session-scoped credential. The Claude apps gateway holds the upstream model credential and issues short-lived SSO bearer tokens.

<!-- chunk: products -->
## Products

sandbox.credentials (deny and mask), apiKeyHelper, cloud session GitHub proxy, Claude apps gateway

<!-- chunk: gaps -->
## Gaps

Masking covers sandboxed Bash only and needs the experimental TLS termination setting. MCP servers, hooks and file tools run outside the sandbox. There is no built-in credential deny list. Rotation and revocation of tool credentials are left to the customer's secrets tooling.

<!-- chunk: options -->
## Options

Deploy sandbox.credentials mask entries through managed settings, pair with a vault-backed apiKeyHelper, and test that masked values never appear in transcripts or OTel logs.
