## Answer

Covered. Remote MCP servers must be set up with OAuth, per-user headers or headersHelper so each user authenticates as themselves. A shared header in managedMcpServers does not give per-user identity.

Source statement: "Pass per-user credentials with one of these instead:" (https://code.claude.com/docs/en/managed-mcp)

Last checked 18 November 2026.

Research detail: The self-hosted session token records an RFC 8693 act chain from the creating user or service identity through runner and environment, so downstream services can verify who started the session and issue scoped credentials. Remote MCP servers can use per-user OAuth so each developer authenticates as themselves.

<!-- chunk: products -->
## Products

Self-hosted session token act claim, MCP OAuth and per-user headers

<!-- chunk: gaps -->
## Gaps

The act chain exists only in self-hosted environments. Anthropic advises treating the token as weaker than a direct login because any code in the session can present it. Local sessions pass the developer's own credentials rather than a delegated, attenuated token.

<!-- chunk: options -->
## Options

Exchange the session token at an internal token service for short-lived, task-scoped credentials and audit by ccr:session_id and jti, as the documentation recommends.
