## Answer

Covered, with conditions. Needs a self-hosted Claude apps gateway backed by Postgres, with an admin: block configured in gateway.yaml. Spend amounts are USD estimates and act as a circuit breaker, not an invoice. By default, enforcement fails open if Postgres can't be reached; setting enforcement.fail_closed_on_error: true makes it fail closed. The gateway's own configurable rate_limits cover only device-grant sign-in, not /v1/messages inference. Inference throttling is done by daily, weekly and monthly spend caps per user, group or organisation, or by an upstream proxy's 429, which the gateway passes through. Non-US Amazon Bedrock regions need a models: block with per-upstream model IDs.

Source statement: "Spend limits cap how much each developer can spend through your Claude apps gateway in a given day, week, or month." (https://code.claude.com/docs/en/claude-apps-gateway-spend-limits)

Research detail: The Claude apps gateway, built into the claude binary and self-hosted, signs users in with the corporate IdP, enforces model access per IdP group server-side, routes and fails over between Bedrock, Google Cloud, Foundry and the Anthropic API, and caps spend per user, group or organisation with live 429 enforcement. Console workspaces also offer spend and rate limits.

<!-- chunk: products -->
## Products

Claude apps gateway, gateway spend limits, Console workspace limits

<!-- chunk: gaps -->
## Gaps

No documented prompt injection screening at the gateway. Spend enforcement fails open by default if Postgres is unavailable. Caps are USD estimates, not token rate limits.

<!-- chunk: options -->
## Options

Set enforcement.fail_closed_on_error, and add a separate screening layer if injection screening at the model boundary is required.
