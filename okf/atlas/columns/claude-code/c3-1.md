## Answer

Covered. Needs a self-hosted Claude apps gateway with Postgres and an admin block in gateway.yaml. Set allowedProviders to gateway in managed settings (Claude Code v2.1.285 or later) so developers cannot bypass it. Spend caps are USD estimates by day, week or month. Enforcement fails open if Postgres is unreachable unless enforcement.fail_closed_on_error is true. Request and token rate limits and prompt-injection screening are not documented at the gateway.

Source statement: "Use spend limits to give each developer, group, or the whole organization a ceiling on a credential everyone shares." (https://code.claude.com/docs/en/claude-apps-gateway-spend-limits)

Research detail: The Claude apps gateway, built into the claude binary and self-hosted, signs users in with the corporate IdP, enforces model access per IdP group server-side, routes and fails over between Bedrock, Google Cloud, Foundry and the Anthropic API, and caps spend per user, group or organisation with live 429 enforcement. Console workspaces also offer spend and rate limits.

<!-- chunk: products -->
## Products

Claude apps gateway, gateway spend limits, Console workspace limits

<!-- chunk: gaps -->
## Gaps

No documented prompt injection screening at the gateway. Spend enforcement fails open by default if Postgres is unavailable. Caps are USD estimates, not token rate limits.

<!-- chunk: options -->
## Options

Set enforcement.fail_closed_on_error, and add a separate screening layer if injection screening at the model boundary is required.
