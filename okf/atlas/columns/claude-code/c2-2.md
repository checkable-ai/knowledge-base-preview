## Answer

Covered, with conditions. availableModels, deniedModels and enforceAvailableModels must be set in managed or policy settings. Sessions on Amazon Bedrock, Google Cloud's Agent Platform, Microsoft Foundry and Claude Platform on AWS do not receive server-managed settings, so the allowlist must be delivered through MDM or managed settings files there. Family-alias substitution does not operate on providers with provider-specific model IDs. Opus 4.6 with 1M context is included on Max, Ultra, Team and Enterprise. Sonnet 4.6 with 1M context requires usage credits on subscription plans. Data-training and retention rules differ between consumer accounts and commercial Team, Enterprise and API accounts.

Source statement: "Aliases point to the recommended version for your provider and update over time." (https://code.claude.com/docs/en/model-config)

Last checked 18 November 2026.

Research detail: Models are selected by alias or pinned ID, with per-alias pinning on Bedrock, Google Cloud and Foundry. Administrators restrict models with availableModels, enforceAvailableModels and deniedModels, cap effort, and restrict API providers with allowedProviders. Data handling and encryption at rest are documented per provider.

## Products

Model configuration, availableModels, allowedProviders, maxEffortLevel, provider choice

<!-- chunk: gaps -->
## Gaps

Aliases move to new model versions over time unless pinned. Organisation-level server-side model controls do not reach third-party cloud providers.

<!-- chunk: options -->
## Options

Pin full model IDs in managed settings and restrict providers for regulated workloads.
