## Answer

Not covered. No sandboxing, file, process or network limits, and no documented kill switch or access revocation. Agent Behavior Governance policy checks and Agent Scan scanning fall short.

Research detail: Agent Behavior Governance runs inside the agent execution loop and evaluates each action against policy before it runs, using full session context. It supports Claude Code, Codex, Cursor and GitHub Copilot, with a limit of 5,000 behavioural guardrail requests per machine per day and seven day data retention. Agent Scan is a discovery and scanning tool and tells users to run it inside a sandbox.

<!-- chunk: products -->
## Products

Agent Behavior Governance, Agent Scan (scanner only)

<!-- chunk: gaps -->
## Gaps

No sandboxing, filesystem or process policy, or network egress control is documented for agents. The docs do not describe a kill switch, session termination or credential revocation. The docs list MCP Governance as the only supported use case and do not describe how policies are configured. A news report describes the feature as a preview, which the docs pages read did not confirm.
