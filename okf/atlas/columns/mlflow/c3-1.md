## Answer

Not covered. The MLflow AI Gateway routes calls through traffic splitting and fallbacks. It also has budget policies that alert, or reject requests with HTTP 429, once USD spend passes a cap. Those caps are scoped globally, per endpoint or per workspace. The vendor documents no request-rate limits and no per-agent or per-user quotas. MLflow's own post on coding agents says the gateway deliberately has no per-minute rate limit and that the only control is dollars. The gateway's LLM-judge guardrails enforce content policies, but the docs do not describe them as prompt-injection screening.

Last checked 17 November 2026. This platform is checked on demand, so this answer has not been rechecked since.

Research detail: AI Gateway routes requests to providers with traffic splits and fallbacks, requires USE permission per endpoint, caps spend with global or workspace budget policies that alert or reject with HTTP 429, and runs LLM-judge guardrails that block or sanitise requests and responses. Prompt injection is not a built-in guardrail type and must be written as a custom one. Budgets are not per user or per endpoint, no request rate limits are documented, and post-LLM guardrails do not run on streaming requests.

## Products

MLflow AI Gateway, Guardrails, Budget policies

## Gaps

No rate limits, no per-user quota, injection screening only via a custom judge. Databricks AI Gateway adds rate limits and per-user budgets.

<!-- chunk: options -->
## Options

Front with a gateway that has per-user rate limits, or test Databricks AI Gateway.
