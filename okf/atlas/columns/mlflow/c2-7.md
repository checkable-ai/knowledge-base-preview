## Answer

Not covered. No sandboxing or per-agent emergency stop; gateway budget rejection only limits spend on gateway calls.

Research detail: MLflow does not execute agent code, so sandboxing sits outside its category. The MLflow AI Gateway can cut an agent's model access: a budget policy with the Reject action blocks all later gateway requests with HTTP 429 once spend passes the limit, and gateway endpoints can be deleted. These act on model calls routed through the gateway only.

<!-- chunk: products -->
## Products

MLflow AI Gateway budget policies with Reject, endpoint deletion

<!-- chunk: gaps -->
## Gaps

No per-agent stop control or credential revocation for a running agent. The request that crosses the budget is allowed to finish. Agents that call providers directly bypass the gateway.

<!-- chunk: options -->
## Options

Route all agent model traffic through the gateway, and pair it with a runtime sandbox for code and egress.
