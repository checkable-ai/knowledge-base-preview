## Answer

Not covered. No ordering or sequencing of steps, no handoff between agents, and no defined retry semantics. Cancellation is cooperative, so the server is not obliged to stop. The nearby feature is the opt-in Tasks extension, which tracks individual long-running requests and not an agent's multi-step work.

Last checked 12 November 2026. This platform is checked on demand, so this answer has not been rechecked since.

Research detail: The protocol defines request cancellation, multi round-trip requests for interim input, and the Tasks extension gives durable task handles with working, input_required, completed, failed and cancelled states. It does not sequence workflows or delegate between agents.
