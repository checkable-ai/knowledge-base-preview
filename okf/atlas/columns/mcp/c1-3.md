## Answer

Not covered. Nothing binds an approval to the exact action about to run. Elicitation is a general user-input mechanism, and the spec says only that clients SHOULD implement user approval controls. It defines no handling of repeat or replayed attempts after a refusal. Enforcement is left to each host and server. The nearby features are elicitation accept/decline/cancel and Tasks input_required, and both fall short.

Last checked 12 November 2026.

Research detail: The specification says hosts must obtain explicit user consent before invoking any tool, and the Tools page says there SHOULD always be a human able to deny tool invocations, with confirmation prompts. Elicitation gives the user decline and cancel options. Approval is not bound to the exact action and replay handling is not defined.
