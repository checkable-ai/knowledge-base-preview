## Answer

Covered. Authorisation is optional and applies to HTTP transports only; stdio servers take credentials from the environment. Short lifetimes are a SHOULD, refresh token rotation is a MUST for public clients only, and revocation is handled by the authorisation server. URL mode elicitation keeps credentials out of the LLM context.

Source statement: "Authorization servers **SHOULD** issue short-lived access tokens to reduce the impact of leaked tokens." (https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization/security-considerations.md)

Research detail: The specification requires audience-bound tokens under RFC 8707, forbids token passthrough to upstream APIs, keeps tokens out of URI query strings and requires refresh tokens to stay confidential. Servers MUST use URL mode elicitation for credentials so they never pass through the LLM context or the client. Rotation and revocation are left to the authorisation server.

## Products

MCP Authorization, URL mode elicitation

<!-- chunk: gaps -->
## Gaps

No rotation or revocation rules of its own. Authorisation is optional and stdio servers take credentials from the environment.

<!-- chunk: options -->
## Options

Test that servers reject tokens issued for another audience and that credentials are only collected through URL mode.
