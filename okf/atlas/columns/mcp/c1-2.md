## Answer

Covered. Applies to HTTP transports that implement MCP authorization, which is optional. Scope names and granularity are defined by each server.

Source statement: "Servers MUST account for scope hierarchies, where a broader scope implies narrower ones, when deciding whether a token is sufficient for an operation." (https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization/index.md)

Research detail: Servers SHOULD declare required scopes in WWW-Authenticate challenges, clients SHOULD request least privilege, and a step-up flow handles insufficient_scope errors. Servers MUST account for scope hierarchies when judging whether a token is sufficient. Scope design itself is left to each server.
