## Answer

Covered. SAP AI Core orchestration; limits per resource group and model, not per user or agent; filtering configured per request.

Source statement: "When creating a deployment for orchestration, you can restrict the choice of models using an allow or deny list." (https://github.com/SAP-docs/sap-artificial-intelligence/blob/main/docs/sap-ai-core/generativeAI/model-restriction-4d499ee.md)

Research detail: The SAP AI Core orchestration service enforces model allow or deny lists per deployment, per-model request-per-minute limits at tenant and resource group level, and optional prompt attack detection through Azure Prompt Shield. Content filtering with Azure Content Safety or Llama Guard 3 applies to input and output.

<!-- chunk: products -->
## Products

SAP AI Core orchestration, model restriction, rate limit management, content filtering

<!-- chunk: gaps -->
## Gaps

Limits are per resource group and model, not per end user or per agent. Filtering is optional and must be configured per request or config.

<!-- chunk: options -->
## Options

Separate agents into resource groups and use stored orchestration configs that include filters.
