## Answer

Not covered. No sandbox limits on files and network, and no kill switch for Joule agents. AI Core deployment stop is asynchronous and egress policy is undocumented.

Research detail: SAP AI Core enforces restricted pod settings on customer workloads: all Linux capabilities dropped, a fixed non-root user and group, and privilege escalation disabled, with non-compliant pods rejected. Deployments and executions can be stopped by setting targetStatus to STOPPED through the API or AI Launchpad. No sandbox or stop control for running Joule agents is documented in the pages that could be read.

<!-- chunk: products -->
## Products

SAP AI Core restricted pod settings, deployment stop in SAP AI Core and SAP AI Launchpad

<!-- chunk: gaps -->
## Gaps

Network egress policy for AI Core workloads is not documented in these pages. Stop is scheduled asynchronously (the API returns Deployment modification scheduled), so timing is not stated. No kill switch for Joule Agents or Joule Studio agents was found, and help.sap.com Joule pages could not be rendered.
