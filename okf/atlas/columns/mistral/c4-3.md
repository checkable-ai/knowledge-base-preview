## Answer

Covered. Connectors are Public Preview. Requires per-user connector credentials; organisation-level App Connections let members use a shared connection and do not give per-user identity. No documented identity propagation through handoffs or workflows.

Source statement: "Use Connector credentials when users or Workspaces need a specific account connection." (https://docs.mistral.ai/admin/identity-access/connectors)

Research detail: Connectors support OAuth2 with per-user credential sets, so tool calls can run under the connecting user's account. Vibe Work custom MCP connectors support OAuth 2.1 with a consent flow. Organisation-level shared app connections instead let members use an admin's connection without signing in.

<!-- chunk: products -->
## Products

Connectors (per-user OAuth credentials), Vibe Work MCP connectors

<!-- chunk: gaps -->
## Gaps

No documented token exchange or propagation of the initiating user identity through handoffs, workflows or service accounts. Shared connections break per-user attribution downstream.

<!-- chunk: options -->
## Options

Use per-user credentials rather than shared connections for sensitive systems. Test which identity downstream systems log for agent tool calls.
