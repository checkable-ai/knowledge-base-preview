## Answer

Not covered. Agents have agent_id and versions, and service accounts are separate identities, but no documented identity ties an agent to an owner, runtime location and release.

Research detail: Agents created through the Agents API get a stable agent_id and numbered versions. Workloads can authenticate as service accounts, which are workspace-scoped non-human identities with assigned roles, and audit logs name the workload rather than a person. Agent IDs and service accounts are separate objects, and nothing documented links an agent to an owner, runtime and release in one identity record.

<!-- chunk: products -->
## Products

Agents API (agent_id, versions), service accounts, workload identity federation

<!-- chunk: gaps -->
## Gaps

No documented link between an agent object and a service account or accountable owner. Service accounts are documented for workflow workers, not agents.

<!-- chunk: options -->
## Options

Map each agent_id to a service account and owner in an external register. Test whether agent actions in audit logs carry the agent ID.
