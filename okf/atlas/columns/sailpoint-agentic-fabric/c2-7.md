## Answer

Not covered. No sandbox for files, processes or network egress and no documented emergency stop. Endpoint Agent AuthZ policies deny matching requests by tool family, but that is not sandboxing. Quarantine and revoke claims appear only on a product page.

Research detail: The Protect product page says dynamic risk-based responses can quarantine a high-risk agent, revoke access, terminate suspicious sessions or isolate an agent. The documentation shows two enforcement points. Gateway Access policies are default deny, and Endpoint Agent AuthZ policies deny matching requests, including by tool family (MCP, terminal, file and category).

<!-- chunk: products -->
## Products

Agentic Fabric Protect, Gateway Access policies, Endpoint Agent AuthZ policies, just-in-time access provisioning

<!-- chunk: gaps -->
## Gaps

The quarantine, revoke and terminate claims are on a product page, and the documentation index read describes alerts for unsanctioned tools rather than blocks and does not say that deleting an application stops access. There is no sandbox, filesystem or process policy and no general network egress control. How quarantine works, how far it reaches and how fast it acts are not documented, and Endpoint Agent AuthZ is allow by default.

<!-- chunk: options -->
## Options

Test whether a quarantine or terminate action stops an in-flight session on the endpoint and gateway, and measure the time to effect.
