## Answer

Not covered. No short-lived or scoped credentials and no documented rotation or expiry feature. Rotation and revocation are guidance in Security Onboarding. Nearby: project-specific keys and Remote MCP header redaction from logs, which do not give scoped or expiring credentials.

Research detail: Each project has its own API keys and logs. Security guidance says to keep keys in environment variables or a secret manager, rotate periodically, use separate keys per environment and revoke on suspected compromise. Remote MCP credentials in the headers field are sent only to the named server and redacted from Groq logs.

## Products

Projects, Security Onboarding, Remote MCP headers

## Gaps

Rotation and expiry are guidance, not documented features. Key scopes and short-lived credentials were not found.

<!-- chunk: options -->
## Options

Use an external secrets manager and one project per workload.
