## Answer

Covered. Applies to runs invoked by a user. Scheduled agents and agents using service credentials do not carry an individual user.

Source statement: "It uses the permissions and tokens of that user, and in connected systems it appears as that user." (https://docs.glean.com/administration/agent-identity/overview)

Research detail: By default an agent runs as the invoking user with that user's permissions and tokens. MCP tools run as the authenticated user with Knowledge Graph ACLs applied, remote MCP servers support per-user OAuth, and A2A host calls carry each user's own authorisation. A tool cannot perform an action the user's account could not perform in the app.

<!-- chunk: products -->
## Products

Glean Agents default execution, Glean MCP servers, remote MCP OAuth User, A2A host

<!-- chunk: gaps -->
## Gaps

Delegation uses per-user OAuth tokens rather than a token exchange that records the agent as actor. Scheduled agents and OAuth Admin connections do not carry an individual user.

<!-- chunk: options -->
## Options

Prefer OAuth User over OAuth Admin or API key for remote MCP servers and confirm downstream logs show the user.
