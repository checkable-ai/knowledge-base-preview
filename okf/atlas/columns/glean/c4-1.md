## Answer

Not covered. Agent identity (beta) gives scoped service credentials per credential and tool, not per agent. Nothing documented ties an agent identity to where it runs or to its release version. Interactive agents run as the invoking user.

Research detail: Independent agents have their own profile and, through agent identity, act as their own bot or account in each connected app using a scoped service credential. Run history and the audit log separate the triggering user or schedule from the agent's actions. Agents have an Owner access tier that can be transferred.

## Gaps

Independent agents are beta. Agent identity is per credential and per tool, not one identity per agent. No documented link from the identity to a runtime or release version. Interactive agents run as the invoking user with no separate identity.

<!-- chunk: options -->
## Options

Use independent agents with service credentials for automation and keep a register mapping agent, owner, credentials and published version.
