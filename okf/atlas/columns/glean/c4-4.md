## Answer

Covered. A2A host supports only the OAuth authorization code flow.

Source statement: "Each person authorizes the external agent separately, so outbound requests use their identity and access." (https://docs.glean.com/administration/platform/a2a-host)

Research detail: Glean supports A2A in three directions. An admin registers external A2A servers with OAuth client details and each user authorises separately. External clients call Glean Assistant under Glean OAuth as the individual user, and single agents can be exposed with a per-agent bearer token with access evaluated per caller.

<!-- chunk: products -->
## Products

Glean A2A host, Glean A2A server, per-agent A2A endpoints

<!-- chunk: gaps -->
## Gaps

The A2A host supports only the OAuth authorisation code flow and text messages. No documented allowlist or logging for A2A host calls. No documented admin control to disable per-agent exposure.

<!-- chunk: options -->
## Options

Restrict who can publish agents and test that per-agent tokens can be revoked.
