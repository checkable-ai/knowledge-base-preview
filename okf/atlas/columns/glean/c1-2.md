## Answer

Covered. Agent access policies need Protect+ and are in beta. Tool enablement is available to admins generally.

Source statement: "The Glean runtime evaluates applicable policies at two distinct phases of a tool invocation." (https://docs.glean.com/administration/protect/ai-security/agent-access-policies)

Research detail: Admins enable tools per app and per tool, choose availability for agents or chat, and restrict who can add tools to agents. Agent access policies (Protect+) evaluate tool calls and outputs at runtime and can block calls, such as writes by a user group or posts to public Slack channels. Service credential scope limits agent identity actions.

<!-- chunk: products -->
## Products

Tool enablement, role-based tool access, MCP tool toggles, agent access policies, agent identity

<!-- chunk: gaps -->
## Gaps

Role-based tool access controls builders, not runtime use. Agent access policies are Protect+ and beta. All gateway tools are enabled for all users by default.

<!-- chunk: options -->
## Options

Disable unused write tools, scope tool access and use agent access policies for high-risk writes.
