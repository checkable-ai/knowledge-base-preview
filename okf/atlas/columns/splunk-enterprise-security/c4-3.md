## Answer

Covered. Applies to agent calls into Splunk Enterprise Security through the Splunk MCP Server app, using an MCP encrypted token. Roles that can run each tool are configurable. Does not cover agent calls into other systems.

Source statement: "The MCP Server app for Splunk Platform does not override role-based access control in Splunk Enterprise Security." (https://help.splunk.com/en/splunk-enterprise-security-8/user-guide/8.7/introduction/use-the-splunk-mcp-server-app-to-access-tools-in-splunk-enterprise-security)

Research detail: MCP clients connect to ES with a user's MCP encrypted token, and the MCP Server app does not override ES role-based access control, so an agent's ES queries are bounded by that user's roles. Admins can also map roles to individual MCP tools.

<!-- chunk: products -->
## Products

Splunk MCP Server app, ES role-based access control

<!-- chunk: gaps -->
## Gaps

Applies only to calls into Splunk. The pages read do not state how the user identity appears in audit events for MCP calls, and there is no propagation to other services.

<!-- chunk: options -->
## Options

Issue per-user tokens with expiry and confirm in the _audit index that MCP tool calls are attributed to the token owner.
