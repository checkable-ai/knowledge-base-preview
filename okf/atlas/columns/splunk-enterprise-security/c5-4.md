## Answer

Covered. Delivered by Splunk Observability Cloud (AI Infrastructure Monitoring and Agent Observability), not by Enterprise Security itself. Applies to customer-run AI stacks, not Splunk's hosted ES agents. Requires data integrations through the Splunk Distribution of the OpenTelemetry Collector; NVIDIA GPU setup is documented for Kubernetes clusters and its DCGM metrics count as custom metrics. Anomaly alerting uses the general Observability Cloud detector conditions (Sudden Change, Historical Anomaly), which the customer configures; no GPU-specific anomaly detector is documented. Splunk AI Agent Monitoring is scheduled for deprecation in favour of Splunk Agent Observability, for which access is requested through the Splunk team.

Source statement: "Monitor and troubleshoot the performance of the AI infrastructure components used to build your AI applications." (https://help.splunk.com/en/splunk-observability-cloud/observability-for-ai/splunk-ai-infrastructure-monitoring)

Research detail: The AI agents page in Splunk APM shows which agents are degraded in performance and when errors began, and a Create Detector action generates alerts for an agent.
