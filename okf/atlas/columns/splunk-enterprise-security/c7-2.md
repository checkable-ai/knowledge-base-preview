## Answer

Not covered. No documented path that delivers agent security telemetry to the SOC linked to sessions and people, with redaction, detections and a named response owner. The Cisco AI Defense ESCU detections are disabled by default and have no user or session fields. Session and user IDs appear only in Observability Cloud AI Security Monitoring traces, which are not documented as feeding ES.

Research detail: ES ingests Cisco AI Defense alerts through the Cisco Security Cloud app into the cisco:ai:defense sourcetype, and a Splunk detection aggregates them by model, connection, application and user into risk events. Lantern describes an AI Defense dashboard and AI Defense findings in the analyst queue. ESCU also has an experimental Ollama prompt injection detection, and AI Security Monitoring propagates user and session IDs in agent traces.

## Products

ES, Splunk Security Content, Cisco Security Cloud app, AI Security Monitoring

<!-- chunk: gaps -->
## Gaps

The AI Defense detection is disabled by default and creates a risk event with score 20, not a finding. The Ollama detection is experimental with failing tests. Detection depends on AI Defense, and AI Security Monitoring data lands in Observability Cloud. Redaction is not documented.

<!-- chunk: options -->
## Options

Enable the AI Defense detection, tune its risk score, and write custom detections over agent logs stored in Splunk indexes.
