## Answer

Not covered. Egress limits are the customer's job and there is no allowlist. Workflow stop and the filesystem sandbox are nearby but no instant access revocation is documented.

Research detail: By default Agent Studio isolates all user-authored tool code and MCP subprocess runs in a Linux namespace (bubblewrap) that prevents arbitrary filesystem access, and Kubernetes network policies block traffic between user namespaces. Cloudera states that Agent Studio does not enforce an allowlist of MCP servers or tool endpoints and that any registered MCP server can make outbound connections. It recommends routing tool traffic through a network proxy for egress allowlisting. No dedicated control to stop a running workflow or revoke an agent's access at once is documented.
