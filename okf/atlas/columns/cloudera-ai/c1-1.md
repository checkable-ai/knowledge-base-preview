## Answer

Covered. Default behaviour for user-authored tool code and MCP subprocesses in Agent Studio. Not configurable per agent or tool.

Source statement: "within a Linux namespace (bubblewrap)" (https://docs.cloudera.com/machine-learning/1.5.5/use-ai-studios/topics/ml-shared-responsibility-model.html)

Research detail: User-authored tool code and MCP subprocess runs are isolated in a Linux namespace with bubblewrap, which prevents arbitrary filesystem access. Kubernetes network policies block traffic between user namespaces. Cloudera tells customers to grant custom tools only the minimal permissions they need.

<!-- chunk: products -->
## Products

Agent Studio tool sandboxing, Workbench Kubernetes network isolation

<!-- chunk: gaps -->
## Gaps

No per-agent or per-tool configurable local permission set is documented. Contributors can write to the shared project filesystem, including the Agent Studio configuration database.

<!-- chunk: options -->
## Options

Keep Contributor membership small and test sandbox boundaries for custom tools before production.
