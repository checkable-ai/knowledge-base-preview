## Answer

Covered. RBAC from Agent Studio 2.2.0, deny-by-default in 3.0.0. Changes are audit logged. No documented retirement workflow.

Source statement: "Restricts all API routes and UI features to explicit permissions" (https://docs.cloudera.com/machine-learning/1.5.5/use-ai-studios/topics/ml-shared-responsibility-model.html)

Research detail: Agent Studio 2.2.0 added role-based access control governing who can view, edit, deploy and delete workflows, models and tools, and 3.0.0 documents deny-by-default RBAC. Creation, change and deletion of workflows, agents, tools and MCP servers are audit logged with the username. Only Project or Site Administrators can select a service account for deployment.

<!-- chunk: products -->
## Products

Agent Studio RBAC, resource management audit logging, Workbench project roles

## Gaps

The cloud security recommendations page still says Agent Studio lacks a native RBAC mechanism, which conflicts with the 2.2.0 and 3.0.0 notes. Contributors can modify agents, tools and MCP registrations broadly. No retirement workflow documented.
