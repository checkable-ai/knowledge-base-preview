## Answer

Not covered. Only workflow-level service accounts are documented. No identity per agent bound to an owner, runtime location or release version.

Research detail: A deployed Agent Studio workflow runs as a Workbench Model plus a Workbench Application, and Cloudera recommends deploying production or shared workflows under a dedicated Service Account, in whose namespace the workflow runs. Resource audit entries and Phoenix traces are tagged with the acting user. There is no separate identity per agent inside a workflow.

<!-- chunk: products -->
## Products

Agent Studio deployed workflows, Workbench Service Accounts

<!-- chunk: gaps -->
## Gaps

No documented link from a workflow identity to a named owner or release version. Individual agents in a workflow share the workflow's runtime identity.

<!-- chunk: options -->
## Options

Deploy each workflow under its own service account and record owner and release in the project or application metadata. Correlate audit usernames with deployment records.
