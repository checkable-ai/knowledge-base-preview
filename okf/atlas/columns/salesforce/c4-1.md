## Answer

Not covered. Agent user records exist, but no documented binding of each agent identity to a named owner, runtime location and release.

Research detail: Agentforce Service agents run as a dedicated agent user record (EinsteinServiceAgent User) with an Einstein Agent licence, profile and permission sets created at agent setup. Lead Nurturing agents run as a dedicated EinsteinSDRAgent User. Employee agents have no separate identity and run as the logged-in user. The documentation does not describe linking the agent identity to a named owner, runtime or release.

<!-- chunk: products -->
## Products

Agent user (Einstein Agent User profile), Agentforce agent versions

<!-- chunk: gaps -->
## Gaps

No documented binding of agent user to an accountable owner or to a specific agent version. Employee agents carry no workload identity of their own.

<!-- chunk: options -->
## Options

Create one agent user per agent, rename it to the agent name as the docs suggest, and record owner and version mapping in an external register.
