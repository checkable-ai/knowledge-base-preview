## Answer

Covered. Employee agents, credential-verified Experience Cloud service agents and per-user MCP OAuth. Unverified or contact-verified service sessions run as the shared agent user.

Source statement: "require verifying a user's identity in a messaging session before an agent can take action on their behalf" (https://trailhead.salesforce.com/content/learn/projects/deploy-agent-authentication/learn-about-authentication-for-topics-and-actions)

Research detail: Employee agents run in the logged-in user's context and respect that user's profile, permission sets and sharing. Service agents on Experience Cloud with credential-based user verification run as the logged-in site user. MCP tools can use per-user OAuth, and in multi-agent solutions the session user identity passes to connected subagents. Service agents without verification run as the shared agent user, so delegation is not automatic in that mode.

<!-- chunk: products -->
## Products

Agentforce Employee agent, credential-based user verification, per-user MCP authentication, Multi-Agent Orchestration

<!-- chunk: gaps -->
## Gaps

Unverified and contact-verified service sessions run as the agent user and context variables do not control data access. ASA orchestrator with AEA subagents is unsupported.

<!-- chunk: options -->
## Options

Turn on credential-based user verification where possible and use the VerifiedCustomerId pattern with scoped actions otherwise.
