## Answer

Not covered. No documented OAuth token exchange or end-to-end propagation of the person's identity to called systems. OGX upstream_header and the MCP gateway (Technology Preview) fall short.

Research detail: OGX can run gateway-delegated authentication with the upstream_header provider, which trusts identity headers injected by a fronting gateway, and 3.5 GA adds user-request header routing so per-user tokens are mapped to external OGX providers. The MCP gateway validates the user JWT and authorises tool calls against roles in that token, and can fetch per-user credentials from Vault.

<!-- chunk: products -->
## Products

OGX upstream_header authentication, User-request header routing for external OGX providers, Connectivity Link MCP gateway AuthPolicy

<!-- chunk: gaps -->
## Gaps

No documented OAuth token exchange in the product docs read. The upstream_header model relies on the gateway stripping client headers and OGX not being reachable directly. MCP gateway is Technology Preview.

<!-- chunk: options -->
## Options

Front OGX with an authenticating gateway and block direct access with NetworkPolicy. Test that a forged identity header sent straight to OGX is rejected.
