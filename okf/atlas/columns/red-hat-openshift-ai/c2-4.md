## Answer

Covered. OGX Conversations API is Technology Preview, not recommended for production. No automatic retention or expiry period is documented, so the customer controls how long state is kept by deleting conversations and items. Read access follows OGX ABAC resource ownership and tenant isolation.

Source statement: "The Conversations API enables multi-turn, context-aware chats by managing server-side conversation state." (https://docs.redhat.com/en/documentation/red_hat_openshift_ai_self-managed/3.5/html/working_with_ogx/ogx-apis_rag)

Research detail: The OGX Conversations API keeps server-side conversation state and can delete a conversation and its history. Stored resources are owned by the creating user under OGX ABAC, and multi tenant mode filters every query by tenant.

<!-- chunk: products -->
## Products

OGX Conversations API (Technology Preview), OGX ABAC and tenant isolation

<!-- chunk: gaps -->
## Gaps

Conversations API is Technology Preview. No retention period is documented.

<!-- chunk: options -->
## Options

Enable multi tenant mode and test that one user cannot read another user's conversation.
