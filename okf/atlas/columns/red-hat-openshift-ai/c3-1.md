## Answer

Covered. Models-as-a-Service requires both an authorization policy and a subscription per group. External model routing is Technology Preview. Prompt injection screening is not part of MaaS and needs a separate guardrails deployment.

Source statement: "Authorization policies grant groups access to model endpoints through the API gateway." (https://docs.redhat.com/en/documentation/red_hat_openshift_ai_self-managed/3.5/html-single/govern_llm_access_with_models-as-a-service/index)

Research detail: Models-as-a-Service is GA. Group-based subscriptions set per-model token rate limits, MaaSAuthPolicy controls which groups reach which models, users hold expiring and revocable API keys, and a dashboard tracks token use and rate-limit violations. NeMo Guardrails can screen inputs for prompt injection and jailbreaks on the model path.

<!-- chunk: products -->
## Products

Models-as-a-Service, NeMo Guardrails

<!-- chunk: gaps -->
## Gaps

External model routing and per-tenant gateways are Technology Preview. Injection screening is a separate guardrails deployment, not part of MaaS.

<!-- chunk: options -->
## Options

Put NeMo Guardrails behind the MaaS route and test that quota exhaustion returns 429 and an injection prompt is blocked.
