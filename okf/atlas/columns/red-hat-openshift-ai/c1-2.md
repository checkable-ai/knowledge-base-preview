## Answer

Covered. Delivered through the Red Hat Connectivity Link MCP gateway (research notes it as Technology Preview). An AuthPolicy on the mcps listener with a CEL expression checks each requested tool against roles in the user's JWT, and the broker filters tools/list to authorised tools. Permissions follow the user's JWT roles rather than a separate per-agent scope. Revocation takes effect only when the token expires and is reissued. OGX route and ABAC policies and MaaSAuthPolicy add access control over platform resources and model endpoints.

Source statement: "The broker filters the tools list using the signed x-authorized-tools header." (https://docs.redhat.com/en/documentation/red_hat_connectivity_link/1.3/html-single/registering_mcp_servers_and_creating_policies/index)

Research detail: The MCP gateway authorisation AuthPolicy on the mcps listener uses CEL to check the requested tool against roles in the user JWT, and the broker filters tools/list to authorised tools. MaaSAuthPolicy grants groups access to specific model endpoints. OGX applies route policies and resource ABAC.

<!-- chunk: products -->
## Products

Connectivity Link MCP gateway AuthPolicy, MaaSAuthPolicy, OGX route and ABAC policies

<!-- chunk: gaps -->
## Gaps

MCP gateway is Technology Preview. Revoked roles persist until token expiry. No per-agent scope model separate from user roles is documented.

<!-- chunk: options -->
## Options

Map agent service accounts to Keycloak clients with tool roles, keep token lifetimes short, and test that an unauthorised tool call returns 403.
