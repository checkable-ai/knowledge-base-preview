## Answer

Not covered. Scoped one-time composite tokens exist, but token lifetime, rotation and revocation are not documented, and tokens are exposed to the job environment.

Research detail: Each flow run gets a one-time composite identity OAuth token limited to the ai_workflows and mcp scopes, and external agents can receive GitLab-managed gateway credentials or CI OIDC ID tokens. MCP server OAuth tokens are obtained through a Connect flow and stored by GitLab. Tokens are exposed to the job as environment variables, and setup_script commands run outside the sandbox with access to the triggering user's OAuth token.

<!-- chunk: products -->
## Products

Composite identity tokens, injectGatewayToken, CI/CD ID tokens, MCP OAuth connections

<!-- chunk: gaps -->
## Gaps

No documented token lifetime, rotation or revocation for composite tokens. Storage of MCP tokens described only as secure. Secrets are reachable from the agent's execution environment, not held outside it.

<!-- chunk: options -->
## Options

Use ID tokens with narrow aud claims and short-lived cloud credentials. Keep secrets out of setup_script and test whether agents can read token environment variables.
