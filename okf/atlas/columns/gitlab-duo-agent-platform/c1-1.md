## Answer

Covered. Agent tool governance is beta and needs Premium or Ultimate. Local access type covers IDE extensions and the GitLab Duo CLI. No filesystem or network sandbox by default.

Source statement: "This feature is in beta. It is subject to change without notice." (https://docs.gitlab.com/user/ai-governance/tool-governance/)

Research detail: Tool governance sets Always Allow, Always Ask or Always Deny per tool for a Local access type that covers IDE extensions and the GitLab Duo CLI. IDE agents ask before terminal commands and write calls. The documentation states IDE and CLI agents have unrestricted network access and recommends a VS Code Dev Container for isolation.

<!-- chunk: products -->
## Products

Agent tool governance (local access), IDE command approval

<!-- chunk: gaps -->
## Gaps

Tool governance is beta and Premium or Ultimate. No local filesystem or network sandbox for IDE and CLI agents. MCP server blocks do not apply to IDE or CLI configurations.

<!-- chunk: options -->
## Options

Run IDE agents in Dev Containers and set write and delete tools to Always Ask or Deny at group level.
