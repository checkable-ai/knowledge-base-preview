## Answer

Covered. Needs runners with Docker or Kubernetes executors. Sandbox needs privileged runner mode and a compatible image.

Source statement: "Flows that use CI/CD run on runners." (https://docs.gitlab.com/user/duo_agent_platform/flows/execution/)

Research detail: Remote flows run as CI jobs on GitLab-hosted or customer runners with Docker or Kubernetes executors. The sandbox uses Anthropic Sandbox Runtime for network and filesystem isolation (blocks ~/.ssh reads, limits writes and environment variables) with allow and deny domain lists set by admins and projects.

<!-- chunk: products -->
## Products

Flow runners, remote execution environment sandbox, network_policy

<!-- chunk: gaps -->
## Gaps

Sandbox needs privileged runners and the default or SRT-equipped image. If SRT is unavailable the flow runs unsandboxed with only a log warning. Local IDE agents are not sandboxed.

<!-- chunk: options -->
## Options

Use strict mode at group level and alert on the unsandboxed warning in job logs.
