## Answer

Covered. Flows on runners using composite identity.

Source statement: "the merge request is attributed to the human user who triggered the flow instead of the service account." (https://docs.gitlab.com/user/duo_agent_platform/composite_identity/)

Research detail: Flow outputs land as merge requests and comments reviewed through normal GitLab review, with flow-created merge requests attributed to the triggering user to support segregation of duties. Flow checkpoints let a user approve, reject or modify with feedback.

<!-- chunk: products -->
## Products

Sessions checkpoints, merge request review, composite identity attribution

<!-- chunk: gaps -->
## Gaps

Review of Agentic Chat answers is left to the user.

<!-- chunk: options -->
## Options

Require merge request approval rules that exclude the triggering user for flow-created changes.
