## Answer

Not covered. Composite identity service accounts are per flow and tied to the initiating user. No per-agent identity bound to runtime and release. Agentic Chat acts as the user.

Research detail: Enabling a flow creates a service account in the top-level group (named like ai-flowname-groupname) that performs the flow's actions, linked per run to the initiating user. Custom and external agents belong to one managing project and carry immutable semantic versions in the AI Catalog. Agentic Chat in the UI and IDE does not use composite identity, so chat agents have no separate workload identity.

## Products

Composite identity service accounts, AI Catalog managing project and versions

## Gaps

Identity is per flow rather than per agent instance. No documented binding of the service account to a runtime or release record. Chat agents act purely as the user.

## Options
