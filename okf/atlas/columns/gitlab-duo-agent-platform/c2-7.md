<!-- chunk: answer -->
## Answer

Covered. Remote sandbox needs privileged runner mode. Local sandbox is experimental. Sessions cancelled cannot be resumed.

Source statement: "Intercepts all network requests before they leave the execution environment" (https://docs.gitlab.com/user/duo_agent_platform/environment_sandbox/)

Research detail: Flows run in a remote sandbox that checks outbound requests against a domain allowlist, limits reads and writes to set directories, blocks sensitive files such as SSH keys and exposes only needed environment variables. Administrators can set a baseline network policy in strict or flexible mode. Running sessions can be cancelled and then cannot be resumed, and Agent Platform can be turned off for an instance or top-level group. A separate local sandbox for IDE and CLI agents is off by default, restricts file access and allows network only to the GitLab host, and fails closed when it cannot start.

<!-- chunk: products -->
## Products

Remote execution environment sandbox (Anthropic Sandbox Runtime), local sandbox, session cancel, Agent Platform on and off setting

<!-- chunk: gaps -->
## Gaps

The remote sandbox needs privileged runner mode and a supported image. If it cannot start, the flow runs without it and only a CI log warning appears. Custom images without the runtime get no network restriction, and setup_script commands run outside the sandbox. The local sandbox is an Experiment and does not support Windows. Effect of turning the platform off on running flows is not stated.

<!-- chunk: options -->
## Options

Enforce network controls on the runner as a backstop, use the default image, and test session cancel and the instance toggle against a live flow.
