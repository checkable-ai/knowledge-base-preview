## Answer

Covered. Tool governance is beta, Premium or Ultimate. Rules are per tool, not per agent.

Source statement: "When an MCP server is blocked, no tools from that server can be invoked." (https://docs.gitlab.com/user/ai-governance/tool-governance/)

Research detail: Remote actions are bounded by composite identity (intersection of user and service account access, Developer role ceiling, ai_workflows and mcp token scopes) and by tool governance modes per tool for cloud and background access. Group rules cascade and projects can only tighten them. If the governance service fails, the agent receives no tools.

<!-- chunk: products -->
## Products

Composite identity, agent tool governance, custom agent tool selection

<!-- chunk: gaps -->
## Gaps

Tool governance is beta. Unconfigured background tools default to Always Allow. Rules are per tool, not per agent. A known issue with the aggregated search tool masks narrower rules.

<!-- chunk: options -->
## Options

Set background-access defaults explicitly at top-level group and restrict custom agent tool lists.
