## Answer

Covered. Tool governance is beta, Premium or Ultimate. Rules are per tool, not per agent. IDE and CLI egress is unrestricted.

Source statement: "When an MCP server is blocked, no tools from that server can be invoked." (https://docs.gitlab.com/user/ai-governance/tool-governance/)

Research detail: Tool governance applies allow, ask or deny per tool and access type at group and project level, including GitLab MCP server tools classified from their annotations. Owners can block external MCP servers. Flow egress is controlled by sandbox allow and deny domain lists with admin strict mode.

<!-- chunk: products -->
## Products

Agent tool governance, MCP server blocks, sandbox network_policy

<!-- chunk: gaps -->
## Gaps

Beta. Rules are not per agent. MCP blocks apply only to Agentic Chat in the UI. No rate limits per tool. IDE and CLI egress is unrestricted.

<!-- chunk: options -->
## Options

Combine group-level deny rules with strict network mode and review the Tool management tab after upgrades.
