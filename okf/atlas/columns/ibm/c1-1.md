## Answer

Covered. Applies to Python tools; sandbox restrictions are fixed by the runtime, not configurable per agent.

Source statement: "Each tool can access only its own filesystem and cannot modify files during execution." (https://developer.watson-orchestrate.ibm.com/tools/create_tool)

Research detail: Python tools run in an isolated container with their own virtual environment and a read-only filesystem, and package installs are limited to a tenant allowlist. On SaaS the tools runtime cannot reach the customer's internal network. Local MCP toolkits run inside the Orchestrate runtime over stdio.

## Products

watsonx Orchestrate tools runtime

<!-- chunk: gaps -->
## Gaps

No per-agent configurable scope for local actions such as file, process or egress permissions.

<!-- chunk: options -->
## Options

Keep risky logic in remote services with their own authorisation. Use on-premises deployment where network segmentation is needed.
