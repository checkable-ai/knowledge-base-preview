## Answer

Covered. SSO/OBO only in embedded web chat; not for local MCP toolkits; OAuth connections in UI.

Source statement: "reserve SSO/OBO for the live environment where tool execution occurs with a real user session" (https://developer.watson-orchestrate.ibm.com/connections/overview)

Research detail: Orchestrate supports member credentials so actions run with the user's own permissions, OAuth flows that generate an access token on behalf of the user, and an SSO/IDP On-Behalf-Of flow where the IdP token from embedded chat is exchanged for a downstream application token. The Workday tutorial documents the token exchange with Entra ID.

<!-- chunk: products -->
## Products

watsonx Orchestrate connections (member credentials, OAuth, oauth_auth_on_behalf_of_flow)

<!-- chunk: gaps -->
## Gaps

OAuth connections work only in the Orchestrate UI and SSO/IDP only in embedded web chat. SSO/OBO is not supported for local MCP toolkits, and cannot be used at remote MCP import time.

<!-- chunk: options -->
## Options

Use embedded chat with an IdP that supports token exchange for OBO. Test that downstream audit logs show the end user, not a service account.
