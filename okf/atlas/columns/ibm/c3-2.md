## Answer

Not covered. Controls apply PII and content guardrails at tool hooks, but no per-tool limits, input schema enforcement, dangerous action blocks or egress allowlists are documented.

Research detail: Controls bind PII filters and content guardrails (HAP, harm, jailbreak and others) to tools at tool_pre_invoke and tool_post_invoke hooks, with block or redact actions. Plug-ins add custom Python checks before and after agent invocation. MCP imports can restrict which tools are exposed.

watsonx Orchestrate controls, plug-ins, toolkit tool selection

## Gaps

No documented per-tool rate limits, schema enforcement beyond tool definitions, dangerous action filters or internet egress allowlists. Controls require the feature to be enabled in the instance.

<!-- chunk: options -->
## Options

Bind content guardrail controls on all tools and add a pre-invoke plug-in for business rules. Place an egress proxy in front of remote MCP servers.
